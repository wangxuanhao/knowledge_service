统一本体工作台 · 总体能力

项目原生样式 · 生命周期统一
统一的含义：发现和人工建模保留各自入口，但从产生变更开始共用一种草案、审核、校验、发布和溯源机制。

两条输入链路

开放发现不受当前本体限制；人工建模可精确控制语义。

A · 开放发现来源候选 → 聚类归纳 → 层级建议 → 证据与置信度
B · 通用建模结构化编辑 / Turtle 导入 / 术语停用 / 外部映射
两条链路都不能直接修改正式本体，也不能绕过审核。
→

统一变更内核

草案基于明确的正式版本，所有修改拆成可审核操作。

Ontology Draft · base_version=v12创建人、来源、时间、理由、证据、风险和状态完整记录
创建术语修改标签增删父级边增删关系约束属性与数据类型SHACL 约束停用术语
草案组合编辑与差异预览
审核逐术语、逐语义边决定
校验DAG、引用、SHACL、影响
发布原子生成正式版本
→

三个正式输出

发布结果不仅是 Turtle 文件，还包含版本和证据链。

唯一正式本体某一时刻只有一个项目当前版本；运行时默认读取它
不可变版本历史完整 diff、回溯、比较和基线冲突检测

实现边界

前端一个本体工作台入口；对象视角、层级总览、关系矩阵；右侧检查器复用统一设计语言。
API统一 drafts / operations / reviews / validate / publish；旧读取接口保持兼容，直接写接口进入草案。
领域模型正式本体不可变版本 + 草案操作集；父级是 0..N 条独立语义边，禁止循环。
存储与运行时正式版本仍是唯一运行基线；草案覆盖层仅供工作台预览，不影响抽取和查询。
推荐的一期目标：做到“业务可完整建设和治理本体”，而不是宣称实现全部 OWL 语言。高级公理在统一草案模型上后续扩展，不破坏当前接口和页面。
