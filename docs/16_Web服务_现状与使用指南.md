# 16 Web 服务：现状 / 数据构建顺序 / 使用指南（2026-09 更新）

> 面向"解读代码/上手使用/内部汇报"。这份把**数据→实体→图→问答**的构建顺序和 Web 每个菜单到底干什么讲清楚。
> 配套：根 `README.md`（目录地图）、`docs/USAGE.md`（模块与 REST）、`docs/17_…链路说明.md`（17 抽取器原理）。

---

## 0. 一句话总览

规则/协议原文（`.md/.txt`）→ 标题感知分块 → LLM 抽取**实体+关系**（受本体白名单约束）
→ 归一/消歧/去重 → 组成**有向图 + 双路向量库**（实体库 + 原文段库）→ 打成离线**项目**
→ Web 里可 **看图 / 体检 / 看原始数据源 / 脑图 / 问答 / 增量更新（含版本回滚）**。

启动：仓库根双击 `apps/start_kg_server.cmd`（或命令行跑 `apps/16_kg_web_server.py`），开 `http://127.0.0.1:8000`。

## 1. 数据是怎么进来的（构建顺序 A：灌数据）

| 步骤 | 做什么 | 谁在做 | 落盘 |
|---|---|---|---|
| 1 放原文 | 规则文档放 `data/rule_demo` / `data/rule_txt`（.md/.txt 均可） | 人工/下载脚本 | — |
| 2 抽取 | `17_rule_demo_semantica_api.py`（服务器默认引擎）标题感知分块 → LLM NER + 关系 | apps/17 | `data/rule_demo_output/run_<时间戳>/`（graph.json / 分块 JSON / ontology_summary.md） |
| 3 载入 Web | 图谱页「📥 载入数据」扫描 `rule_demo_output/run_*` 每个子目录 | 16 Web | `data/projects/<项目名>/` |

> 引擎可切换：环境变量 `KG_EXTRACTOR=15` 则用 15 的手写直连抽取器；默认 17（semantica 原生 NER/Rel + structure_aware_split，偏移校正、JSON 稳定）。详见 docs/17 链路说明。

Web 里一共有 3 条"进数据"的路：
- **📥 载入数据**（图谱页）：免 LLM，把 15/17 已产出的 run 批量建成项目 —— 日常主力；
- **📎 增量写入（Upsert）**（脚本页）：把**单篇**新 .txt/.md 并入某个已有项目（LLM 抽取→消歧→合并），不是新建；
- **新建解析**（图谱页）：直接给一个文件夹路径让服务端现抽（也可勾 demo 免 LLM 试玩）。

## 2. 实体 / 关系 / 图是怎么构建的（构建顺序 B：一张图怎么来）

对**每一篇**文档，构建链如下（对应 `apps/16_kg_web_server.py` 里的 `run_upsert_job / build_project_from_meta`）：

1. **读取清洗**：.md 直接按文本读；去掉分页噪声；按行清洗。
2. **标题感知分块**（structure-aware）：标题与正文同块、超长块再滑窗，块 ~8000 字、重叠 400 —— 保证"一条规则不会被腰斩"。
3. **LLM NER**：按本体白名单（`ontology/meituan_ontology.ttl` 的实体类型，如 Platform/商户/Violation/Penalty…）抽取**实体**，并校正起止偏移。
4. **LLM 关系抽取**：在已抽实体上抽 `主体-谓词-客体`，谓词也是白名单（`commits/prohibits/triggers/handles…`），并做 domain/range 约束回检。
5. **归一 + 去重**：别名/规范名归一（如"卖家/店铺/商户"），实体按 `(text,label)`、关系按 `(s,p,o)` 去重；再从章节/条款标题补结构实体（partOf）。
6. **消歧/合并（可人工校正）**：Web「实体」页可**标注别名**、**向量相似合并**两个实体、删实体；增量写入时若命中别名或向量高度相似（类目一致）自动并入旧节点（阈值 0.88，逐条打日志）。
7. **构图**：实体=节点（属性 label/置信度/来源文件/出处条款），关系=有向边（谓词/置信度/来源）；networkx DiGraph 存于内存，落盘 `graph.json`。
8. **双路向量库**：实体库（按 "名称(类型)|上下文片段" 编码）+ 原文段库（按整段文本编码），bge-m3 本地模型，FAISS IndexFlatIP；与 corpus.json 行序对齐。
9. **打包项目**：`data/projects/<名>/` 下 `manifest.json`（含别名、来源全文、统计）+ `graph.json` + `entities.json` + `segments.json` + `embeddings/`。

> 版本：每次 upsert 写入前自动把整包快照到 `<项目>/history/<时间戳>/`，保留最近 15 份，Web「📎 增量」页可**一键回滚**（回滚前再存档当前态，可反复回退）。

## 3. Web 每个菜单是什么（从左到右）

| 菜单 | 一句话用途 | 关键交互 |
|---|---|---|
| 📊 看板 | 项目体检：实体/关系/段/类型/关系分布、高连接度 Top、数据来源 | 顶部🔍可全局搜 |
| 🗺 图谱 | 力导向图 + 检索 | 点节点看详情(出/入边+出处条款)；全图/1跳/2跳；图例中文色卡对齐 |
| 📋 实体 | 按类型列实体 + 数据治理 | 添加实体/关系（谓词可自定义）；🗑删除；🧩消歧/合并：查重、标注别名、合并 |
| 🧬 本体 | 类目/谓词字典（来自 ttl） | 浏览 + declared/observed 谓词 |
| 📄 数据源 | 看**这个项目背后的原文** | 左列文档列表(字数/实体/关系/段)，右读全文 |
| 🧠 脑图 | 以某实体为根展开 | 顶部可切项目；点卡片展开/收起；「设为根」重画；双击看详情 |
| 💬 问答 | 端到端 LLM 问答（Local） | 流式输出、思考过程可见；答案带 [n] 证据编号、可展开证据、可跳图定位 |
| 📎 增量 | 把新文档并入已有项目 + 版本回滚 | 选项目+传文件→后台任务：实时日志+运行计时+分块进度；下方「历史版本/回滚」 |

顶部 `appbar` 右侧的 **🔍 搜索框**全局可用：输入实体名回车=在图谱定位；输入一句话回车=执行全文/图检索。

## 4. 问答（Local QA）是怎么答的

1. 多通道召回证据：实体向量 top-k → 图内 seed（别名归一、问题提及、**命中段落里出现的实体**也补为 seed）→ seed 沿出/入边各扩展 hops 层取关系证据 → 原文段 top-k。
2. 把证据编成带编号 `[1][2]…` 的上下文 + 系统提示（只依据证据作答、逐条标出处、证据不足明说）。
3. LLM 流式作答（逐 token 推回浏览器，思考过程可预览）。
4. 每条卡片可展开「证据 N 条」查看原文出处并可跳图定位 → 答案可审计、可溯源。

> 现为**单轮无状态**问答（主流 GraphRAG Local Search 同款）：每问独立召回、独立作答，证据干净、可追溯；如需"追问/多轮"，前端把最近 N 轮传回即可，属可选增强。

## 5. 运维与排查

- 日志（重启后自动生成，旋转 5MB×5）：`data/kg_web/logs/server.log`（启动信息+每个 API 请求+异常堆栈）、`out.log`（stdout/stderr 全量镜像，含 LLM/模型/任务的 print）。
- 后台任务（解析/导入/增量）跑在服务进程的线程里，**切换页面不影响**；增量的进度/日志在页面上实时滚动。
- FAISS/embedder 非线程安全：已用进程级锁把"后台写入 vs 前台检索"串行化，避免并发段错误。
- 常驻内存项目在 `LOADED`（服务重启后按需从 `data/projects` 重载；`/api/…` 会自动装载）。
- 出问题先看两个日志文件尾部，再看任务的 `logs`。
