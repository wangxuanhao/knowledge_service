# 同屏工作台与加载优化

本次以原 `data/kg_web/static/index.html` 的图谱页为对照，不替换旧数据和编号脚本。

| 原版 / 用户所需能力 | 当前实现 |
|---|---|
| 图谱与检索同屏 | 左侧检索及分类证据、中间图谱、右侧节点 / 边详情 |
| 检索联动图谱 | 关键词输入自动检索；命中节点高亮，可选择仅命中 / 1 跳 / 2 跳 |
| 原文、实体、关系分类 | 检索结果按三个通道展示，不用纯实体结果挤掉原文 |
| 实体选择与脑图 | 名称 / 类型过滤后下拉选择，不要求手输 ID；节点详情可跳脑图 |
| 图谱专注视图 | 隐藏左右面板，保留全图 / 邻域 / 复位操作 |
| 时间与 metadata | 紧凑双时态工具条、高级 metadata 浮层，先筛选再检索 |
| 本体可视管理 | 类及继承、关系定义域 / 值域、属性列表；表单新增并保存新版本 |
| 原有治理 | 保留别名、消歧、合并、修订、软删除、撤销、快照及 Turtle / SPARQL |

## 加载慢的证据与修正

修改前在现有服务测得：项目列表 18 ms，本地项目扫描 559 ms，已导入项目图数据 232 ms。
旧的首次导入任务记录为 05:41:58–05:44:05 UTC，约 127 秒。
旧导入路径在返回前调用本地向量模型，编码实体、关系、片段和全文；显示图谱不应依赖这一步。

新增快速载入：不加载模型，先写入原始知识、本体及审计记录，立即支持图谱与关键词检索。
语义向量作为派生索引通过 `/indexes/rebuild` 单独后台构建，只编码尚缺当前模型向量的实体、关系和片段。
构建索引不增加事实版本；如果构建期间知识发生修订，只写回未被替代的版本。
未就绪时语义检索明确提示先建索引，不静默降级冒充语义结果。

4 个旧项目实测纯加载分别 2.895、0.372、0.356、0.555 秒。
这不是声称模型计算更快，而是把浏览与向量构建解耦。首次语义检索仍可能涉及本地模型冷启动。
检索界面显示服务侧及浏览器侧耗时；关键词检索不调用模型。

真实语义检索（已有向量的 `run_20260906_073158`，同一服务连续请求）分段计时：

| 阶段 | 第一次 | 第二次 |
|---|---:|---:|
| 整体 HTTP 请求 | 54.320 s | 1.619 s |
| 查询编码，含首次模型加载 | 52.215 s | 0.154 s |
| 向量排序，含 Windows 隔离进程启动 | 1.766 s | 1.255 s |

语义首查冷启动仍然存在；本次没有把这部分说成已消除，也没有用关键词结果冒充语义结果。

## Neo4j 实机验证

已读取用户本机配置并连接 `samr`；同步 5 个带旧项目来源标记的服务项目，
版本节点分别为 155、453、124、105、137，合计 974，远端数量与本地导出快照逐项相符。
SQLite 与旧目录继续保留，Neo4j 当前仍是手动同步副本，不是在线检索的主存储。

## 保留的限制

- 旧数据的生效时间仍可能未知，不把上传 / 导入时间冒充生效时间。
- 历史导入采用兼容本体；本次没有自动重写旧知识类型或自动执行实体融合。
- 本体可视表单支持添加项；复杂 SHACL 和现有项修改仍在 Turtle 编辑器完成。
- 当前是单进程后台任务，不是分布式任务系统；索引耗时和失败状态可查看。
