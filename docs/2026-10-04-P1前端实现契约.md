# P1 前端实现契约（本体建模层单画布 + 知识写入）

> 日期：2026-10-04　承接《2026-10-04-本体建模层实施规划.md》§2 的 B1–B8 / C1–C5 与《2026-10-04-本体建模层单画布设计.md》。
> 本文是**实现边界契约**：谁写哪个文件、通过什么接口通信、复用哪些现成代码。实现者只读本文 + 它指名要读的现有文件。

## 0. 一句话目标

把结构层的三个页面（编辑台／审核台／档案）与「知识写入」**重组成两个独立页面**：

- **本体建模层**（`tab-ontology-model`）= 单画布：左清单（类/关系/属性）＋ 中画布（可拖拽连线）＋ 右详情 ＋ 顶栏（图谱/分层切换 ＋ 版本历史）＋ 底栏（校验并审核 → 发布）。
- **知识写入**（`tab-ingest`）= 上传/自然语言 → 抽取（分析师对话流）→ 候选（收下/忽略）→ 分流（新概念→建模层，新实例→台账）。

**后端一行不改**（设计文档 §5.3「UI 先合、治理先保留」，§8「这是前端重构，不是后端重写」）。全部走现有 API。

## 2. 接口契约（唯一通信方式）

### 2.1 主控 `window.OntologyModel`（地基已实现，实现者只读消费）

```js
window.OntologyModel = {
  S,                    // 共享状态对象（见 2.2）
  on(event, handler),   // 订阅；返回取消订阅函数
  emit(event, payload), // 发布
  render(),             // 触发整页重渲染（装配 canvas.render + panel.render）
  refresh(),            // 重读本体 + 草案状态（异步）
  ensureDraft(),        // 确保存在可编辑草案；没有则自动新建。返回 draft 对象或抛错
  sendCommand(command), // 把一条命令发给当前草案（自动 ensureDraft）。返回更新后的 draft
  status(message, err), // 出提示（复用 app.js 的 status / noticeCard，带本地兜底）
  helpers: { label, shortIri, esc, dtypeOf }, // 术语取名/短 IRI/转义/属性数据类型短名
};
```

**事件（主控 ↔ canvas/panel 的唯一通道）**

| 事件 | 谁发 | 载荷 | 谁听 |
|---|---|---|---|
| `select` | canvas / 左清单（主控） | `{ iri }` | panel（刷新详情）、canvas（高亮） |
| `graph:changed` | 主控（load/refresh 后） | `{ graph }` | canvas |
| `draft:changed` | 主控（sendCommand 后） | `{ draft }` | canvas、panel |
| `stage:changed` | 主控（refreshState 后） | `{ stageAvailability, readiness }` | panel（底栏门禁） |
| `view:changed` | 主控（顶栏按钮） | `{ view }`（`'graph'` / `'hierarchy'`） | canvas |

### 2.2 共享状态 `S`（主控持有，canvas/panel 只读）

```js
S = {
  summary:  { classes:[], relations:[], attributes:[] } | null, // GET /ontology 的 summary
  graph:    { nodes:[], edges:[] } | null,                     // 主控算好的画布图（见 2.3）
  selected: null,                 // 选中的术语 IRI
  draft:    null,                 // 当前草案对象（含 id/revision/status）
  view:     'graph',              // 'graph' | 'hierarchy'
  stageAvailability: null,        // GET /stage-availability
  readiness: null,                // GET /publish-readiness
  candidates: [],                 // 待收下候选（虚线节点）
  error: null,
};
```

### 2.3 画布图格式（主控把 summary 编译成画布图，canvas 只渲染）

```js
S.graph = {
  nodes: [
    { id:'urn:...:类', label:'类名', kind:'class'|'relation'|'attribute',
      iri:'urn:...', dtype:'string'|'',  // dtype 仅 attribute 有
      state:'published'|'pending'|'selected' } // published=实线, pending=虚线待收下
  ],
  edges: [
    { id, source, target, kind:'inherit'|'relation'|'pending',
      label }  // inherit=父子实线, relation=关系紫虚线, pending=待收下虚线
  ],
};
```

### 2.4 `window.OntologyCanvas`（实现者 A 实现）

```js
window.OntologyCanvas = {
  mount(host, ctx),      // host=中栏 DOM 容器, ctx=<主控实例>。建 Cytoscape 实例、绑事件
  render(state),         // 用 state.graph 重画；保留当前选中与缩放
  setView(mode),         // 'graph' | 'hierarchy' 切换布局
  focus(iri),            // 选中并居中某节点
  destroy(),
};
```

### 2.5 `window.OntologyPanel`（实现者 B 实现）

```js
window.OntologyPanel = {
  mount(detailHost, actionsHost, ctx), // 右栏详情宿主 + 底栏宿主 + ctx
  render(state),                       // 用 state.selected / draft / stageAvailability / readiness 重画
  openHistory(),                       // 打开版本历史抽屉
};
```

### 2.6 `window.IngestFlow`（实现者 C 实现）

```js
window.IngestFlow = {
  mount(host, ctx),  // host=#tab-ingest（或它的容器）；会 prepend 到「添加文档」折叠块之前
  refresh(options),  // options.full=true 时连开放发现候选一起重读
  startPolling(), stopPolling(),
  send(),            // 「发送」＝提交输入框里的正文（或 ＋文件 队列），并留在这一页
  get state(),       // 只读状态，便于排查
};
```

**交互口径（2026-10-05 起，用户原话驱动的改造）**：这一页只有「一段对话 + 一个输入框」——
你说的话、它怎么处理（💭思考 / 📄证据 / ▶运行）、要你决定的事、以及决定的回执，全部按顺序出现在
同一段对话里；要你决定的事**逐条以气泡提问**，按钮就在气泡里。
平铺的候选表与「已收下（累计）」清单已删除（用户：「你这样下面平铺我都不知道是干什么的，看不懂都」）。
详见 `docs/2026-10-05-知识写入与台账改造.md`。

## 3. 关键后端 API（已侦察；实现者按需在 `api/*.py`、`services/*.py` 深挖）

### 3.1 本体结构 / 版本

| 方法 路径 | 说明 |
|---|---|
| `GET /api/projects/{p}/ontology` | 当前本体 → `{ id, summary:{classes[],relations[],attributes[]}, triples }`。class=`{id,label_zh,label,name,parents[],active}` |
| `GET /api/projects/{p}/ontologies` | 版本列表 `{...versions}`（**注意返回键**，读原始 JSON 核对） |
| `POST /api/projects/{p}/ontologies` | 建本体草案（旧式，画布走 draft API） |
| `POST /api/projects/{p}/ontology/validate` | 校验 |

### 3.2 草案治理 `prefix = /api/projects/{p}/ontology-drafts`（画布编辑/校验/发布全走这里）

| 方法 路径 | body / 说明 |
|---|---|
| `POST ''` | `{base_ontology_id?, source_kind:'manual', title, actor, source_context?, summary?}` → draft |
| `GET ''` | `{items, total}` |
| `GET /stage-availability?draft_id=` | 阶段门禁（**唯一出处**）：`stages.<id>.{allowed,reason}` + `status_label/status_copy` + `next_action` |
| `GET /{draft_id}` | 草案详情（含 revision / status / changes） |
| `POST /{draft_id}/commands` | `{expected_revision, command}` → 更新的 draft。**command 见 3.3** |
| `POST /{draft_id}/validate` | `{expected_revision}` → 校验报告（warnings / 指纹） |
| `POST /{draft_id}/submit` | `{expected_revision}` → 提交审核 |
| `POST /{draft_id}/decisions` | `{expected_revision, expected_ontology_id, validation_fingerprint, decisions[], actor, acknowledged_warning_codes[]}`；decisions 项 `{action:'approve'|'reject'|'request_changes', ...}` |
| `POST /{draft_id}/decisions/batch-approve` | 一键批准（服务端挑安全的）→ `{expected_revision, expected_ontology_id, validation_fingerprint, actor, acknowledged_warning_codes[]}` |
| `GET /{draft_id}/review-plan` | 风险分类（safe/manual/blocked）+ `auto_approvable` |
| `GET /{draft_id}/publish-readiness` | 只读发布清单（逐条未满足条件/级别/建议） |
| `POST /{draft_id}/publish` | `{expected_revision, expected_ontology_id, validation_fingerprint, idempotency_key, actor, acknowledged_warning_codes[]}` |
| `GET /{draft_id}/evidence` | 证据投影 |

### 3.3 命令通道 `command` 的形状（`services/ontology_drafts.py:_operation_args`）

```js
command = { action, target_iri, kind?, before?, after?, ... }
// action：
//   'create_term'       新建术语；kind='class'|'relation'|'attribute'
//   'add_parent'/'remove_parent'   父子；值放 parent_iri 或 value
//   'add_domain'/'remove_domain'/'add_range'/'remove_range'  值放 value 或 domain_iri/range_iri
//   'add_annotation'/'remove_annotation'  {predicate,value,language?,datatype?}
//   'set_datatype'      {datatype}
//   'retire_term'/'restore_term'/'advanced_rdf_patch'  ← 不可逆（IRREVERSIBLE_ACTIONS）
//   'turtle'/'replace_turtle'/'diff_turtle'  整份源码
```

### 3.4 层级浏览（可选，画布分层视图可用）

`prefix = /api/projects/{p}/ontology-hierarchy`：`GET /roots`、`/search?q=`、`/children?iri=`、`/neighborhood?iri=`（都带 `ontology_id?`/`draft_id?`）

### 3.5 知识写入 / 抽取（实现者 C）

| 方法 路径 | 说明 |
|---|---|
| `POST /api/projects/{p}/documents` / `/documents/upload` | 上传文档（201） |
| `POST /projects/{p}/documents/upload/preview` | 上传前预览（parity 路由，注意前缀无 /api 的那组也挂着） |
| `POST /projects/{p}/documents/upload/jobs`（202） | 上传并处理（返回 job） |
| `GET /api/projects/{p}/ingest-runs` | 抽取运行列表 → `active_stage` / 阶段输出（**分析师对话流的唯一数据源**） |
| `GET /projects/{p}/structure-pending` | 结构待定知识 |
| `GET /projects/{p}/reclassify` + `POST /reclassify/preview` | 受控重分类 |
| `GET /api/projects/{p}/ontology-discovery/runs` `/runs/{id}` `/candidate-mindmap` `/audit` | 发现候选 |
| `GET /reviews` / `POST /reviews/{doc_id}/{candidate_id}` | 候选收下/忽略 |

> ⚠️ 前端已有 `ingest-mode.js`（文件队列/校验/元数据，**已实现，别重写**）；实际"上传并处理"的提交逻辑在 `workbench.js` 里。实现者 C 的活是**在其上加"对话流 + 候选"**，不是重做上传。

## 6. 交付标准（每个实现者都要满足）

1. 改完 `node --check` 每个 JS 文件通过。
2. 不引入新的全局命名冲突；只用契约里的命名空间。
3. **每个功能要有一句话说明「它做什么、不做什么」**（写在 UI 上或注释里）——用户明确要求（"只给一个开关/数字"是他的核心不满）。
