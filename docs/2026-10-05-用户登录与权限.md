## 1. 一句话

服务多了一个**账号层**：没登录的人只能看到登录浮层；登录后按**角色**决定他能写还是只能读。
角色只有两档——写的人（`admin`）和只读的人（`viewer`）——本轮补上了**在界面上**建账号、
改角色、停用/启用、重置口令、改自己口令的全套动作，并把守门逻辑收进服务端（前端只是不摆出按钮）。

## 2. 两档角色：为什么不细分

| 角色 | 能做什么 | 界面上 |
|---|---|---|
| `admin` 管理员 | 读一切 + **写入**（上传知识、本体建模、发布版本、改台账）+ **管理账号** | 侧栏四个层全在；左下角账号区多一颗「用户与权限」 |
| `viewer` 只读用户 | 检索、问答、看脑图、查来源证据（**读**） | 只看到「消费层」；账号区写着"写入入口已隐藏，要写入请联系管理员给你管理员角色" |

只有两档是有意的：这个服务的写入动作都集中在少数人手里，而**每多一档角色，就得在界面上多解释一次
"他和另一档差在哪"**。真需要第三档（比如"能写实例但不能改本体"）时再加，加的时候必须同时补上
那句解释，否则用户只会看到一堆看不懂的角色名。

## 3. 怎么用（管理员视角）

1. **首次启动**：库里没有任何账号时，服务会播种第一个管理员：
   `KG_SEED_ADMIN_USERNAME` / `KG_SEED_ADMIN_PASSWORD`（默认 `admin` / `admin123`）。
   启动日志会明确警告"仍在用默认口令"，请在下面第 2 步改掉。
2. **改自己的口令**：左下角账号区 →「改口令」→ 填当前口令 + 新口令（≥6 位）。
   自己改完**其他设备上已登录的会话立刻失效**（原因见 §4 的令牌指纹）。
3. **建账号**：账号区 →「用户与权限」→ 顶部「新建账号」：用户名 / 初始口令 / 角色 / 显示名（选填）。
   建出来的是**本地账号**（用户名+口令），不是对接外部认证中心。
4. **改角色 / 停用 / 重置口令**：账号清单里每一行右侧三个动作。三点必须知道：
   - 改角色**立刻生效**（角色每次请求都回查库，不是写在令牌里）；
   - 停用后他手里的令牌**立刻失效**，也不能再登录；
   - 重置口令后他手里的令牌**立刻失效**，得用新口令重新登录。
5. **你自己这一行没有"改角色/停用"**：不是漏了，是**故意的**——管理员把自己降级或停用会当场
   失去管理权限，界面上只留「改口令」。

## 4. 服务端怎么把关（三层，别只看前端）

| 层 | 位置 | 干什么 |
|---|---|---|
| ① 认证 | `api/security_middleware.py` | 校验令牌签名、有效期；**回查库**核对账号是否启用、角色是什么、**口令指纹是否还对得上** |
| ② 授权 | 同上 | 按"这个方法+这个路径要不要 admin"判定；**fail-closed**：GET/HEAD/OPTIONS 算读，PUT/PATCH/DELETE 算写，POST 默认算写，只有白名单里的只读 POST（检索、问答、查证据…）和自助改口令例外 |
| ③ 端点自查 | `api/users.py` 等 | 除 ② 之外的业务约束：不能改自己角色/停自己、不能弄掉最后一个启用管理员 |

两个关键设计：

- **令牌带"口令指纹"**（`core/security.py:credential_fingerprint`）：令牌里除了 user_id/角色，
  还压了一段口令哈希的短指纹。改口令或管理员重置口令后，旧令牌回查库时指纹不符 → 立刻 401
  `stale_credentials`。这样"改口令＝踢掉所有旧会话"，不需要额外的会话表。
- **拒绝理由要说对话**：只读用户去读账号清单，回的是
  "用户与权限只有管理员能看，当前账号是只读用户"，**不是**"只读用户不能写入"——他在读，没在写；
  说错理由会让人以为是自己操作方式不对。

## 5. 本轮补齐了什么（对照"缺什么"）

| 之前 | 现在 |
|---|---|
| 有 `users` 表、有登录/注册、有"只读不能写"的守卫、有登录浮层 | — |
| **没有任何管理入口**：改角色/停用/重置口令只能手写 SQL | `api/users.py`：列表 / 建号 / 改角色 / 停启用 / 重置口令（`/api/users`） |
| 没有任何改口令的能力（默认口令只能一直用） | `POST /api/auth/password` 自助改口令（要填当前口令）+ 管理员重置 |
| 令牌在改口令后仍然有效（改了口令也踢不掉别人） | 令牌带口令指纹，改口令/重置即刻作废旧令牌 |
| 只读用户也能看到"用户与权限"这类入口（点进去才被 403） | 前端按角色隐藏（`.admin-only` + `body.is-admin`），后端照样拒 |
| 首次启动库里没账号 → 谁也进不去 | `_ensure_seed_admin` 播种首个管理员（env 可改用户名/口令） |
| 每次重启所有人都掉线（签名密钥是进程级随机的） | 未配置 `KG_JWT_SECRET` 时警告；本机已在 `.env` 写入该键（值不外显） |
| 只读用户侧栏出现"有标题、里面空空"的分组 | `menu-hierarchy.js` 确知是只读用户时把"全是写入口"的分组整组收起 |

### 本轮真机抓到并修掉的三个问题

1. **管理员也看不到任何写入口**：`.admin-only{display:none !important}` 是 `!important`，
   而"管理员显示"那条没带 → 永远被压住。这是**已上线代码里的真 bug**（只不过此前没人以管理员身份
   在真浏览器里量过可见性）。现在两条都带 `!important`，并有契约测试钉住。
2. **会话区按钮 id 与登录输入框撞名**（都叫 `auth-password`）：`getElementById` 拿到按钮，
   登录时读 `.value` → 登录直接崩。已改为 `auth-open-password` / `auth-open-users`。
3. **只读用户查"来源证据"被 403 拦住**：证据是**读**，却不在只读 POST 白名单里，
   只读用户点"查看来源"会被授权层拦掉（应走到业务层）。已修：只读用户得到 404（记录不存在），
   而不是 403（越权）。`verify_auth_rbac.py` 专门钉了这一条。

## 7. 还差什么（明确边界，别当成已做）

| 项 | 现状 | 该怎么补 |
|---|---|---|
| **删除账号** | 只有"停用"（`0008` 的取舍：禁用优于删除，保留"谁在什么时候改了什么"的留痕） | 真要彻底删，用迁移角色跑 `DELETE FROM users WHERE username='x'`（应用角色**没有** DELETE 权限，是故意的） |
| **口令策略** | 只校验长度 ≥6 | 要复杂度/有效期/禁止复用，加在 `api/auth.py` 的 `PasswordChange` 校验里 |
| **登录失败锁定** | 无（可无限试密码） | 中间件里按用户名+IP 计数，连续失败 N 次锁一段时间 |
| **找回口令** | 无（只能管理员重置） | 本地账号场景够用；要自助找回得先有邮件/短信通道 |
| **项目级权限** | 角色是**全局**的：只读用户能看到全部项目 | 要"某人只能看某项目"，需要 ACL 表 + 在检索/问答/台账的查询里带上范围过滤 |
| **操作审计界面** | 无（改角色/停用/重置没有留痕表） | 加 `user_audit` 表 + 一个只读列表；比"删除账号"更该先做 |
| **UI 测试的 Edge 争锁** | 12 个 UI 测试文件各自 `chromium.launch()`，与桌面常驻 Edge 争默认配置目录，偶发 `TargetClosedError`（本轮实测 1 次，重跑即过） | 统一抽一个 `ui_browser.py`：给 launch 加隔离 `--user-data-dir`（本轮的 `test_auth_ui.py` 已这么做） |
| **权限申请流程** | 无 | 只读用户看到"请联系管理员"就够了；要做自助申请得有通知与审批，先不做 |

## 9. 自助注册：默认关（本轮的取舍）

`POST /api/auth/register` 以前对所有人开放（注册出来的账号恒为 viewer）。**本轮默认关掉**：

- 关掉的理由：任何能访问这个服务端口的人都能给自己开一个**能读全部知识**的只读账号。
  而"开号"这件事现在已经有正经入口了（「用户与权限」，只有管理员能调）——留着一个公开
  注册口，等于把账号发放权交给了网络可达性。
- 关掉之后怎么开号：管理员在「用户与权限」里建，能直接指定角色（viewer/admin）。
- 关掉时的界面：登录框**不再摆一个点了会被拒的「注册」按钮**，改写成
  "没有账号？让管理员在「用户与权限」里给你开一个（自助注册已关闭）。"
- 要恢复旧行为：`.env` 里 `KG_ALLOW_SELF_REGISTRATION=1`（登录框会自动把「注册」摆回来）。
  这条策略由公开的 `/api/health`（字段 `self_registration`）告诉前端，前端不猜。
- 拒绝时说的话：`403 self_registration_disabled` +
  "自助注册已关闭：请让管理员在「用户与权限」里给你开一个账号。"——给下一步，不只说"不行"。

## 10. 顺带修掉的两个真问题（都是 auth 接进 `index.html` 之后才暴露的）

1. **未登录首屏的杂散 401 被当成"掉线"**：`workspace.js` / `projects-view.js` 在未登录时也会
   拉项目列表（`app.js` 那条链是等登录的，这两处不是）→ 401 → 登录框红字写着
   "登录状态已失效，请重新登录。"，而用户**从来没登录过**；顺带把会话标记成"挂起"，
   登录后还会多一次整页重载。
   修法：① 401 只在"本来带着令牌"时才算掉线；② 两处改走 `Auth.whenReady()`。
2. **登录浮层把整页盖住 → 用真实 `index.html` 的浏览器契约套件成片失败**
   （真机报错是 Playwright 的 `auth-overlay ... intercepts pointer events`）：
   那些套件的服务端是 `auth_disabled=True` 起的（不校验），但**前端仍然摆了登录浮层**。
   修法：`/api/health` 增 `auth_enabled`；前端只有在**确知启用鉴权**时才等登录，
   没启用就直接放行、界面按"完全放开"渲染（写入口都显示）——即接入认证之前的样子。
   读不到这个字段时按"启用"处理，保持原行为，不会因为一次网络抖动把门打开。

## 11. 已知的测试环境噪声（不是功能问题）

- 12 个浏览器套件各自 `chromium.launch()`，与桌面常驻 Edge 争默认配置目录 →
  偶发 `TargetClosedError`；连跑 35 个浏览器用例时也会有 1 条卡在 30s 超时
  （**同一用例单独跑 5s 通过**，且每次失败的是不同的用例 → 属负载相关抖动）。
- 根治办法：统一抽一个浏览器夹具，给 launch 加隔离 `--user-data-dir`
  （本轮的 `test_auth_ui.py` 已这么做）；再给那批用例的关键等待放宽到 60s。
