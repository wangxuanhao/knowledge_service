# 知识写入 & 知识台账改造（2026-10-05）

一句话：**写入页变成"一段对话 + 一个输入框"，台账回到"具体的东西"的四件事上（查 / 改 / 并重复项 / 撤销），
「把这批知识迁到新本体」那一整块从台账撤掉、能力搬到「本体建模层」发布新版本那一刻。**

用户原话（就是本次的验收口径）：

> 知识写入的这个-抽取过程与候选，展示形式太差了，那就不要了，就是跟输入框一样，问答，然后处理，
> 你这样下面平铺我都不知道是干什么的，看不懂都，什么收入不收入，
> 然后知识台账不是维护实体、关系、属性新增、删除、修改、融合的吗
> 把这批知识迁到新本体 "把这批知识迁到新本体"这块是为了展示什么的，感觉也不需要吧

---

## 1. 知识写入：从"平铺"改成"对话"

### 改之前是什么样

页面下面竖着三块：`分析师对话流` / `候选（收下 / 忽略）` / `已收下（累计）`。
每抽一批文档，候选就像表格一样平铺出来，加上一份会一直累加的清单 —— 用户看不出"这块是干什么的"。

### 改之后是什么样

一个卡片，从上到下只有三样东西：

| 位置 | 内容 | 它做什么 / **不**做什么 |
|---|---|---|
| 顶部 | 标题 + 一句话说明 + 工具栏（刷新状态 / 清空这段对话 / 本页已写下 N） | 说明里写明"只做抽取与候选决定，**不**替你发布本体新版本" |
| 中间 | **对话记录**（可滚动） | 你说的在右（青底），它的在左：💭思考 / 📄证据 / ▶运行 / ❓提问 / 回执 |
| 底部 | **输入框 + 发送**（＋文件 / 拖放） | 发送＝把正文交给它抽取，**留在这一页**看结果 |

要你决定的事**逐条以气泡提问**，按钮就在那句问话里：

- 新实例 → 「写进知识台账」/「不要」
- 新概念 → 「加到本体建模层」/「不要」（并写明"要发布新版本才生效"）
- 约束异常 → 「确认这是例外」/「不确认」

每个气泡下面都有一行灰字，写清"点了会怎样、不会怎样"（这是这个项目里反复被要求的：功能不能只有一个开关）。

### 三个刻意的决定

1. **不在这一页做发布。** 新概念只是"加进本体建模层的发现草案（画布上的虚线节点）"，
   要发布新版本才正式生效 —— 文案里说死，避免让人以为"点一下本体就变了"。
2. **发送不跳页。** 表单那条"上传并处理"会跳到「项目与运行 → 后台任务」，
   那是给人看任务日志用的；在对话里等于把人赶走。所以对话自己 POST，**复用**既有上传通道：
   校验仍由 `ingest-mode.js` 的 `readDocumentBatch()` 一处负责，解析设置仍读 `readParseSettings()`
   （切片策略 / 消歧 / 发布时间 / Metadata 一份口径），标题取正文首行前 20 字。
3. **精细设置还在，只是收起来了。** 原「添加文档」面板整块收进 `<details class="ingest-flow-advanced">`，
   对话卡 prepend 到它之前 —— 主路径是输入框，要批量文件 / Metadata / 高级解析时点开即可（同一条上传通道）。

### 平铺的两块删掉了

`.ingest-flow-cand-list` / `.ingest-flow-ledger-list` / `.ingest-flow-section-title` **不存在**了
（不是隐藏）。"本页已写下"改成工具栏上的一句话（`知识台账 3 · 本体建模层 1`），
它的作用是回答"我这一页忙了半天都做了什么"，而不是再开一列。

## 2. 知识台账：补齐「属性」，请走「迁到新本体」

### 2.1 四个视角：实体 / 关系 / **属性** / 原文片段

用户说台账是"维护实体、关系、属性新增、删除、修改、融合"的 —— 而**属性以前在台账里没有视角**：
查询那行写死了 `kinds=['entity','relation','chunk']`，把 `attribute` 滤掉了（后端 `current_records`
一直都收 `attribute`）。属性是一条独立记录：

```
{kind:'attribute', subject_id:'e1', type:'urn:ex:重量', value:12, datatype:'integer', …}
```

现在新增「属性」视角，列是 `属性 / 所属实体 / 挂在哪一版本体上 / 版本 / 原文断言 / 操作`：
第一列读作 `属性名 = 值`，第二列是它挂在哪个实体上，操作里仍可「编辑 / 版本历史 / 在图谱定位」
（属性不是图上的点，所以定位转发它**所属实体**的 id —— 与关系行转发 `subject_id` 同一条规矩）。
增 / 删 / 改 / 融合仍走原来的写入通道（编辑弹窗 / 修订 / 软删除 / 实体消歧与融合），本次没有新增写路径。

### 2.2 「把这批知识迁到新本体」从台账撤掉

- **撤掉**：台账里那块面板、它的 KPI 磁贴（"N 条知识挂在旧本体"）、三档处置图例、逐组勾选、
  干跑/确认按钮、`ledger-reclassify*` 那一整套样式，以及对应的 7 条浏览器用例。
- **台账留着什么**：只在真有旧版本知识时显示**一行**提示：

  > 另有 4 条知识还挂在旧本体版本上（3 条能搬到 本体 v2（当前），1 条在新本体里没有去处）。
  > 它们能查、能用，只是类型还是旧结构；要不要搬去「本体建模层」发布新版本的那一步处理（迁移可整批撤销）。

  读不到就什么都不说（不编数字），0 条也不显示（那是最正常的情况）—— 与「结构待定」同一条三态规矩。

- **能力去哪了**：搬到它的**触发点**上 —— 「本体建模层」发布完新版本后那条提示
  （`announceStaleKnowledge`，本来就是"你刚发的新版本还有多少旧知识挂在上一版"的那句话）。
  那里从一个"跳去台账"的按钮，变成真能干的按钮：「把这批知识迁到<当前版本>」。
  点下去是 **干跑 → 确认 → 迁移**：干跑用与真正写入同一个校验（"干跑说行"就一定能迁成），
  确认框里写清会改多少条、怎么撤；三条硬约束仍在界面上：**默认不跑 / 不原地改 / 可整批撤销**。
  服务端口径一处没动（`services/reclassify.py`、`/reclassify`、`/reclassify/preview`），
  台账里「可撤销的操作」照旧认得 `reclassify` 这个操作名并显示为「迁到新本体」。

## 4. 明确不做（免得下次又被问）

- **不在台账里做本体版本迁移**：迁移是本体版本的事，入口跟着触发点走。
- **不在写入页发布本体新版本**：写入页只产出"候选 + 决定"，发布永远在「本体建模层」。
- **不做逐字 token 流式**：抽取是结构化 JSON，要整段拼完才校验 → 这一页是**阶段流式**
  （切片/断言/入图/就绪），这一点在页面上写明了，免得被期待成打字机效果。
- **不新增写路径**：编辑 / 修订 / 软删除 / 融合全是既有接口，写入页用的也是既有上传通道。
- **不迁前端框架**：仍是原生 JS；对话卡、折叠块都是 `createElement` + 事件监听（不用内联 `onclick=`）。
