# 本体能力与 Semantica 对照（2026-10-12）

本轮关注本体如何约束抽取、审核、发布、正式事实和问答，而非逐个包装上游 API。
实际运行使用 Semantica 0.7.0，本地 SentenceTransformer 与 Milvus 均为 1024 维。

| 能力/流程 | 当前落地 | 后续差距 |
| --- | --- | --- |
| 项目本体、类层级、关系和数据属性 | 项目隔离与版本归属；父子闭包、domain/range、属性约束；画布、详情、版本管理 | 尚未集成完整 OWL 推理器，不应把子类闭包等同于完整逻辑推理 |
| 本体驱动抽取 | 按文本选择术语、层级和属性契约，向 LLM 提供切片；最终仍由完整本体校验；每个切片保存选择收据 | 选择器主要是词法命中与图闭包；尚缺向量术语检索、预算优化及召回率评测 |
| 开放发现闭环 | `OntologyDiscoveryWorkflow` 统一持有创建/终结事务、快照校验、运行状态及候选物化；HTTP 适配器不再持有这些规则 | 自动层级建议仍需人工治理；跨本体概念对齐和外部词汇表复用不是完整自动流程 |
| Semantica 质量检查 | 已接入版本化的质量 DTO、指标、阈值和问题列表；引擎不可用及严重错误阻断校验 | competency questions 与自定义阈值尚无完整产品入口；Semantica 警告还需要与现有警告确认流程统一 |
| 人工审核与正式发布 | 快照复核、审批、幂等发布、不可变版本、原子事实计划；HTTP 操作身份绑定登录用户 | 部分兼容 API 仍保留较多编排，可继续收敛到明确的应用用例接口 |
| 发布与派生索引一致性 | 事务 outbox、租约领取、错误与重试、项目版本/模型/记录指纹对账及补偿 | 向量索引是异步投影，客户端需要关注项目对账状态；并非发布后立即强一致 |
| 问答依据与原文 | 主页面流式问答保存 offered 溯源，直接展示冻结标题、原文与版本；文档修改后仍能追溯旧原文 | 非流式 JSON 问答入口尚未统一为同一套持久溯源组装路径 |
| 运行与评测 | 探活/就绪分开，模型与向量能力分开报告；真实检索、发布、原文冻结有验证脚本 | 尚缺基于固定业务材料的本体覆盖率、术语召回率和问答正确率持续评测集 |

## 取舍

优先补质量与 competency-question 评测入口、基于业务材料的本体切片召回评测，以及两个问答入口的溯源一致性。
当有明确的跨域词汇复用需求时再推进本体对齐；需要逻辑蕴含时再选择推理器并定义支持的 OWL 子集。

后台任务使用持久输入和 PostgreSQL 租约，已覆盖摄取、上传、旧数据导入、Milvus 重建和 Neo4j 同步。
取消在处理检查点生效；远程调用尚未返回时，任务状态和结果回写可以被隔离，但已发生的业务写入不自动撤销。
多实例消费上传任务需要共享暂存目录，并保持模型、凭据和任务处理器版本一致。

## 对标依据：上游模块存在，也要核对实际实现

本轮对照了当前环境安装的 Semantica 0.7.0 源码，而不只依据模块介绍：

| 上游入口 | 0.7.0 实际实现 | 对本项目的影响 |
| --- | --- | --- |
| `RequirementsSpecManager` | 提供目的、范围、利益相关者、用例和问题列表的数据模型与追踪入口 | 本项目还缺“业务问题—本体术语—验收结果”的产品闭环，这是优先补的流程差距 |
| `CompetencyQuestionsManager._can_ontology_answer` | 按问题关键词与类名/属性名做启发式匹配 | 不能把此分数直接当作业务问题已可回答。应加入可执行 SPARQL/检索断言和预期答案 |
| `OntologyEvaluator.evaluate_ontology` | 基于上述匹配计算问题覆盖率，再结合结构完整性等指标 | 质量指标可以辅助审核；正式验收仍需有业务样本和错误案例 |
| `OntologyValidator.validate/check_constraint` | 源码明确标为 placeholder；HermiT/Pellet 一致性、可满足性检查并未真正执行 | 不能通过包装这个入口宣称完整 OWL 推理已完成。本项目的 RDF/SHACL/业务约束继续承担真实校验 |
| `ReuseManager.evaluate_alignment` | 主要检查命名空间，并返回简单的固定兼容性评分 | 此入口不足以证明两个领域概念语义等价，跨本体对齐仍需明确映射和人工审核 |
| `ReuseManager.import_external_ontology` | 将 URI 记入 `imports` 并保存复用决策，没有在此方法中拉取和合并 RDF 内容 | 外部本体复用要补导入闭包、冲突处理、版本固定与发布审查，不能只添加一个 URI |

因此优先级应是业务验收问题与可执行测试、切片召回评测、两种问答入口的溯源一致性。
已经接入的 `ontology_quality_check` 属于质量门禁，不等同于上述占位推理入口；完整推理和自动对齐需单独选择实现并验收。
