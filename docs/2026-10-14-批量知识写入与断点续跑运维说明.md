# 批量知识写入与断点续跑

## 上传和并发

在「知识写入」选择项目和提取模式，添加文件。在「高级解析设置 → 解析并发」选择自动推荐、1、2、4 或 8。系统能力接口给出当前文件数与大小上限；默认每个批次最多 1000 个文档，5000 份规则应拆为多个批次。

点击「上传并处理」。浏览器最多同时上传 3 个文件，上传完成后才开始处理。部分上传失败时，成功文件保留，点击「重试失败」补传。批次卡显示申请并发、实际并发和完成/排队/需要处理数量。申请 8、实际 4 表示当前服务端上限为 4。

批次详情每页最多 50 行，使用状态筛选及「下一页」查找文件。可「暂停」「继续」「重试全部失败」「取消未开始文件」，或「下载失败明细」。取消不撤销已经完成的知识。

## 失败处理

临时超时、限流和服务不可用会自动重试；文件行显示自动重试次数、下次时间、失败阶段及切片。认证错误、文档损坏、缺失附件和 OCR 低置信度需要人工处理。同批大量相同模型错误会暂停批次，检查模型连接后点击「继续」。

失败文件提供三种操作：

| 操作 | 适用情况 |
|---|---|
| 从断点继续 | 默认操作；复用配置兼容的成功切片，继续失败和未完成切片。 |
| 只重试失败切片 | 重新执行明确失败的切片，未开始切片保持待处理。 |
| 整份重新处理 | 更换文件、模型、本体或关键设置后，创建新尝试，重新解析和抽取。 |

原文件、切片、本体版本、模型、提示词版本或抽取设置变化时，不能自动复用旧检查点。不要把不兼容检查点当作当前输出。服务重启后，租约到期的文件可以从成功检查点继续。

## Markdown 知识包与图片 OCR

规则脚本推荐 Markdown + 相对附件 ZIP；Word 继续用于人工办公文档。ZIP 可包含多份 Markdown 和共享图片，图片路径必须在包根目录内。没有 manifest 时自动发现 `.md` 文件。

本地图片先经过 OCR，识别文字再按所选模式抽取或建立仅文档检索索引。OCR 只能识别文字，不证明流程线、图标或空间关系的语义。网络图片只登记为「外部图片，未固化」，不自动下载。

OCR 失败或低置信度会阻止该文档提交。在来源阅读器「解析视图」核对文字、引擎与置信度，点击「重试 OCR」。若图片确实没有知识文字，点击「该图片无知识文字，忽略并继续」，填写原因；系统保存操作者、时间和原因。处理完成后回批次卡「从断点继续」。缺失图片请重新上传包含正确附件的知识包。

## 原文阅读器和图谱来源

在原文数据源或知识详情证据中点击「在原文中打开」。阅读器固定到该知识引用的来源版本：

- 阅读视图：阅读标题、正文、表格和固化图片，定位并高亮来源块。
- 解析视图：检查块、源文件行号、OCR 文字、置信度和图片区域框。
- 原始视图：只读源文件并下载固定版本原文件。

来自图片 OCR 的证据显示原图文字坐标框。多来源知识分别核对每个证据分支。旧记录没有映射时明确显示缺失，不自动跳到当前新版文档。

## 部署与检查

Python 统一使用 `D:/anaconda/envs/llm_model/python.exe`。先运行迁移，再启动新版服务：

```powershell
& D:/anaconda/envs/llm_model/python.exe -m knowledge_service.repository.migrate
& D:/anaconda/envs/llm_model/python.exe scripts/verify_ocr_models.py
```

OCR 权重位于 `data/model/ocr/pp-ocr-v6-small`，服务只读取本地权重，不在业务请求中下载。通过 `scripts/install_ocr_models.py --source <已校验模型目录>` 离线安装。权重哈希或运行时不匹配时先修正部署，不绕过校验。

原始文件存储由 `KG_SOURCE_OBJECT_ROOT` 指定，数据库备份必须同时保留对象仓库。只删除已无业务引用的对象。查看公开错误即可定位阶段，不将密钥或供应商原始响应复制到错误明细。

## 模型目录迁移与识别基准

向量模型与 OCR 分开放置：`data/model/embedding/bge-m3` 和 `data/model/ocr/pp-ocr-v6-small`。`scripts/prepare_model_layout.py --verify-encoding --env .env` 先复制并逐文件校验，再实际编码成功后修改路径；原权重保留供回退。已有向量使用的模型标识通过 `KG_EMBEDDING_IDENTITY` 保留；只有权重相同才可沿用，不用于掩盖模型变化。

本机已验证向量输出为 1024 维。OCR 真机基准见 `docs/research/2026-10-14-image-ocr-benchmark.json`，重跑使用 `scripts/benchmark_image_ocr.py --model-root data/model/ocr/pp-ocr-v6-small`。中文和正常方向英文识别通过；空白图片及本次旋转英文样本被质量门拒绝。置信度不是准确率，旋转、小字号或复杂表格应人工核对。
