# 资料原件存储与图文阅读

## 数据分工

原件用于下载、重新解析和核对。资料库阅读使用固定版本的解析正文、表格、图片及其顺序；检索使用正文和通过质量校验的 OCR 文字。

| 内容 | 保存位置 |
| --- | --- |
| 原始 PDF、Word、Markdown、ZIP 和提取图片 | MinIO 私有业务 bucket |
| 正文、块顺序、来源版本、附件关系、解析及 OCR 记录 | PostgreSQL |
| 检索投影 | Milvus；其 MinIO bucket 与业务文件分开 |

图片通过项目鉴权的后端接口加载，浏览器不接触 MinIO 凭据。对象键保持 `哈希前两位/完整 SHA-256`，相同字节复用存储，但文档版本和证据引用保持独立。

## 配置与本地模型

在现有 `llm_model` 环境安装 S3 存储 extra：

```powershell
& D:/anaconda/envs/llm_model/python.exe -m pip install -e '.[s3]'
```

MinIO 预建私有 `knowledge-sources` bucket，为业务账号配置该 bucket 的 ListBucket/GetBucketLocation/GetObject/PutObject/DeleteObject 权限。不要复用 Milvus 的 bucket 和管理员账号。凭据仅保存到本机配置或密钥管理系统。

应用配置键见 `.env.example`：

```dotenv
KG_SOURCE_OBJECT_BACKEND=s3
KG_SOURCE_S3_ENDPOINT=http://127.0.0.1:9000
KG_SOURCE_S3_BUCKET=knowledge-sources
KG_SOURCE_S3_ACCESS_KEY=<专用账号>
KG_SOURCE_S3_SECRET_KEY=<专用密钥>
KG_SOURCE_S3_REGION=us-east-1
KG_DOCUMENT_ARTIFACTS_PATH=data/model/document-parser/docling
KG_SOURCE_REMOTE_IMAGES_ENABLED=true
```

部署前准备 PDF 所需的布局、表格和 OCR 模型，再仅校验本地文件：

```powershell
& D:/anaconda/envs/llm_model/python.exe scripts/prepare_document_models.py
& D:/anaconda/envs/llm_model/python.exe scripts/prepare_document_models.py --check
```

请求处理只使用本地模型，PDF 模型缺失时明确返回 `model_unavailable`。DOCX、TXT 的处理不依赖 PDF 模型目录。`KG_DOCUMENT_OCR_MODE=disabled` 禁用 PDF OCR。

## 从本地文件与旧队列迁移

1. 保存数据库、来源对象和批次原件备份，暂停上传、来源 GC 和 worker，并停止旧后端。旧进程无法读取迁移后可空的 `content`。
2. 执行正式迁移入口，应用当前全部编号迁移：

   ```powershell
   & D:/anaconda/envs/llm_model/python.exe -m knowledge_service.repository.migrate
   ```

3. 在维护命令进程设置目标 S3 配置，先运行默认核查：

   ```powershell
   $env:KG_SOURCE_OBJECT_BACKEND='s3'
   & D:/anaconda/envs/llm_model/python.exe scripts/migrate_source_objects.py --source-root data/sources --output .benchmarks/source-rich-reading/inventory.json
   ```

4. 核对无错误后显式复制和更新队列引用：

   ```powershell
   & D:/anaconda/envs/llm_model/python.exe scripts/migrate_source_objects.py --source-root data/sources --apply --output .benchmarks/source-rich-reading/migration.json
   ```

5. 再次核查所有目标对象，确认大小和完整 SHA-256；将应用配置设为 S3，再启动新版后端，验证原件下载、图片读取、资料阅读及固定版本定位。

工具不会自动切换配置、创建 bucket、修复或删除本地文件。默认核查不修改任务状态；`--apply` 也不会触发无关摄取运行的启动恢复。原件从目标存储完整校验通过后，旧队列才清空 BYTEA 并保存对象引用。重跑可以复用已校验的目标对象。

缺失文件仅从哈希完全一致的旧队列字节或冻结 Markdown 恢复；ZIP 内的一篇 Markdown 不能充当原始 ZIP。无法恢复的对象在报告中标记为错误，须处理后再切换。暂停的整份 ZIP 重试仍会查找其上一来源版本。

## 导入与阅读边界

- PDF、Word 提取图片和可获得的页码/区域、图注，使用有序解析结果阅读；原始文件始终单独保留。
- Markdown 相对图片随 ZIP 上传，Base64 图片可直接固化。公开 HTTP(S) 图片在导入时按大小、类型、网络地址和重定向限制抓取；登录链接、失效链接和私网地址显示缺图状态。关闭 `KG_SOURCE_REMOTE_IMAGES_ENABLED` 可禁用外链抓取。
- 阅读不重新访问外链。图片能显示与 OCR 是否成功是两回事：仅文档模式保留可读内容并提示 OCR/缺图问题，知识抽取模式继续执行严格的 OCR 质量检查。
- 重新解析生成新的来源版本。旧证据继续引用原版本；更新阅读格式不会重写历史证据。
- 图文展示不等同于理解流程图或曲线的含义；OCR 文字及其质量状态单独保存。

## 备份、恢复与核对

PostgreSQL 备份须与业务 bucket 一起保留。只备份数据库无法恢复原件和图片；只备份 Milvus 的 bucket 也无法恢复业务资料。恢复后按对象清单逐个核对大小和 SHA-256，下载固定版本原件检查字节一致性。

保留本地迁移回退副本和迁移报告。迁移新增的队列原件若原本不在本地，回退到 local 前需从 S3 按清单校验复制回来，或恢复配套数据库备份；不能只修改 backend 就认定回退完成。

### `data/sources` 能否删除

当前本机已切换 S3，运行时不再依赖这个目录。清理其他环境时须同时满足：所有登记对象在目标端完整读取并核对大小和 SHA-256（迁移报告每项 `destination=verified`），队列旧 BYTEA 已迁移，并已核对未登记的本地文件。仅看 `error_count=0` 不够，dry-run 的 `would_upload` 仍表示目标缺少文件。

2026-10-29 先将本机整个目录移到被 Git 忽略的验收备份位置，核对 32 个文件，其中 14 个有登记引用、18 个没有登记。随后在原目录不存在时验证全部登记对象、正式页面及新上传均正常，没有重新创建该目录。用户确认不再保留旧文件后，验收备份也已移入 Windows 回收站，原位置已清理。不要删除 MinIO 的业务 bucket 或 Docker 数据卷。

当来源原件缺失且无法精确重建时，原件接口返回明确的 `source_object_unavailable`。解析正文仍可能可读；图片缺失会单独提示。不要把解析文本重新打包成 PDF/Word 冒充原件。
