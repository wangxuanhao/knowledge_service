# 平台规则文档上传规范

本规范适用于“平台经济规则”资料。图谱默认展示全部业务时间，用户可通过现有时间筛选查看当前或指定日期的知识。资料时间自动识别与 HTML 表格图片支持的验收进度见同日实施计划。

## 推荐上传结构

每个平台分批准备 ZIP，保留 Markdown 与图片的相对目录。下列目录既可以放在 ZIP 根部，也可以整体放在一个平台子目录中。

```text
抖音电商-第01批.zip
├── 规则A.md
├── 规则B.md
└── assets/
    ├── a.png
    └── b.jpg
```

规则A.md 中的图片引用保持以下形式。

```markdown
![违规场景示例](assets/a.png)
```

包含合并单元格的原始规则也可能使用 HTML 表格。

```html
<table>
  <tr>
    <td>违规场景</td>
    <td><img src="assets/a.png" alt="违规场景示例"></td>
  </tr>
</table>
```

相对路径按每份 Markdown 所在目录解析。文件名大小写、中文、空格与压缩包中的实际名称应一致。多个文件可引用同一 assets 图片。使用 UTF-8 编码保存 Markdown。

单个 .md 的上传内容为文本。带本地图片的资料通过上述 ZIP 一并提交。上传后图片固化到业务来源对象存储，原文通过对应来源版本的鉴权资产接口读取。

## 分批范围

目前服务能力的默认值为单个上传文件或 ZIP 25,000,000 字节、一个批次最多 1,000 份资料、一个批次上传量最多 1,000,000,000 字节。实际值以系统返回的上传能力为准，管理员配置可能改变这些值。

ZIP 解析另外限制最多 5,000 个成员、解压后总量 512 MiB，以及压缩比。平台目录达到数 GiB 时，按文档及其引用图片拆为多个包。每个包保留自身所需图片，优先按文档与图片大小拆分。

ZIP 自动发现其中所有 .md。规则原件与引用图片进入资料包，采集脚本、开发配置、缓存和工作台账分别保存在资料包外。需要精确指定规则文件时可采用下节的 manifest。

## 可选 manifest

ZIP 根目录可放 manifest.json，用于明确选择规则及保存逐文件来源字段。以下为字段示例，规则 ID 与来源链接按实际采集值填写。

```json
{
  "documents": [
    {
      "path": "规则A.md",
      "title": "规则A",
      "metadata": {
        "rule_id": "rule-a",
        "source_url": "https://example.com/rule/rule-a"
      }
    },
    {
      "path": "规则B.md",
      "metadata": {
        "rule_id": "rule-b"
      }
    }
  ]
}
```

path 使用压缩包内的完整相对路径。平台、业务及适用对象通过该上传批次的现有范围控件填写。自动识别时间按各文件正文分别解析；手工填写的时间为该次上传的明确覆盖值，上传前核对适用范围。

根目录 manifest 含 documents 时按该清单及顺序导入，清单里的 title 和 metadata 分别应用到对应文档。没有该清单时，系统遍历包内所有 .md 并按路径排序。打包脚本将 manifest.json 放在 ZIP 根目录，保留子目录中的 MD 和附件。

## 上传前预览 ZIP

上传区在选择文件、资料与处理方式、确认处理三个步骤中均保留，支持继续拖放追加文件，并同步更新确认数量。格式、超限等提示在当前步骤直接显示。

选取 ZIP 后，使用独立的“预览原文”和“预览切片”按钮。原文窗口展示图文正文、图片与附件状态，支持图片放大。切片窗口展示片段列表、文字、数量及位置。两个窗口都可通过“ZIP 内文档”选择器逐份切换，日期识别结果随对应资料展示。

预览图片使用包内原件，缺失、不可读和外链待固化有独立提示。OCR 与知识抽取在正式处理批次执行。预览临时文件在响应后清理，图片浏览资源在切换或关闭时释放。

当前支持单独 MP4/WebM 和 MD 引用的本地视频。视频放在 assets 中，正文使用 `[观看视频](assets/clip.mp4)` 或 `<video src="assets/clip.webm"></video>`。打包工具会收集实际引用的视频，预览可播放，正式处理生成带起止时间的 ASR 文字。视频上限为 25 MB、600 秒，编码范围为 H.264/AAC MP4 或 VP8/VP9/AV1 与 Opus/Vorbis WebM。远程视频引用显示待固化状态。现行实现与扩展格式设计详见同日多模态文档。[多模态设计](superpowers/specs/2026-11-10-multimodal-rule-package-design.md)

## 日期与状态

保留原文件中的发布时间、生效时间、失效时间及“是否生效”等内容。自动识别将明确的文档级结果写入现有规范字段，并保存原文与定位依据。规则条款中的发货、退款、申诉期限继续作为对应业务知识抽取。

首次生效、最新修订生效和修订公告的目标规则分别判定。缺失或冲突的日期在结果中标为未知或待核验。采集到的“已失效”状态与具体失效日期分别保存。

## 原文阅读与核对

1. 在资料库的“添加文件”中选取 ZIP，核对服务返回的能力与包内文档数量。
2. 填写该批平台及适用范围，保留默认的“自动识别每份文档时间”，选择本次资料处理模式。手工填写的具体时间字段作为该批明确覆盖值。
3. 在预览、处理结果和资料详情中核对时间。打开原文，检查正文、表格及图片的顺序，展开“识别依据”查看日期原文及解析正文位置。
4. 对图片缺失或不可读提示，核对 Markdown 相对路径和压缩包成员。图片读取与 OCR 结果分别核对，图片可见本身不代表图片中的文字已经可靠抽取。
5. 按全部业务时间、当前有效和指定日期查看检索及图谱结果，核对节点、关系及来源片段。

图片支持范围依据当前来源解析能力，包括 PNG、JPEG、WebP、GIF、BMP、TIFF。网页阅读展示清理后的文章内容、表格与图片，脚本及活动属性按现有清理规则处理。

## 图文阅读与已保存正文

这两个入口属于同一份资料，分别服务于阅读原文和核对知识处理输入。

| 入口 | 展示内容 | 核对用途 |
| --- | --- | --- |
| 图文阅读 | 固定来源版本经过清理的排版、标题、表格与图片 | 核对原文上下文、表格和图片，放大图片阅读 |
| 已保存正文 | 文档记录中保存的解析文本，以纯文本展示 | 核对切片、抽取和检索所使用的正文 |

图片成功经过 OCR 后，识别文字可以进入已保存正文。图文阅读继续通过固定来源版本展示图片。旧资料缺少固定来源版本或图文读取暂时失败时，页面使用已保存正文作为回退。

## ZIP 上传后的存储

本机当前业务来源使用 S3 兼容的 MinIO，bucket 为 knowledge-sources。

| 内容 | 存储位置 | 关联方式 |
| --- | --- | --- |
| 上传的完整 ZIP，包含选中的 MD 与附件 | MinIO 来源对象 | 按 SHA256 寻址，同一包内多份资料关联原包 |
| 解析成功的图片字节 | MinIO 独立图片对象 | 每个来源版本登记图片、原始路径、尺寸和校验信息 |
| 单独上传的原始 MD | MinIO 来源对象 | 固定来源版本关联原件 |
| 每份 MD 的冻结文本、解析块与阅读 HTML | PostgreSQL | 来源版本关联对应资料和图片 |
| 已保存正文、切片、OCR 结果、元数据与知识证据 | PostgreSQL | 文档、来源版本、原文片段与知识记录关联 |

ZIP 内各份 MD 分别建立来源版本，原始文件对象共享完整 ZIP。下载选中的 Markdown 时，服务使用对应版本的冻结正文。页面图片经带项目与版本校验的来源接口读取，因此上传完成后可以从服务器读取图片。

对象键按内容哈希保存，原始文件名与图片相对路径由来源版本元数据关联。

## 选取部分 MD 自动打包

打包入口为 scripts/package_rule_documents.py。在仓库根目录使用既有 llm_model 环境运行。

先编辑一份 UTF-8 文本清单，每行写相对采集根目录的 MD 路径。空行及以 # 开头的说明行可以保留。

```text
抖音电商/创作者管理_「违规营销：憋单」实施细则_aHsCBTFBK4YS.md
抖音电商/专题解读_生鲜和鲜花绿植虚假宣传规则白皮书_aJkzdMC7vZJy.md
```

然后运行以下命令。

```powershell
& 'D:\anaconda\envs\llm_model\python.exe' scripts/package_rule_documents.py `
  --root 'D:\workspace\知识图谱源数据\平台经济规则' `
  --list-file selected.txt `
  --output-dir 'D:\workspace\knowledge_service_v2\outputs\我的规则包-第01批'
```

输出目录应使用新目录名。脚本逐份解析选中的 MD，收集标准 Markdown 和 HTML img 引用的本地图片，按采集根目录保留相对路径。同一包内共享图片去重，原始 MD 与图片字节保持一致。图片缺失、格式不支持或路径异常时给出对应文档与图片引用，补齐后可以重新运行。

默认按每包最多 200 份 MD、24,000,000 字节自动拆包，较大的选择清单可以生成多个 ZIP。每包包含 manifest.json，输出目录还包含 packaging-report.json，可核对文件、图片、大小与 SHA256。使用 ZIP_STORED 编码，包体积可预测并满足现有压缩比校验。

少量文件也可重复使用 --file 参数。使用已有 JSON 清单时选择 --manifest，格式与前文的 manifest 相同，显式提供的 title 与 metadata 随对应文档打包。平台与业务范围仍需核对上传批次的范围控件，任意 metadata 键对应的筛选能力以系统已实现字段为准。

外链图片保留原 URL，并在打包报告中列为警告。上传时按系统远程图片导入配置尝试固化，离线可读性需要核对固化结果。本地 assets 图片随 ZIP 一起提交。

真实三份资料的案例、选件清单与使用说明位于 D:/workspace/knowledge_service_v2/outputs/platform-rule-package-example。

## 本轮验收与边界

时间提取覆盖明确字段及文档自身的生效、失效和修订表述，复杂相对日期或歧义表述保留未知或待核验。时间筛选使用规范生效/失效字段，平台原始状态单独保存。仅有“已失效”而缺失日期时显示待核验，统一业务状态的推理和筛选属于后续步骤。
