# 类型不合适或重复时怎么处理

类型定义与实体实例是两种对象。把“直播人员”归并到“主播”，不意味着把张三与李四合成一个人。

| 遇到的情况 | 操作入口 | 对已有实体的影响 |
|---|---|---|
| 类型只是名称或说明不准确 | 本体建模层，编辑术语名称和说明，审核发布 | 类型 IRI 保持不变，不自动改变实例身份 |
| 个别实体分错类型 | 知识台账或实体详情的“编辑” | 纠正该实体分类，产生新修订；原绑定本体外的新结构走受控迁移 |
| 两个实体类型表示同一概念 | 类型详情 → “合并到已有类型” | 草案阶段不改实体；发布后预演并确认迁移旧知识 |
| 类型不再适用 | 术语详情 → “停用这个术语”，可选替代术语 | 保留旧实体和历史，不级联删除；没有替代目标时不自动迁移 |
| 同一个实体被抽成两条记录 | 知识台账中的实体合并 | 这是实例身份合并，须单独核对，不能由类型合并代替 |

## 重复类型合并

1. 在“本体建模层”选择需要归并的源实体类型，展开“合并到已有类型”。历史版本只读；源和目标都必须启用。
2. 选择保留的目标类型，填写合并原因。
3. 点击“准备草案并预览影响”。如没有工作草案会准备一份；如果已有多份，需要先明确选择目标草案。该操作不迁移实体。
4. 核对影响的正式知识、关联关系、父类及约束变更。目标保留原名称和说明，源标签可成为目标别名；源类型保留为停用术语并记录替代目标。
5. 点击“确认合并变更加入草案”，逐项审核后发布。部分批准只代表部分结构修改获批，不能视为整个合并已完成。
6. 发布后点击“打开受控重分类”，选择旧知识分组，先预演，再确认迁移。迁移保留实例 ID、正文、有效期与历史，按新结构校验实体、关系和属性。
7. 在知识台账核对新修订与类型。若需回退，使用迁移结果或操作历史中的撤销入口；后续又被修改的记录可能阻止撤销，应按当前状态处理。

源与目标不能相同，也不能把类合并成关系或属性。父类循环、不支持的语义引用等会阻止自动合并，应先明确处理这些结构。预览后若目标、草案或关联知识改变，需要重新预览，不会按旧影响面直接执行。

## 类型不再适用

在“停用这个术语”中，可选同种类且启用的替代术语，再填写原因并加入草案。活动子类或约束仍引用源术语时，服务会要求先处理依赖。

选择替代目标不会立即迁移实体，仍须审核发布后预演并确认。未指定替代目标时，旧知识与版本历史保留，但没有自动迁移去处。

多次演进如“旧分类 → 中间分类 → 当前分类”，重分类会追踪到最终启用目标。若存在循环、多个替代目标、跨种类映射或失效终点，会明确阻止迁移并提示核对映射。

## 能力边界

本次专用合并入口支持实体类型。关系类型和属性类型支持停用及同种类替代，但不机械合并不同关系含义或属性数据类型。类型拆分需要逐记录或按明确规则分类，本次未实现自动拆分。尚未发布的候选须重新核对映射，不会因为类型合并而自动获批。
