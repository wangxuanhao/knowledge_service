知识写入：准备文件、批次处理与结果核对

按选模式、准备文件、设置解析与并发、上传、处理失败、核对结果和原文的顺序完成一次写入。固定材料用于演示，实际模型的措辞、数量和置信度可能变化。

先选对知识写入模式

这三项是“知识写入模式”，不是三种推理方式。只有前两种会做图谱抽取。

模式什么时候用是否入图结果去向
使用项目本体 · 正式入图已有稳定的类、关系和属性定义，要按当前本体抽取。通过的知识正式入图；待确认项保留待审核。已入图去知识台账；待审核去知识审核。
开放本体发现 · 候选暂存文档可能出现当前本体里没有的概念，先发现再人工决定。开放发现不正式入图。发现结果全部作为待建模候选暂存，不直接进入正式图谱。去本体画布处理候选；人工建模与审核后才能成为正式结构。
仅文档检索 · 不抽取图谱只要保存切片供全文/向量检索，不需要实体、关系或属性。否。这是主动不抽取，结果里没有实体是正常情况。去原文数据源核对文档和切片。

查看批次进度

操作：按状态筛选文件，用“下一页”查看后续文件。需要时暂停或继续；取消未开始文件不撤销已完成知识。遇到失败先按下面的恢复说明处理。

看到：每个文件有明确状态，失败行显示阶段、切片、公开原因、自动重试次数和下次时间。

失败恢复：先处理原因，再选择继续方式

临时超时、限流和服务不可用自动退避重试。同批大量相同模型错误会暂停批次，检查模型连接后点“继续”；自动重试耗尽后需要人工处理，可下载失败明细逐文件核对。

操作何时使用之后核对什么
从断点继续原因已解决，继续失败与未完成切片。兼容的成功切片被复用，文档继续处理。
只重试失败切片只重新执行明确失败的切片。未开始切片仍待处理，之后用“从断点继续”完成。
整份重新处理模型、本体或关键设置改变，旧检查点不兼容。产生新尝试，旧尝试与来源保留；修正文件内容须重新上传。

图片 OCR 失败怎么处理

ZIP 内本地图片先 OCR 再提取文字知识。OCR 失败或低置信度会阻止文档提交：点“查看原文与 OCR”，到解析视图核对文字、引擎和置信度，再点“重试 OCR”。若确认图片无知识文字，点“该图片无知识文字，忽略并继续”，填写原因；系统记录操作者与时间，然后回批次“从断点继续”。缺失附件应补齐知识包后重新上传。

网络图片显示“外部图片，未固化”；OCR 只识别文字，不能判断流程线与图标语义。

结果工作区五类分支

看到什么点击哪里完成标志
已入图去知识台账核对在实体、关系、属性视角核对到正确的知识和来源。
待审核去知识审核对待确认知识完成收下、退回或不收的决定。

失败先核对批次行错误与失败明细；旧任务可查看任务日志根据错误原因修正文件、模型或运行配置，再重试。

核对固定版本原文：确认知识来自哪里

在图谱知识证据或原文数据源点击“在原文中打开”。阅读视图核对正文、表格与固化图片；解析视图核对块、行号、OCR 文字与图片区域框；原始视图只读源码并下载固定版本原文件。

来自图片 OCR 的知识应能定位到原图文字区域。多来源知识分别核对各个证据分支；历史映射缺失时页面明确说明，不自动跳到新版文档。

主知识图谱：拖节点、平移、缩放

操作：进入“检索与交互图谱”，选实体或点“重新渲染全图”。拖节点调整位置，拖空白平移；滚轮或“放大 / 缩小”按钮调整缩放。点节点或连线查看右侧详情。

动作看到什么是否修改知识
拖动节点仅被拖节点移动；松手不弹详情、不把全图重新缩放否
拖空白 / 滚轮画布平移 / 缩放否
适应画布 / 双击空白恢复可见视图，保留已摆放节点的坐标否
重新布局自动重新排列节点，放弃本次手工摆放否
在详情点编辑并保存创建新修订，台账与图谱刷新是；仍走原版本校验
完成标志：同范围刷新后，节点摆放和缩放保持；单纯拖动没有生成知识修订。切项目或清理工作区会清理本次布局与路径会话。

路径循迹：看清两个对象如何关联

操作：展开画布下方“路径循迹 · 当前已加载图谱”。选择起点、终点；也可点一个实体，在详情中使用“设为路径起点 / 设为路径终点”。同名对象在选项中附编号，请核对后选择。

选择“按关系箭头”或“忽略方向”，设置最大跳数，再点“寻找路径”。示例：平台 A → 适用规则 → 规则 R → 要求材料 → 材料 M。

看到：画布突出显示一条按边数最短的路径，下方链条给出关系与跳数。点链中的关系查看该条事实的证据、有效期和修订；逆向经过的步骤明确标注，原关系箭头不改变。

改起终点、方向、跳数后重新寻找；切范围、更新关系端点或修订后，旧路径清理。点“清除路径”恢复普通展示。

完成标志：路径链条与高亮相符，每条关系可回查；无结果会说明“当前已加载图谱及所选方向、跳数内未找到”。
循迹只搜索当前画布已显示的实体和关系，不是全库寻路；类型筛选或局部邻域可能隐藏中间节点。需要时先扩大已加载范围。最短链只说明关联，不代表因果或业务规则推导；虚拟属性值节点不参加寻路。

  • 版本冲突：其他操作已修改记录。重新读取最新修订，核对变化后再编辑；不要手工提高预期修订号强行覆盖。

问答原文、Milvus 与本体质量怎么验收

把消费层看到的依据、运行时向量能力和本体发布门禁放在同一套验收口径里。

问答先看原文，再看结论。 每条回答下方的前三条依据默认展开；每条依据的第一份冻结原文默认可见。 “另有 N 个来源”只展开这一条依据的其他来源，“再看 N 条依据”才展开其余依据。

多平台规则文档：先核对时点，再看回答依据

本功能直接利用已上传的业务规则原文，不需要接入订单等外部业务数据库。属性抽取是可选增强；没有属性仍可查条款、比较文档并查看原文，不能因此保证完成全量数值筛选或统计。

  1. 进入“知识问答”，选择当前项目及平台范围，提出条款问题或平台比较问题。每个平台分别取证，缺项表示未检索到合格依据，不表示该平台没有规定。 未限定平台时，未维护平台归属的原文仍可作带提示的文档说明；指定平台时不借用归属未知材料形成该平台结论。
  2. 核对“规则判断时点（本地时间）”：留空查当前，填入历史时间查当时。生效起点包含、失效终点不包含；到失效时刻即不再有效。只改业务时点不会自动把系统已知时点也改成历史。
  3. 按需勾选“显示历史／未来／待核对参考”。历史与未来内容作为独立参考展示，不参与本次时点有效规则的结论。参考有独立数量限制，提示未覆盖全部内容时不要当成完整规则清单。
  4. 核对每个编号和来源。点击编号打开冻结溯源，核对文档版本、原文位置和时间；缺少来源时先核对维护记录，不拿最新原文替代旧版本。
分区与编号如何使用
E · 有效依据支持本次判断时点的规则回答；历史查询中，当时有效的旧规则也可进入这一组。
U · 有效性待核对允许依据原文说明，但明确标注有效性待核对，不宣称当前有效。缺日期不等于失效，不需要先补齐属性才能查看内容。
R · 已失效参考可查看与追溯，不作为本次规则结论依据，不进入组织当前结论的模型输入。
F · 尚未生效参考可核对未来规则及起始时间，不提前用于本次规则结论。

有效期主要取记录的 valid_from / valid_until，时间来源由 effective_time_source 说明。仅有发布时间时可能只是推定生效，须核对；上传时间、系统修订时间，以及 ready / failed 处理状态都不代表业务生效或失效。同一实体的多个来源要分别核对，不能把失效来源混入有效实体的依据。原文版本和有效期核对版本可能不同：后来维护的失效时间会参与判断，但“查看原文”仍定位当初引用的正文；在来源详情分别核对版本与日期。

等待回答时：需要先核对规则时可关闭模型生成，直接查看证据；开启生成时先看证据，再等流式正文。若明显变慢，交给维护人员核对检索、证据准备和模型首字的分段耗时。关闭额外参考只控制参考展示，不会放宽有效期或平台校验。不要为提速跳过原文核对。

完成标志每个平台的结论都有相应原文；已失效条款只在参考中；缺有效期的原文明确提示待核对；点击编号能看到本次冻结版本，缺失来源会有提示。
图谱关系路径不是 OWL 推理。它只展示命中实体沿现有关系边可到达的多跳路径，用来解释“这些实体在当前图中怎么连”。它不根据 OWL 公理生成新事实。本阶段暂不实施 OWL 推理，也不把路径展示宣称为 OWL 2 RL 能力。
冻结来源

不追当前版本

标题、摘录、文档版本与检索通道来自生成答案时保存的 offered 溯源分支；手工录入或历史缺口会明确标注，不拿今天的文档补写。

运行能力

Milvus collection_ready

项目与运行的健康信息要同时核对 configured、connected、collection_ready、实际维度与期望维度。已配置但不可用时状态是 degraded。

发布门禁

Semantica 质量检查

草案校验保留 Semantica 版本、指标、阈值与问题列表；质量引擎不可用属于阻断错误，不能假装校验通过。

本体切片收据：受控抽取应记录用了哪个本体版本、命中了哪些术语以及选择原因；看到降级为全本体时要单独审核，绝不能静默切换成开放发现。
  1. 问答完成后，先直接阅读默认展开的原文，再核对答案中的 [E1] / [E2]。
  2. 需要审计时点击引用编号，打开完整的历史溯源抽屉。
  3. 到“项目与运行”核对本地模型 identity 与 1024 维是否和 Milvus collection 一致。
  4. 草案接口的 validation_report.semantica_quality 保存 Semantica 质量报告；阻断项修复后重新校验。 当前页面主要展示现有业务校验警告，Semantica 警告尚未统一接入逐条确认入口，需另行核对质量报告。
完成标志问答能直接看到冻结原文；运行状态显示 1024 维且 collection_ready；草案保存 Semantica 质量报告。
常见误解只看到回答正文不代表可追溯；只看到 Milvus 进程 healthy 也不代表 collection 与模型维度一致。

身份、任务和索引同步怎么核查

发布版本与索引同步分别核查；任务失败可查看原因并重新处理。

审计人由登录身份决定。 创建、审核、发布和重分类由服务器记录用户 ID、用户名和显示名；页面不能指定另一位操作人。 关闭认证的环境会明确显示“未启用认证”。
统一运行环境：本项目的 Python/pytest 命令使用 conda 环境 llm_model。
  1. 探活访问 /livez；就绪检查访问 /readyz。模型仍在加载或必需向量后端不可用时，就绪返回 503。
  2. /api/health 的 capability_matrix 分别报告 keyword、semantic、llm、ocr、neo4j。 semantic 为 ready 才代表真实模型已完成编码验证且向量 collection 就绪；远程 LLM 未探测时显示 degraded。
  3. 本体发布成功意味着权威版本已提交。索引由后台 outbox 同步，pending/running/retry_wait 都不表示索引已完成。 disabled 表示未启用 Milvus，failed 保留失败原因。只有 completed 才表示消费成功。
  4. GET /api/projects/{项目ID}/ontology-index 查看权威版本与索引版本；POST 同一路径的 /repair 触发补偿。
  5. 维度自动读取本地 model 的 config 并核对真实编码输出；不要把 1024 当成所有模型的固定值。 换模型导致维度不匹配时，“构建语义索引”会迁移共享集合并恢复全部项目；普通重建只处理当前项目。 rebuilding 期间项目对账不报告 ready；失败后重试会继续恢复全项目，不能把空集合当完成。
  6. 进入“项目与运行 → 后台任务”，任务卡片可取消、重试或重新排队。 接口对应 POST /api/jobs/{任务ID}/retry、/cancel、/resume。 重启后持久任务会在原租约过期后重新领取；取消在下一个处理检查点生效，已提交的事实不自动回滚。 上传文件在停止任务期间保留以支持重试。
完成标志能辨认当前用户、模型就绪、任务状态和权威版本与索引版本是否一致。
常见误解Milvus 进程 healthy 或本体发布成功都不能替代项目索引对账。

卡住时按现象排查

每一项都给出“看到什么 / 原因 / 下一步”，不要只停在错误描述。

拖节点后想恢复摆放

看到什么节点位置被手动调整。

原因拖动只改布局，不改知识。

下一步只想找回视图点“适应画布”；想自动重排点“重新布局”。

循迹找不到路径

看到什么当前方向和跳数内未找到。

原因可能有方向限制、中间实体被类型筛选隐藏，或邻域尚未加载。

下一步核对起终点与方向，适当增加跳数，扩大当前已加载图；不要据此断言全库没有关系。

属性表单无法保存

看到什么格式、时间、版本冲突或本体归属提示。

原因值类型、有效期或预期修订不满足保存条件。

下一步按提示修正，核对所属实体；版本冲突先刷新再比较，未知归属先治理。失败不会清空已填表单。

创建项目后看不到本体

看到什么本体建模层提示读不到状态或空画布。

原因项目尚未选中，或页面还在加载。

下一步先在左上角选择项目；仍为空就刷新页面，再确认项目模式是加载默认本体。

发布按钮是灰的

看到什么按钮不可点。

原因草案未校验、仍有待审核操作、没有发布说明，或警告未确认。

下一步从底栏提示依次处理：校验并审核 → 逐条处理 → 填发布说明 → 确认警告。

属性没有画在本体节点上

看到什么画布只看到类和关系。

原因v1.1.0 以类详情承载属性定义，属性不是独立节点。

下一步选中员工查看属性定义；实例值到知识台账的属性视角核对。

脑图里没有工号

看到什么张三脑图只有实体和关系。

原因实体脑图当前排除属性分支。

下一步进入知识台账 → 属性，按张三筛选并查看工号、入职日期。

发布 v3 后张三没变

看到什么本体已有产品经理，张三仍是员工。

原因发布本体不修改实例；员工在 v3 仍有效。

下一步先确认业务事实，再在知识台账单独编辑张三类型。

受控重分类没有把员工变成产品经理

看到什么预演没有该转换。

原因重分类只处理有结构依据的归属迁移，不做岗位推断。

下一步若业务确认张三是产品经理，单独修订实体；不要强行扩大迁移范围。

抽取数量和截图不同

看到什么模型返回的实体或关系数量不同。

原因真实 LLM、模型参数和文本细节会影响结果。

下一步以固定材料和本体约束为准，逐条审核；截图只教入口和验收方式。

仅文档模式没有实体

看到什么任务完成，但结果工作区没有实体、关系或属性。

原因“仅文档检索”主动不执行图谱知识抽取。

下一步去原文数据源核对文档和切片；需要入图时重新选择项目本体或开放发现模式。

抽取结果为空

看到什么使用项目本体或开放发现模式，任务完成却没有识别出知识。

原因系统已执行抽取，但材料、切片、本体匹配或模型输出没有产生可用断言。

下一步先查切片预览和任务日志，再核对模式与项目本体；修正材料或配置后重试。

待确认去哪里处理

看到什么结果卡显示待审核或待建模，但不确定下一步。

原因待审核是已有结构下的知识确认；待建模是本体中还没有相应概念。

下一步待审核点“去知识审核”；待建模点“去本体画布处理候选”。

软删除后想找回

看到什么当前关系视角不再显示该关系。

原因软删除生成了删除修订，不是物理抹除。

下一步打开历史或可撤销操作，核对目标 ID 后恢复；恢复会生成新修订。
