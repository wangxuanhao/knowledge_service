# OAG 性能优化与验收

日期：2026-10-16。执行者：主 agent；没有委派。基于本地 `master` 的 `2a14f09`，本轮改动尚未提交。

## 改动

- E/R/F/U 一次批量读取冻结活动、边和不可变版本，避免每条证据重复加载整组边。按 citation 分组后投影，调用内缓存共享断言及精确事件；对外单条溯源接口保持相同契约。
- 冻结来源时，在事务内批量预取直接版本、共享文档来源，并复用本次读取。有效期核对批量读取来源原文与指定知识时点的文档治理版本，不再为每个文档加载完整修订历史。缓存不跨请求，当前规则修改不会命中旧答案缓存。
- 参考检索在 PostgreSQL 先匹配文本，再返回最多 501 条候选。新增 0019 迁移的字符对 GIN 表达式索引，覆盖中文两字词；完整子串检查排除字符对凑成的假命中，百分号等按字面量处理。它仍是有界关键词检索，不是全量历史或语义索引。
- JSON/SSE 提供 `timings_ms`，区分检索、资格核对、冻结、摘要、模型、保存和总计。SSE 额外记录模型首个正文片段等待；该时间包含在模型整体耗时中。日志只含数值，不含提示、密钥或供应商响应。
- 普通问题采用简洁回答，避免强制重复多个段落；比较保留平台、前提、例外、时间及引用。不截断证据，不自动更换模型。
- **修复关键词查询误做向量编码。** 原 `_search_via_milvus` 无论模式都先调用 `cached_query_vector`，导致纯 BM25 查询也加载本地 embedding。现在仅语义/混合模式计算向量。纯回归将编码器设为一调用就报错，先复现失败再修复通过；语义/混合共享编码的已有回归继续保留。

## 真实请求与统计口径

使用之前保留的合成验收项目 `434c84fc-49aa-4a63-97c6-0932b6f55e0f`；7/15/91/43 天仅为验收材料，非实际平台政策。正常 API 登录、真实 PostgreSQL/Milvus、真实配置的模型，未模拟供应商接口。

优化前关闭模型的三次 HTTP 总耗时：3.4531、1.5169、1.8573 秒。期间本地服务停止监听，后续重启。第一版计时抓到一次检索冷请求 74.07 秒，随后降到 2.26/6.26 秒；冻结为 2.76–3.71 秒。后续批量来源读取后的三次总耗时为 5.9883、4.1752、4.0025 秒。运行条件存在冷启动、测试及后台负载变化，**这些结果不能证明 HTTP 总耗时相对最初基线降低**，也不计算提速百分比。

中间一次真实模型 SSE：当前规则证据在约 3.04 秒出现，首正文在 9.77 秒出现，10.80 秒完成；模型首正文等待 6.73 秒。历史规则证据在约 2.70 秒出现，首正文在 17.49 秒出现，18.74 秒完成；模型首正文等待 14.79 秒。历史结果仍按 2025-06-01 引用当时的 91 天来源。该轮还保留三段格式，之后简化了默认格式。

在修复关键词误编码前，代码重启后首个证据模式请求耗时 48.26 秒（检索 46.09 秒），后两次为 2.407/2.396 秒。随后定位到 BM25 路径无条件计算向量，并以编码器不可用的回归锁定该调用。修复后再次重启，**相同请求首次 2.2733 秒，后两次 1.9162/1.6195 秒**，检索分别 743.001/710.814/755.783 ms。不把单组数字推广成普遍 20 倍提速；确定消除的是纯关键词路径的无用编码。语义/混合的首次模型加载仍需要预热。同期主机采样 CPU 约 79%，31.68 GB 内存中空闲约 3.89 GB；仅记录运行条件。

## 规模与回归

10/100 条证据的批量 trace 与逐条 trace 逐项比较，并检查共享读取预算：两次活动读取、两次边读取、一次不可变版本批量读取；不随 citation 数增加共享往返。记录内容仍随实际证据数量增长，不代表总 CPU/内存常数。

隔离 PostgreSQL 中构造 10,001 条记录，检索稀有退款词，只解码匹配的 1 条。最初的一万条测试因逐条写入准备耗时过长而中止，未计为通过；改用隔离测试库的批量 SQL 造数据，仅用于测试权威读路径，不代表摄取或 Milvus 投影性能。

## 限制及后续重点

- 没有进行百万条、并发或生产容量验收，不能据此给 SLA。完整权威回退仍可能读取较大范围，不能用一万条参考候选验证替代整条问答链路容量测试。
- 高频词/单字符查询、复杂 metadata 和本体范围仍可能缩小索引收益。最多 501 条关键词候选在复杂筛选与相关性排序前截断，页面继续说明覆盖限制。
- 溯源边仍逐条事务写入；本轮减少了读取及重复解码，后续若 `freeze` 仍高，应优化边的批量写入并保留原子性与幂等冲突检查。
- 生成模型首字等待仍有明显波动；连接池复用、模型路由和思考强度尚未调整。关键词路径已不调用 embedding，语义/混合仍需关注向量模型首次加载；应在同一材料、环境和输出要求下多轮比较，再决定模型配置。
- 0019 会为记录原文建立索引，增加索引空间与写入维护成本。已有大库升级应评估建索引窗口；批量写入后需保证 PostgreSQL 自动统计及时更新。
