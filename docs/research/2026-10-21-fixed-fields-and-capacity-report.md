# 固定 Milvus 字段与 15 万实体性能复测（2026-10-21）

本轮已移除 Milvus 的 16 个 `bf_` 自动扩展列，保留 21 个明确字段；修复普通实体文字修订的全项目快照开销，以及图谱重复查询后退化为扫描 30 万关系的问题。保留测试项目可以继续从项目管理进入。

**验收结论有范围：** 大库文字修订、台账分页、详情及局部图扩展已获得本轮实测；全图清单创建 P95 仍为 2.115 秒，未达到 2 秒目标。一次完整 HTTP 图谱枚举为 29.468 秒，不能代替浏览器绘制或完整加载 P95。容量项目本轮未向量化，普通项目的 Milvus 检索结果不构成 15 万实体向量容量认证。

## 现场与方法

- 唯一正常应用：`http://127.0.0.1:8100/`。最终读测服务 PID 44644；此前最终写测 PID 23776。二者依次运行，没有同时启动两套应用。
- PostgreSQL 为权威存储；Milvus 3.0.2 的 `knowledge_vectors` 为当前检索后端，1024 维、关闭动态字段。当前关键词、语义、混合检索均未降级；历史关键词查询仍由 PostgreSQL 承担。
- 保留项目：`46249548-2189-4ad7-8f23-70ee2bcc7f6f`，名称“容量验收 · 15万实体 / 30万关系（保留测试）”，150001 实体、300000 关系。语料为合成夹具，不评价业务语义质量。
- 正常账号认证，真实产品 HTTP 接口，`trust_env=False`；容量读测与编码、pytest 分阶段执行。资源观测使用单独只读连接。
- 每项暖态查询先保留一次 warmup，再连续测 20 次；P95 使用 nearest-rank，不将预热时间混入暖态。写测包括首次 PUT，20 次全部纳入。失败与预期拒绝单独记录。
- 局部图使用同一个有连接的代表性种子，双向扩展，最多 500 实体、1000 关系。该结果不覆盖任意高连接度节点与所有筛选组合。

## 字段与投影结果

迁移没有 drop collection，没有删除 PostgreSQL 业务数据。删除前保存 schema、索引、业务列值和权威计数检查点；显式重建仅覆盖两个已选普通项目，容量项目排除。最终只读复核确认 `bf_` 列为 0。

| 字段用途 | 当前物理列 |
| --- | --- |
| 身份与隔离 | vector_id、index_version、version_id、project_id、record_id |
| 检索内容 | kind、type、ontology_id、text、embedding、sparse |
| 适用范围 | platform_mode / platform_values、business_mode / business_values、audience_mode / audience_values |
| 时态、片段所属与条件状态 | valid_from_us、valid_until_us、chunk_owner_id、filter_present |

`mode` 表示 all / specific / unknown；`values` 保存 specific 的具体取值。空数组不能同时表达“全部适用”和“尚不清楚”，因此保留两列。不再遍历任意 metadata 生成物理列；将来新增明确需求时，再声明可读业务列及回填、校验方法。

当前检索/问答普通条件支持 id、kind、type、source_id、valid_from、valid_until，本体与适用范围沿用专用范围。source_id 在此只表示片段所属文档，不能代替实体多来源断言。任意 metadata 或其他不支持的条件整棵拒绝，前端保留条件并提示；不静默丢弃某个 AND/OR 分支。图谱、资料库、台账的 PostgreSQL 条件能力保留。

| 普通项目 | 当前代际 | Strong 查询有效记录数 | 索引状态 |
| --- | --- | --- | --- |
| 10.14真实模型批次验收 | 2 | 37 | ready，applied_seq = watermark = 0 |
| 统一知识写入验收 · 2026-10-20（合成示例） | 2 | 5 | ready，applied_seq = watermark = 32 |

有效记录合计 42。Milvus 统计接口曾返回 rowCount 88；该统计不代替 Strong `count(*)` 的有效行核对，不据此推断当前业务记录翻倍。两项目 Strong 分范围计数与全集合有效计数一致。

普通增量不再逐条强制 flush，使用写确认与 Strong 读取验证可见性。构建仍须显式触发，租约丢失、旧目录或 schema 不匹配不会自动重建或切换就绪状态。

## 卡点与修复

| 路径 | 查到的原因 | 本轮处理及边界 |
| --- | --- | --- |
| 单实体文字修订 | 原路径为单条修改构造两次全项目 Python 快照，历史时间预留读取大量行 | 纯 text 修改且依赖可证明闭合时，读取精确权威依赖；时间预留改 SQL 聚合。保留事务、锁、CAS、来源、断言、事件、版本映射及回滚 |
| 文字修订安全门禁 | 最初 SQL 门禁仍重复解析、扫描大量关系与端点 | 用精确时态存在性、窄实体标志和集合差判断。SQL 对照原查询 6.453 秒，新查询三次 1.312 / 1.328 / 1.703 秒；仍有随项目规模增长的数据库集合运算，不能称为 O(1) |
| 多次调用后的局部扩展 | 自动 prepared statement 使用 generic plan，ORDER BY/LIMIT 促使扫描 300000 关系再过滤，实际只需 4 条边 | 将邻接选择留在带 OFFSET 0 的派生查询内，外层排序限量，并保留端点资格。未改全局 prepare 或计划缓存策略 |
| 健康状态 | 编码器尚未真正编码也可能被报告 ready | 非空编码且维度校验成功才 ready，异常清除；健康探测本身不加载模型 |

图谱计划对照中，同一 frontier 的原 generic plan 约 1.074 秒，新形状约 12–16 毫秒，记录顺序、version_id 与 payload digest 一致。该微基准只解释执行计划；下面真实接口连续 20 次的结果用于确认端到端效果。

复杂 SHACL、修改类型/来源/本体/属性/时态、批量或无法证明闭合的治理操作仍使用完整校验。没有通过跳过治理换取速度，**也没有把本轮文字修订结果推广为所有写入都同样快**。

证据：[门禁 SQL 对照](../../.benchmarks/2026-10-21-text-gate-sql-comparison.json)、[custom/generic 执行计划对照](../../.benchmarks/2026-10-21-neighborhood-plan-comparison.json)。

## 内存、锁与剩余限制

按每轮 started_at / finished_at 裁剪独立观测：写测 34 个资源样本、28 个 PostgreSQL 样本；读测 102 / 102 个。主机可用内存最低分别约 10.08 / 10.04 GiB；服务 RSS 峰值约 168.6 / 279.7 MiB。此时没有加载 embedding 模型。普通项目真实语义查询后服务 RSS 约 3.0 GiB，可用内存约 7.42 GiB。

两轮采样 `blocked_backends` 与未获准锁的最大值均为 0，没有观测错误。它支持本轮未捕获到数据库锁阻塞，不能排除采样间隔中的短等待。Windows pagefile 已用字节不等于实际换页速率，不能凭该值归因内存抖动。读测主机仍有其他 CPU 活动，未将整机视为空闲专用服务器。

仍需明确保留：全图清单 2 秒 P95 未通过；完整浏览器加载与绘图需要单独认证；容量项目未向量化；复杂治理写入仍可能受全项目验证开销影响。当前回归还保留一个既有 xfail：READ COMMITTED 下，同一答案两次摄取状态读取可能混合，尚需共享快照或重复读隔离修复。

证据：[裁剪后的资源统计](../../.benchmarks/2026-10-21-fixed-fields-capacity-resource-summary.json)、[写测观测](../../.benchmarks/2026-10-21-fixed-fields-final-resources.jsonl)、[读测及最终语义阶段观测](../../.benchmarks/2026-10-21-fixed-fields-final-resources4.jsonl)。
