# 现有渐进图谱展示优化与纯 CPU 验证

日期：2026-10-27。用户批准的范围是改善现有展示，不重建已经具备的“首批 → 下一批 / 自动继续 / 暂停”机制。保留局部 ECharts、全量 WebGL、原会话与真实数据；本轮未新增后端图块、全库索引服务或持久图快照系统。

## 实际改动

- 新增共享 `GraphAppearance`：按真实类型 ID 取色；中文名称只影响文字。局部节点、类型按钮、图例与全量节点同色。图例用独立分类键，避免不同类型恰好同名时互相覆盖；真实实体类型与虚拟属性值分别处理。
- 近白画布、低对比关系线、密度自适应节点大小、清楚的选择轮廓与路径。局部普通名称候选最多 50 个并分布到整个图面，根实体、检索命中与路径优先，名称避让并带轻量底色；开关同时控制普通、选中和路径名称。未减少实体或关系记录来提速。
- 全量节点按有限颜色组准备坐标缓冲，颜色处理发生在数据同步时，保持原始坐标、ID、顺序与真实选择结果。单条关系选中时只叠加对应两个顶点，不额外扫描全图。
- 全量视图增加左侧 `− / ＋ / 适应画布`；逐批加载按钮独立放到画布下方并保留齐全。循迹 / 图谱设置保留各自有效范围、统一控件样式，详情头部和关闭按钮固定。本体扩展用独立状态按钮，仍以原 checkbox 与 change 事件作为检索参数来源。
- `SessionLoader`、请求函数和导出尾部与本轮冻结基线逐字节相同。PostgreSQL、权限、数据水位、资格、游标、取消、端点校验和完整数量核对未改。

本机 8100 静态页面及新增脚本已返回当前资源；前端版本号已更新。没有改业务数据，也没有通过登录态或业务接口做生产容量验收。

## 为什么额外做了当前画面复用

第一版逐顶点颜色与较复杂片元程序，在纯 CPU 大图对照中慢了约 23–28%，未采用。改成有限颜色组和原有简单关系程序后，仍观察到约 10% 的大图帧间隔开销，因此增加了现有 WebGL 内部的**完整概览画面复用**。

它只在当前已加载的全部几何都在画面内、实体不少于 5,000、纹理大小受限时，保存已经画好的不透明画面；附近平移和相对约 2/3–1.5 倍缩放复用该画面，名称仍实时绘制。深度缩放、裁切画面、设备不支持或资源不足时回到精确颜色组绘制。数据、选择、关系显示、画布大小或 DPR 改变时失效。纹理每边不超过 2,048 像素，保守内存预算不超过 16 MiB。

这不是跨浏览器重启的持久缓存，也不是把尚未加载的数据标成完整。诊断分别报告 `node_layer`、`cached_entities`、加载量和关系缓存量。原会话仍负责全库完整性；位图只复用当前合法数据的画面。

真实软件 WebGL 检测还发现：`alpha:false` 的默认帧缓冲没有 alpha 位，直接复制为 RGBA 会返回 `INVALID_OPERATION 1282`。独立操作探针确认绘图及纹理准备无错误，RGBA 复制失败而 RGB 成功；已改为 RGB 并加入回归。旧失败试验的退出码虽然为 0，但缓存实际未启用，明确作废，不用于提速结论。

## 测量条件

- 本机 Intel i5-1340P，独立 Edge，禁用 GPU / 硬件 Canvas，使用 SwiftShader CPU 软件 WebGL。CDP 核验 Canvas、合成器为 `disabled_software`，实际 GL renderer 为 SwiftShader Device。
- 全量绘图夹具固定 viewport 1280×1000、同一 `1240×760; max-width:96vw` 图容器、同一 DPR、确定性实体与关系。两档 30 万实体都保留全部 60 万 / 150 万关系，没有抽掉关系或缩小测试画布。
- 每档连续相机变化 3 次，每次至少 3 秒，记录每帧间隔；表内给出三次各自 P95 及其中位数，不把三次中位数叫作跨机器容量承诺。首批、追加、点击样本另行记录。
- 局部图走真实工作台 `drawGraph`，隔离 API 夹具，固定 900×620 实际画布，从 400 实体 / 800 关系追加到 500 / 1,000；通过真实图形变换确认屏幕上的节点移动，非只检查数据坐标。相机交互期间 `setOption` 次数为 0。
- 本机其他任务使 CPU 多次处于 90–100% 忙碌，内存压力也不同。保留原始样本与主机负载，不将前后差值全部归因于代码。局部图另做紧邻的基线 / 新版配对复测。
- 不含生产 PostgreSQL、Milvus、鉴权或部署网络延迟。现有业务 API 需要认证，未绕过认证。追加绘图是单样本，不能据此给出稳定加载 P95。

测试浏览器参数：

```text
--disable-gpu --disable-accelerated-2d-canvas --use-gl=angle
--use-angle=swiftshader --enable-unsafe-swiftshader --enable-precise-memory-info
```

**以上改善限定在缓存完整概览附近的平移 / 小幅缩放分布。** 初次切入、重建或回退仍观察到约 126–164 ms 的尖峰，不能解释为每帧都在 33 ms 内。深度放大使用真实颜色组绘制，不能套用这张表的缓存帧结果。

| 追加到目标规模：同步缓冲至完成绘图，单次 | 基线 | 新版 |
|---|---:|---:|
| 400 / 800 | 90.6 ms | 70.2 ms |

真实边命中仍沿用线性检查：新版 30 万 / 150 万关系的 12 个样本中，关系拾取 P95 约 **609 ms**、空白拾取约 **356 ms**。这些不满足此前提出的 200 ms 对照目标；节点直接命中不能代替关系和空白测试。本轮没有用图像缓存伪装拾取已经加速。

| 实体 / 关系 | 基线帧间隔 P95，3 次 | 新版帧间隔 P95，3 次 | P95 的中位数：前 → 后 |

紧邻基线 CPU 忙碌约 96.63%，新版约 89.89%，因此不能把全部差值归因于样式。早期不同轮次曾出现更慢样本；完整原始记录均保留。配对结果没有重现相机交互退步，但**密集局部图仍没有达到 33 ms，不能称作已流畅验收**。

单次首轮绘图约 1.479 → 1.435 s；追加重绘约 1.052 → 1.198 s，追加样本仍较慢。实体 / 关系数量不变，原先 400 / 500 个常驻名称改为最多 50 个候选，经避让实际显示 28 / 32 个，根、命中、路径与悬停提供优先名称；这项显示变化明确披露，不是数据删减。
