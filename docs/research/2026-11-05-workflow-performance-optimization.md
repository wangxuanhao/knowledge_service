## 实现及集成修复

1. 冻结溯源集合先完整校验，再以每批最多1000条写入。终态不可变、严格载荷比较、逻辑身份、外键隔离和原子性保持；只有精确主键冲突转换为原有 ID 冲突异常。
2. 一批已确认建议复用本次请求拥有的图和正式记录快照，沿用相同 RDF 修改及逐前缀校验。保留原操作、风险、证据、影响顺序和指纹；有匿名节点入向引用时保留兼容复制路径，不承诺该特殊路径解析次数恒定。
3. 来源断言按项目和唯一 ID 分批读取，但每个冻结快照仍按原顺序比较。仓储最终发布守卫在原事务内重新读取，独立于服务预检查。异常历史快照保留逐条检查路径和原错误优先级。
4. API 数据读取通过现有 ApplicationData 门面转发，保留异常身份、读取顺序、响应、入队及元数据生成器的事务范围。
5. 修复关联探索调用已删除参数导致的实际 TypeError，以及实体匹配中私有候选参数被忽略、无资格高排名候选挤占名额的问题。使用公共 ID 过滤前先完整校验和计算调用方条件，保留原范围及最终版本检查；深度16仍有效、17仍拒绝。当前非空探索增加覆盖预加载至最终结果的项目水位检查；空查询和显式历史查询保留既有规则。真实修改并激活新索引的竞争、非命中邻接变化、类型通道及重试均有回归。
6. 新增追加式迁移0031，修复旧统计覆盖索引将两个合法长端点一起放入 B-tree 后超过索引行上限、错误阻止写入的问题。先并发建立紧凑替代索引再并发移除旧索引，保持分组键、可见性条件和有效期标志，不改记录或标识。真实旧索引失败、升级、原行保留、有效索引和重复迁移已验收；部分资格判断可能增加堆读取，本轮已按新 schema 重测。

这些生产改动及相关夹具修复均经过独立规则/意图和质量审查。早期专项数量存在重叠，不与最终全量结果相加。旧夹具按现行公开接口、真实索引状态、可见页面入口及服务端会话规则更新，没有恢复过时检索回退或放宽业务守卫。
