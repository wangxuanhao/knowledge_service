## 核对出的操作边界

- TTL 接入入口实际为「本体目录 → 高级 → RDF 源码 / 导出 → 编辑 Turtle → 把源码差异加入草案」。没有独立的 TTL 文件上传按钮。
- 当前四步为「上传核对 → 配置资料 → 解析与检查 → 确认处理」；属性开关位于第 2 步的「高级解析设置」，默认关闭。上传只暂存，明确开始解析后才识别和预计算切片向量；原件预览与解析后的正文切片分开。
- 未提交准备会话自创建起保留 7 天，访问不会续期；过期需重传，已提交资料和批次仍保留。此期限与切片向量缓存有效期分别说明。
- 资料详情重新处理请求只包含处理模式和请求编号。`DocumentReprocessing.create` 复用原资料最近的处理设置，UI 和请求模型没有属性开关覆盖。因此原先关闭的资料不能通过再次点击重处理就开启属性提取。手册第 8、10、26 章明确说明此限制，没有修改业务实现。
- 图谱和脑图不将数据属性画为节点/连线，属性详情按值、来源、期间阅读。
- 主检索关键词、语义、混合由 Milvus 执行；PG 是业务权威。资料库关键词检索与主检索分开说明。
- 首次项目索引、旧版本升级、同维度模型变化及普通故障恢复自动处理；统一「检索索引」提供覆盖数量、进度、错误和手动重建。草稿向量准备完成不能视为正式可检索。
- 页面混合默认关键词候选语义排序，另可选双路召回融合。正文同时注明「限定关键词范围」「扩展相近含义」与截图中原标签的对应关系。语义阈值默认 0.35，在融合前作用于向量一路；BM25、余弦和 RRF 分数不能当作同一概率比较。问答直接应用本页筛选，移除旧范围提问入口说明。
- ZIP 推荐唯一根 MD / HTML 与 assets，无需 manifest；旧清单也须满足根主文档校验，document.pages 仅供已入库历史来源读取。脚本保留相对 root 的路径，新上传示例改为 MD 直接父目录 root 与不带子目录的文件名；旧包拆分后若仍嵌套，须重新整理到各包根。PDF、Word、独立图片、视频直接上传，数字和混合扫描 PDF 分别核对正文覆盖。
