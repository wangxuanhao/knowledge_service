# 检索索引的自动处理

1. 上传只验证并保存文件。用户确认开始解析后，后台执行解析、OCR/ASR、分块，再计算切片向量。卡片展示“计算切片向量”“切片向量已准备”，向量失败与解析失败分别呈现。
2. 预计算只写可丢弃的内容缓存。草稿未提交时不创建正式知识记录、不写正式 Milvus 索引，不能被搜索或问答引用。缓存按编码模型、维度及完整索引文本寻址，包含文档标题与上传文件名（ZIP 使用上传包名，与正式来源一致）；相同内容提交后复用，文本、标题、文件名或模型标识改变时重算。解析完成后调整标题或分块配置，页面标记“向量待更新”，提交时自动补算。默认缓存上限 512 MiB、有效期 7 天，不在 PostgreSQL 存向量。
3. 确认提交后，正式文档与切片的变更进入现有持久投影队列；首次检索索引、旧版本索引及故障恢复通过持久后台重建任务处理。多次自动或手动请求复用同一活跃任务，失败从 5 秒逐步退避至 5 分钟。纯空白新项目不会启动模型。写入请求只唤醒后台，不在请求线程执行向量编码。
4. 本体发布仍按治理规则发布不可变的类型定义，不能凭空产生实体实例。已接纳实体、关系、属性及其支撑上下文的实际变化自动投影。发布同步检查跟随当前索引版本；等待长时间构建不消耗错误重试次数。
5. 资料库、知识图谱、知识问答及知识台账的“检索索引”入口可查看切片、实体、关系、属性的当前数量与已确认索引数量、阶段进度和错误。管理员可手动重建全部关键词与语义索引；二者使用同一份索引文本，不要求分别操作。

向量预计算失败不损坏解析正文。提交后会在正式索引流程重新计算，索引未就绪时搜索明确返回未就绪，不假装可用。缓存不可写或损坏也不能阻断正式索引：编码成功后直接写 Milvus。

同维度模型更换或可升级的索引字段变化，沿用隔离的新代际构建、校验和原子激活，不直接删共享集合。向量维度等共享集合结构不兼容时明确失败，需要维护集合后重试。关键词、语义与混合检索都使用已确认的索引代际，不静默回退另一种检索。
