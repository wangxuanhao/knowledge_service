# 提取本体版本可见性

用户已批准，主 agent 在当前工作区执行，不派发子 agent。

**目标**：上传前展示项目最新已发布本体的版本和发布时间，提交绑定展示的 ID；完成结果展示实际版本。有未发布草案、无已发布本体、读取失败时明确提示。

**方案**：新增独立前端模块读取 `/ontologies` 与服务端的 `/ontology-drafts/stage-availability`。复用后端权威版本号，不按数组下标生成版本。将 `ontology_id` 加入所有受控上传路径；保留后台批次的固定设置，禁止重用版本不同的半上传批次。结果按断言/记录中的本体 ID 解析，不用当前最新版本代替历史版本。

- [x] 先验证版本选择、切换项目竞态、无本体/错误、草案提示的失败测试。
- [x] 实现版本信息卡、查看详情、刷新与发布事件更新。
- [x] 接入上传版本绑定及任务/批次结果展示。
- [x] 更新静态资源缓存版本，运行相关前端契约与语法检查。

沿用现有上传页样式，仅增加版本信息卡；不改变本体发布或抽取规则。

验证：124 项 Node 前端测试、58 项 Python 静态契约测试通过。独立浏览器样例验证了详情展开、版本 ID 绑定、无本体及网络错误提示；本地实际服务需要登录，未操作真实项目数据。旧记录无版本依据时明确显示未知；多个归属版本时明确显示多个版本，不猜最新版本。
