# OAG 请求性能优化实施计划

执行：主 agent。用户已确认上一轮提出的优化方向，本轮在当前 checkout 实施，不委派、不自动提交。

**目标：** 减少随证据条数增长的重复数据库读取，提供 JSON/SSE 一致的阶段计时；保持平台、业务/知识时点、引用与冻结原文语义。

**设计：** 每次回答批量读取冻结活动与边，按 citation 分组，并批量载入不可变记录版本；缓存只限本次调用。先消除证据摘要 N+1，再测有效性核对和参考候选读取。参考检索在有界返回前先匹配关键词，避免无关 ID 占满预算；候选内相关性排序仍在 Python，不把预算称为全库穷尽。模型保持现有配置，默认提示改为简洁、不重复原文，不硬截断证据。计时仅记录数值，不记录密钥或提示内容。

**技术栈：** Python/FastAPI/PostgreSQL/Milvus，原生 JS 页面。

- [x] 编写失败回归：批量 trace 与逐条 trace 内容相同；活动/边读取次数不随 citation 线性增长；记录版本项目隔离；JSON/SSE 阶段计时一致。
- [x] 实现批量冻结 trace 与证据摘要，所有 E/R/F/U 共用一次批量读取。
