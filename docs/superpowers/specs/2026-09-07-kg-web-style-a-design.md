# 16 Web「科研工作台」前端升级设计

日期：2026-09-07

## 目标

把 `apps/16_kg_web_server.py` 提供的现有知识图谱 Web 界面升级为适合长期使用的专业系统界面。采用已确认的 A「科研工作台」视觉方向：深蓝导航骨架、明亮内容区、青绿色主强调色、克制的数据密度。升级不得破坏现有 API、项目数据、图谱渲染、问答、增量、评测等能力。

## 范围

正式修改仅涉及：

- `data/kg_web/static/index.html`
- `data/kg_web/static/style.css`
- `data/kg_web/static/app.js`

`apps/16_kg_web_server.py` 只做兼容性检查，不计划修改。所有现有 `/api/*` 请求路径、请求参数与响应结构保持不变。

实施前快照位于 `backups/16_web_before_style_a_20260907_1135/`，包含 16 脚本和三个静态文件。

## 信息架构

保留九个现有一级页面，不删减功能：看板、图谱、实体、本体、数据源、脑图、问答、增量、测评。

导航在视觉上分为两组：

- 工作区：看板、图谱、实体、本体、数据源
- 智能与治理：脑图、问答、增量、测评

侧栏支持展开与收折。收折后保留图标、选中态和悬浮提示；刷新页面后使用 `localStorage` 记住状态。窄屏下侧栏默认收折，不实现移动端抽屉。视口低于 1180px 时响应式规则优先于已保存的展开状态；回到较宽视口后再恢复用户保存的状态。

## 视觉系统

- 主背景：冷灰白；内容面板：纯白；导航：深蓝黑。
- 主强调色：青绿色，用于选中态、关键数据和图谱焦点；蓝色保留为信息色。
- 使用 CSS 变量统一颜色、圆角、阴影、间距、字号和动效时长。
- 去掉 Emoji 作为主要图标的依赖，改为内联 SVG/字符图标；在无图标资源时仍可正确显示。
- 页面层级依靠留白、细边框和局部色块建立，不使用大面积渐变、玻璃拟态或强阴影。
- 动效只用于导航收折、面板显隐、按钮反馈和页面进入，时长 120–220ms；尊重 `prefers-reduced-motion`。

## 页面骨架

### 全局导航与顶栏

顶栏显示当前页面、当前项目、全局搜索、服务状态和界面控制。当前项目仍由现有 `state.current` 驱动，不新建后端状态。项目选择器只复用已有项目列表及 `loadProject()`。

### 看板

保留六张统计卡、两张分布图和两个排行面板。统计卡缩小纵向占用；图表使用新的主题色、轴线和 tooltip。项目未加载时提供清晰的下一步入口。

### 图谱

保留左侧项目与检索区、中间 ECharts 图画布、右侧节点/边检视区和底部三类检索结果。

新增两项纯前端能力：

1. 图谱专注模式：仅图谱工作区切为深色画布，并弱化左右面板；不改变图数据与 ECharts 交互。状态保存在 `localStorage`。
2. 检索结果收折：底部结果区可收起或展开，默认展开；状态保存在 `localStorage`，收折后调用图表 `resize()`。

### 其他页面

实体、本体、数据源、脑图、问答、增量、测评统一使用同一工具栏、面板、表单、标签、空状态和状态提示样式。业务字段、按钮行为、表单提交和危险操作确认逻辑不变。

## 前端组件边界

项目保持原生 HTML/CSS/JavaScript，不引入构建工具或新依赖。

- `index.html`：补充语义结构、导航分组、全局控制按钮和图谱结果区收折按钮。
- `style.css`：建立设计令牌，覆盖全部现有视图与响应式状态。
- `app.js`：增加导航收折、图谱专注模式、结果区收折和本地状态恢复；现有数据请求及业务渲染函数尽量不改。

新交互以独立的小函数实现，不混入 `api()`、`loadProject()`、`fetchGraph()`、`askQA()` 等业务函数。视图尺寸发生变化后统一调用现有 ECharts 实例的 `resize()`。

## 数据流与兼容性

页面初始化时：

1. 从 `localStorage` 读取三个界面状态：导航是否收折、图谱是否专注、结果区是否收折。
2. 应用对应 CSS class。
3. 继续执行现有的项目列表加载和页面初始化逻辑。

用户切换项目、检索、问答或增量写入时，沿用当前 API 数据流。新界面状态不发送到服务器，也不进入项目数据文件。

旧浏览器或禁用 `localStorage` 时，状态读写通过 `try/catch` 降级为当前会话默认值，不阻塞页面功能。

## 错误与空状态

- 网络/API 错误仍使用现有错误信息，但统一为可见的状态块或消息提示样式。
- 没有项目、没有检索结果、没有节点详情、问答为空时保留明确说明和下一步操作。
- 超长项目名、实体名、来源文件名必须截断显示并保留 `title`，详情正文允许换行。
- 窄屏低于 1180px 时自动收折导航并缩小左右面板；低于 900px 时图谱页允许横向滚动，避免强行堆叠导致 ECharts 尺寸失效。

## 可访问性

- 所有新增图标按钮都有 `aria-label` 和 `title`。
- 键盘可聚焦元素提供清晰的 `:focus-visible` 样式。
- 文本与背景对比满足常规系统界面的可读性要求。
- 不以颜色作为唯一状态信号；服务状态同时提供文字。

## 验收与测试

### 静态检查

- HTML 中所有 `app.js` 使用的 ID 仍存在且唯一。
- JavaScript 通过语法检查，浏览器控制台无初始化错误。
- CSS 在 1440×900、1280×800、1024×768 三种视口不出现主要区域覆盖。

### 功能回归

- 项目列表刷新、项目加载、删除确认正常。
- 看板统计与图表正常。
- 图谱节点/边点击、范围切换、复位、检索和定位正常。
- 实体增删、关系新增、别名与合并入口正常。
- 本体浏览、SPARQL、约束检查正常。
- 数据源、脑图、问答、增量、历史回滚和评测页面能正常加载。
- 三项本地界面状态刷新后能够恢复，`localStorage` 不可用时不报错。

### 视觉验收

- 主界面与已确认的 A 蓝图一致：深色分组导航、明亮工作台、青绿色强调、克制阴影。
- 图谱是视觉主角，左右面板和底部结果不会抢夺注意力。
- 常用按钮与危险按钮层级明确，文本密度高但不拥挤。

## 非目标

- 不重写后端或拆分 `16_kg_web_server.py`。
- 不迁移 React/Vue，不引入前端构建链。
- 不新增权限、账号、多租户或云端同步。
- 不改变图谱算法、节点颜色业务映射或问答逻辑。
- 不制作纯展示性质的首页、营销页或大幅动画。
