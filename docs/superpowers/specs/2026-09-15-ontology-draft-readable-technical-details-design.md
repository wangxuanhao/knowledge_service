# 本体草案技术详情中文化设计

## 背景

“本体草案与发布记录”当前直接展示版本差异 JSON、Turtle 源码和 IRI 映射。中文术语在 IRI 中按 URI 规则编码为 `%E4%...`，底层数据有效，但普通用户容易将其理解为乱码。重新创建项目不会改变这一生成规则。

## 目标

- 默认界面以中文业务术语和通俗说明为主。
- 保留完整、可复制的原始 Turtle、JSON 和 IRI，满足技术排查与交换需求。
- 不修改数据库结构，不迁移既有本体，不要求重新创建项目或重新上传文档。

## 页面结构

原折叠标题“版本差异 · Turtle 与 IRI 映射”改为“查看版本变化与技术详情”。展开后依次显示三个有标题和说明的区域。

### 1. 版本差异

说明：“展示本草案相对上一版新增、保留或删除的实体类、关系和属性。第一版草案会把全部术语显示为新增。”当前后端按 IRI 成员关系计算差异，不宣称识别标签、说明、适用范围等内容修改。

默认提供中文摘要，按实体类、关系、属性分组。原始差异 JSON 放在该区域的“查看原始数据”二级折叠中，并提供复制按钮。

### 2. 本体定义

说明：“本体定义规定系统认识哪些事物、它们可以建立什么关系，以及可使用哪些属性。系统以 Turtle 标准格式保存。”

默认显示中文易读视图。实体类展示中文名称、说明和父类；关系展示中文名称、说明、起点类型和终点类型；属性展示中文名称、说明、适用实体类型和数据类型。字段分别来自 `schema_summary` 中类的 `parents`、关系/属性的 `domain` 与 `range`。页面先用 `summary.classes`、`summary.relations`、`summary.attributes` 建立 `id` 和 `name` 到中文标签的索引；无法解析的值显示解码后的短标识，缺失值显示“未指定”，多个值使用顿号连接。原始 Turtle 放在“查看 Turtle 原始源码”二级折叠中，并提供复制按钮。

### 3. 名称与技术标识

说明：“每个中文名称都对应一个唯一 IRI，供系统稳定引用。`%E4%...` 是中文经过 URI 编码后的技术表示，不是乱码，日常使用无需处理。”

默认以“中文名称 → 简短技术标识”列表展示，并按实体类、关系和属性分组。短标识按以下固定规则生成：先取 IRI 最后一个 `#`、`/` 或 `:` 之后的非空片段，再仅对该片段执行一次 `decodeURIComponent`；没有非空末段时显示完整 IRI；解码失败时显示原片段并标记“编码格式不完整”。`%2F`、`%23` 等保留字符只在截取末段后解码，避免改变 IRI 分段。名称重复时仍逐项展示，并以完整 IRI 区分。完整原始 IRI 放在每项技术详情中，支持单项复制；原始映射 JSON 放在二级折叠中并支持整体复制。

## 解码与容错

前端新增安全的 IRI 显示转换：仅对截取出的末段展示文本调用 `decodeURIComponent`，不改变接口返回值和保存值。解码失败时，简短标识位置显示未解码的原始末段并标记“编码格式不完整”；完整原始 IRI 始终保留在技术详情中，防止信息丢失或页面渲染中断。HTML 输出继续经过现有转义函数处理。

## 交互与可访问性

- 三个区域都具有可见标题和简短说明，并以 `aria-describedby` 将区域与说明关联。
- 原始技术内容默认折叠，用户主动展开后才展示。
- 所有复制控件使用原生 `button`，具有唯一可访问名称和清晰的键盘焦点样式。
- 复制内容严格使用未改写的源数据：Turtle 复制 `d.turtle`；差异与映射分别复制 `JSON.stringify(d.diff || {}, null, 2)` 和 `JSON.stringify(d.mappings || {}, null, 2)`；单项 IRI 复制原始映射值。
- 复制成功后按钮文字显示“已复制”两秒，并通过 `aria-live="polite"` 状态区播报；Clipboard API 不可用或拒绝时显示并播报“复制失败，请手动选择内容”，不改变原始内容。

## 测试

- Web UI 合约测试确认三个中文标题、说明和无障碍属性存在。
- 将 IRI 显示转换与草案技术详情渲染拆成可独立执行的前端函数；使用代表性草案 fixture 做 DOM/helper 测试，而不只检查源码字符串。
- 测试 URN、HTTP IRI、`#`/`/`/`:` 分隔、编码保留字符、空末段、重复短名称、完整中文编码和不完整编码；不完整编码不得抛错，并显示格式提示。
- 测试缺失/null 字段、多父类、多 domain/range，以及无法从摘要索引解析的 IRI。
- 测试三个原始技术区域默认折叠但仍可访问，复制值与源 payload 完全一致，并覆盖复制成功、Clipboard API 缺失和拒绝三种路径。
- 测试原生按钮可经键盘聚焦，区域说明有关联，复制结果通过 live region 宣告。
- 运行现有 Web UI 与本体发现测试，确保发布流程和底层数据未改变。

## 非目标

- 不把现有 IRI 批量替换成英文或未编码中文。
- 不修改本体发布、候选归纳或数据库格式。
- 不重新生成 `test_0915_开放` 项目的草案。
