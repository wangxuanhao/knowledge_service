# 检索图谱同屏与知识问答界面设计

## 目标

保留“检索与交互图谱”同屏工作流，同时维持后端已经完成的检索与图谱加载解耦；将“证据问答”更名并重做为独立的“知识问答”菜单，采用接近 DeepSeek 的专注式聊天交互，而不是表单和卡片堆叠。

## 信息架构

侧栏中保留两个独立入口：

1. **检索与交互图谱**：检索、三通道结果、局部图和证据详情在同一页面。
2. **知识问答**：独立聊天页面，不复用检索页 DOM，也不前置调用检索或图谱接口。

不再出现单独的“知识检索”菜单。旧 DOM 控件 `retrieval-mode` 保持删除；后端请求字段 `retrieval_mode` 继续保留。

## 检索与交互图谱

页面采用三栏工作台：

- 左栏宽约 300px：查询输入、唯一检索模式、实体／原文／关系三通道结果。每个通道独立显示命中数量和空状态。
- 中栏自适应：局部交互图谱，是页面视觉主体。顶部只保留唯一的扩展跳数、实体定位和复位视图操作。
- 右栏宽约 280px：当前节点、关系或来源的详情、版本和证据操作。

数据流必须保持解耦：点击“检索”只请求 `/search`，快速渲染左栏，不清空或重载当前图谱；只有点击实体或关系命中的“在图谱中查看”时才请求 `/subgraph`。关系以 `subject_id` 为默认种子。原文命中进入来源或版本详情，不触发图谱请求。项目切换、范围筛选、时间点切换和输入联想都不得隐式调用 `/explore`。

初始图谱显示“从左侧检索结果选择实体或关系”的空状态。执行新检索时，已经显示的图谱、选中节点和详情保持不变；用户明确点击另一命中后，以一次局部图请求替换。项目切换必须立即清空检索结果、图谱和详情且不自动加载；范围或时间点变化也清空图谱和详情，避免显示已不在当前范围内的数据。输入过程不自动搜索，只有按钮点击或键盘提交才请求一次检索。

## 知识问答

页面采用专注、克制的聊天布局：

- 页面主体居中，最大宽度约 900px，大面积留白，不显示传统后台系统的 panel 边框。
- 空状态显示产品标题“知识问答”、一句能力说明和 3 个可点击示例问题。
- 发问后以连续对话流展示用户问题与助手答案；用户消息简洁靠右，助手回答占据主阅读列。
- 输入区固定在内容区底部，使用大圆角组合输入框；发送按钮位于右下角；生成开关收进输入框工具栏。
- 回答通过 `/qa/stream` 流式追加。一次请求内先接收 evidence，再接收 delta 和 done，严禁调用 `/explore` 或 `/search` 作为前置步骤。
- 证据不与正文争夺空间。助手回答下方显示“查看 N 条依据”的折叠入口；展开后按引用编号显示实体、原文和关系，可进一步定位图谱或查看来源。
- 流式期间显示轻量加载状态并禁用重复发送；错误在当前助手消息位置展示，用户问题保留，可直接重试。

页面可在当前会话中视觉保留多轮问题和回答，但每次发送都是独立的一次性请求，不把之前的消息作为模型上下文。重试必须原样重放失败轮次的请求。项目、范围或时间点变化时清空当前会话，并显示范围已变化的轻量提示，防止旧证据与新范围混用。

知识问答证据中的“在图谱中查看”是明确的跨菜单操作：实体用自身 ID，关系用 `subject_id`，切换到“检索与交互图谱”并只发出一次局部图请求，不触发检索或 `/explore`。原文证据的“查看来源”打开现有“原文数据源”页面并定位对应 `source_id`；没有 `source_id` 时只展示引用内容，不显示不可用操作。

视觉风格延续项目现有墨绿和纸张色体系，但去掉密集边框、嵌套卡片和大块说明文字。重点是清晰的阅读层级、底部输入焦点和流式回答节奏，不复制 DeepSeek 品牌元素。

## 接口契约

- `POST /api/projects/{p}/search`：请求包含 `query`、`retrieval_mode`、`filters`、`valid_at`、`known_at`、`include_unknown`，以及 `k_entities`、`k_chunks`、`k_relations`。响应只含三通道命中与检索元数据，不含 `nodes` 或 `edges`。
- `POST /api/projects/{p}/subgraph`：请求包含 `node_id`、`hops` 及相同的范围／时间字段。只返回该种子周围的局部节点和关系。
- `POST /api/projects/{p}/qa/stream`：请求包含 `query`、`generate`、`retrieval_mode` 及范围／时间字段。SSE 顺序为一个 `event: evidence`、零个或多个 `event: delta`、一个 `event: done`；失败可返回 `event: error`。前端不得接入旧式 `/qa/stream/{name}` 或 `start/token` 事件。

## 可访问性与响应式

页面使用语义化标题和区域；所有输入均有可见标签或可访问名称，按钮保持清晰的键盘焦点。结果、证据和图谱定位操作必须可由键盘触发。证据折叠按钮维护 `aria-expanded` 和 `aria-controls`。流式回答区域使用 `aria-live="polite"`，按完整句或完成状态批量播报，不逐 token 打断读屏。发送后焦点留在输入框；错误后聚焦重试按钮；跨菜单定位后聚焦图谱标题。输入框规则为 Enter 发送、Shift+Enter 换行，IME 组合输入期间不得发送。加载和错误除颜色外还要有文字或图标状态，文字与背景达到 WCAG AA 对比度。

在视口宽度大于 1100px 时使用 300px／自适应／280px 三栏；701–1100px 时检索栏约 280px、图谱占剩余宽度，详情成为可关闭抽屉；不超过 700px 时按“检索 → 图谱 → 详情”纵向排列，图谱高度至少 55vh，页面不得产生水平溢出。知识问答输入区在桌面固定于内容区底部；移动端使用 `position: sticky` 并避让安全区和软键盘，侧栏沿用可横向滚动的分组导航。

## 测试与验收

真实浏览器测试必须覆盖：

- 侧栏存在“检索与交互图谱”和“知识问答”，不存在独立“知识检索”或“证据问答”。
- 检索点击只产生一次 `/search`，三通道结果可见且不触发 `/subgraph`。
- 点击实体或关系后才产生一次 `/subgraph`，图谱与检索仍在同一 tab。
- 点击知识问答发送只产生一次 `/qa/stream`，同一响应同时渲染证据和回答，不调用 `/explore` 或 `/search`。
- 证据默认折叠，展开后可见引用；回车发送与按钮发送行为一致。
- 页面无 JavaScript 错误，窄屏时三栏顺序降级为检索、图谱、详情。
- 预先加载的图谱和详情在执行检索后保持 DOM 内容不变；三个通道均显示标题、数量及各自空状态。
- 测试 SSE 中证据先于增量回答、增量文字逐步出现、请求中禁用发送；错误和重试保留用户问题。
- 测试从问答证据定位图谱只产生一次 `/subgraph`，不产生检索；原文证据可进入并定位来源。
- 在 700px 窄屏下断言无横向溢出、图谱高度可用；验证 Enter、Shift+Enter、IME、焦点和证据 ARIA 状态。
