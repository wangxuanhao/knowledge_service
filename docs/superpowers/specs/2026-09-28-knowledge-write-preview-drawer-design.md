# 知识写入页：切片预览抽屉与结构化导入分层设计

日期：2026-09-28

## 背景

“知识写入”页目前包含两条不同的数据入口：

1. 文档写入：上传文件或粘贴正文，经解析、切片，并可继续抽取实体与关系。
2. 结构化写入：直接提交 JSON `records`，写入文档、实体、关系、属性或切片记录。

现有页面将“结构化知识批量写入”以普通面板直接放在文档上传区下方，容易被理解成另一种批量文档上传方式。切片预览结果也直接追加在上传面板底部，内容一多就拉长页面、打乱上传区与结构化写入区的视觉关系。

## 已确认的设计

### 1. 切片预览使用右侧抽屉

点击“预览首份切片”后，在当前页面上方打开右侧抽屉，并保留被遮罩的上传页上下文。

抽屉内容分为三部分：

- 顶部：标题“首份切片预览”、文件名、关闭按钮，以及“仅预览，未调用模型、未写入知识”的状态说明。
- 左侧片段目录：显示本次预览返回的片段序号、字符数和原文位置；当前片段有明确选中态。
- 右侧正文：显示当前片段的原始文本，并在顶部重复展示序号、位置与字符数。

抽屉只展示现有预览接口返回的数据，不改变切片算法或接口协议。用户切换片段时仅在前端更新正文，不再次请求后端。

交互规则：

- 请求开始后按钮进入加载态，避免重复提交。
- 请求成功后再打开抽屉；默认选中第一个片段。
- 抽屉使用 `role="dialog"`、`aria-modal="true"`，由可见标题提供 accessible name，并由“仅预览”说明提供 accessible description。
- 抽屉打开后，主页面内容进入 `inert` 状态，键盘焦点被限制在抽屉内；`Tab` / `Shift+Tab` 在关闭按钮、片段按钮和正文滚动区之间循环。
- 可通过关闭按钮、遮罩点击和 `Escape` 关闭。
- 关闭抽屉后，已选文件、处理选项和页面滚动位置保持不变。
- 抽屉打开时锁定页面背景滚动，并将键盘焦点移入抽屉；关闭后焦点回到“预览首份切片”按钮。
- 桌面端抽屉宽度约为视口的 58%，并设置合理的最小、最大宽度。
- 片段目录使用带可访问名称的导航列表，列表项为原生 `button`；当前片段通过 `aria-current="true"` 标记，每个按钮通过 `aria-controls` 指向正文面板。键盘使用原生 `Tab` / `Shift+Tab` 移动、`Enter` / `Space` 选择，不模拟 ARIA tabs 的方向键协议。
- 窄屏下改为接近全屏的底层/全屏面板，片段按钮列表切换为横向滚动，避免正文过窄。

### 2. 结构化写入降级为高级入口

将标题改为“结构化记录导入（高级）”，并放入默认折叠的 `details` 容器。摘要区域直接说明：

> 面向 API 或业务系统的 JSON 记录导入，不是批量上传文档。

展开后补充以下边界说明：

- 一次可提交 1–1000 条记录。
- 支持 `document`、`entity`、`relation`、`attribute`、`chunk`。
- 实体、关系与属性按当前项目本体校验，关系通过记录 ID 引用端点。
- 整批原子写入；任一记录校验失败，整批不写入。
- 已存在的记录 ID 需要走“知识与历史”中的修订流程。

保留现有 JSON 文本区和“写入知识”按钮，不改变 API、默认示例或提交行为。本次只修正信息架构与文案。

## 组件与职责

### `chunk-preview` 抽屉容器

现有 `#chunk-preview` 从普通文档流容器改为具备遮罩和对话框语义的抽屉宿主。它负责：

- 呈现加载后的预览结果；
- 管理片段选择；
- 管理打开、关闭与焦点恢复；
- 对空结果和异常状态提供稳定布局。

预览请求、文档读取与解析设置继续由现有 `workbench.js` 逻辑负责。

修改 `workbench.js` 或 `workbench.css` 时同步更新 `index.html` 中对应静态资源的版本查询串，确保缓存客户端不会得到新标记与旧行为/样式的混合版本。

### 结构化导入容器

使用原生 `details/summary` 实现默认折叠，避免增加新的状态依赖。内部继续复用 `#batch` 与 `#write-batch`，因此现有绑定无需改动。

## 数据流

1. 用户选择文件或粘贴正文，并设置切片参数。
2. 点击预览后，前端仍只读取批次中的第一份内容。
3. 文件模式调用 `/documents/upload/preview`；文本模式调用 `/documents/preview`。
4. 后端返回 `total` 与预览 `chunks`。
5. 前端缓存本次响应、渲染片段目录并打开抽屉。
6. 用户切换目录项时只更新当前正文。
7. 用户关闭抽屉后可继续修改参数、重新预览或正式上传处理。

结构化记录导入保持独立路径：解析 `#batch` JSON 后调用 `/records`，不与文档预览或文档解析队列合并。

## 异常与空状态

- 未选择内容、JSON metadata 无效、切片参数无效：沿用当前统一状态栏报错，抽屉不打开。
- 预览接口失败：恢复按钮状态，在统一状态栏显示错误，保留上传表单。
- 接口成功但无片段：抽屉显示“未生成可预览片段”，不渲染空目录。
- 正文过长：仅正文区域滚动，抽屉标题与片段目录保持可见。
- 文件名和正文继续经过现有 `esc` 转义，禁止以 `innerHTML` 注入未转义内容。

## 视觉方向

延续现有绿色、纸张感和克制的知识工作台风格，不引入新的主题。抽屉使用白色主体、轻遮罩、清晰边界和固定信息层级；片段选中态使用现有绿色强调色，不使用大面积渐变或高强度动画。

动画限于约 180–220ms 的抽屉进入、遮罩淡入和片段切换反馈，并兼容 `prefers-reduced-motion`。

## 验收与测试

### 行为测试

- 文件模式和文本模式都能打开抽屉并默认显示第一片。
- 目录按钮切换准确展示对应片段正文、位置和字符数，并正确更新 `aria-current`。
- 关闭按钮、遮罩和 `Escape` 均可关闭，并恢复按钮焦点。
- 抽屉打开时背景内容不可聚焦或被辅助技术操作，焦点循环不逃离抽屉。
- 重复预览会替换旧结果，不累积旧 DOM。
- 请求失败时抽屉不出现，按钮恢复可用。
- 正式上传流程与结构化写入流程保持原行为。

### UI 契约测试

- 页面包含抽屉标题、关闭控件、片段目录和正文区域。
- “结构化记录导入（高级）”默认折叠，摘要明确写明“不是批量上传文档”。
- 原有 `#chunk-preview`、`#batch`、`#write-batch` 等关键 ID 保留，避免破坏现有绑定。

### 人工验证

- 在常见桌面宽度下，抽屉不遮断关闭按钮，正文具有舒适行宽。
- 在 850px 和 520px 以下视口检查全屏/底层布局与横向片段导航。
- 仅使用键盘的 `Tab` / `Shift+Tab`、`Enter` / `Space` 和 `Escape` 可完成打开、切换片段和关闭预览。
- 页面背景在抽屉打开时不可滚动，关闭后滚动状态恢复。

## 不在本次范围

- 不预览批次中的第二份及后续文档。
- 不增加切片编辑、删除或拖拽重排。
- 不修改切片算法、预览接口或正式上传任务队列。
- 不为结构化记录导入新增表格编辑器或 CSV 导入。
