# 交互图谱节点点击与全图恢复设计

## 背景

当前交互图谱在点击实体节点时会调用 `drawGraph(nodeId, hops)`，把当前图替换成该节点的邻域。之后“重新渲染全图”又会从隐藏字段或实体下拉框回退取得已选节点 ID，因此继续请求邻域，无法恢复顶部筛选范围内的全图。

## 目标交互

- 点击图中的实体节点或关系边，只更新右侧详情面板，不改变图谱节点、关系或当前缩放范围。
- “展开邻域”是唯一从实体选择进入 N 跳邻域的显式入口。
- 顶部“应用筛选”按实体类型、关系类型和 Metadata 条件确定全图范围。
- “重新渲染全图”始终请求顶部筛选范围内的全图，不复用当前选中的实体 ID。
- “重置视图”只重置当前图的缩放和位置，不请求数据。

## 状态与数据流

图谱范围和详情选择是两类独立状态：

1. 顶部筛选生成 scope，`drawGraph(null, hops)` 以 `node_id=null`、`attribute_mode=summary` 请求该 scope 的全图。
2. 实体选择框或节点点击可以更新当前实体选择，并调用 `inspect(row)` 展示详情，但节点点击不得调用 `drawGraph`。
3. 用户点击“展开邻域”时，读取当前实体 ID，调用 `drawGraph(entityId, hops)`，以 `attribute_mode=expanded` 请求邻域。
4. 用户点击“重新渲染全图”时，显式清除影响图谱请求的实体选择状态，再以 `node_id=null` 请求全图。右侧详情可以保留，直到用户关闭或点击其他节点；它不再参与图谱范围计算。

`drawGraph` 的 `node` 参数必须区分“调用方显式要求全图”和“调用方要求使用当前选择”。本次不再让 `null` 自动回退到隐藏字段或实体下拉框；需要邻域的调用方必须显式传入实体 ID。

## 错误处理

- 未选择实体时点击“展开邻域”，继续显示现有明确提示，不发送请求。
- 全图或邻域请求失败时保留当前图，并通过现有状态栏展示错误。
- 现有请求序列保护继续生效，旧请求不得覆盖较新的筛选或邻域结果。

## 测试

- 浏览器回归测试：点击图中节点后，只出现详情内容，`/subgraph` 请求次数不增加，图谱摘要保持不变。
- 浏览器回归测试：进入邻域后点击“重新渲染全图”，请求体为 `node_id=null`、`attribute_mode=summary`，图谱恢复到顶部 scope 的节点和关系数量。
- 保留现有“展开邻域”测试，确认其仍发送显式实体 ID 和所选跳数。
- 运行前端检索流程测试文件，并用本地真实服务重复原始 `3 → 2 → 3` 场景。

## 非目标

- 不移除实体选择框或“展开邻域”能力。
- 不改变后端 `/subgraph` 契约、顶部筛选语义、详情内容或图谱布局算法。
- 不增加新的模式开关、历史栈或自动返回机制。
