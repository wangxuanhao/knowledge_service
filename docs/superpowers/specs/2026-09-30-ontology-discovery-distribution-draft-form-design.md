# 本体发现分布与累计草案表单改版设计

## 背景

“本体工作台”的发现阶段目前把“实体类别分布”“关系类型分布”“属性定义分布”同时排成独立卡片。每张卡片展开后都会变成长列表，页面高度和视觉密度迅速增加；类别行只显示名称和数量，也不利于比较比例。类别筛选与下方候选类型切换是两套相邻控件，关系不够清楚。

“生成累计草案”当前在右侧检查器中直接排列标题、说明、一个没有可见字段标签的输入框和主按钮。用户难以快速理解输入内容的用途、当前会冻结哪些候选，以及能否取消操作。

## 目标

1. 实体、关系、属性三类分布保持同一信息层级。
2. 用户能够快速比较各类别数量，也能点击类别筛选对应候选。
3. 任一时刻只展开一种分布，避免三组长列表同时撑开页面。
4. 分布类型、筛选条件和候选列表使用同一状态，避免出现“点了关系类型却仍在看实体候选”的割裂状态。
5. 累计草案表单明确说明操作结果、冻结范围、字段含义和后续去向，并保持舒展的纵向节奏。
6. 保持现有发现、筛选、草案创建 API 及数据模型不变。

## 非目标

- 不修改候选发现、聚类、归纳或草案创建的后端逻辑。
- 不改变候选统计口径、草案状态机或发布流程。
- 不新增多选类别筛选；本次继续使用单类别筛选。
- 不重做整个本体工作台的视觉系统。

## 分布总览设计

### 三类总览入口

把三张同时展开的分布卡片替换为一个“分布总览”组件。组件顶部包含三个等宽入口：

- 实体类别：展示实体候选总数和类别数。
- 关系类型：展示关系候选总数和类型数。
- 属性定义：展示属性候选总数和定义数。

入口使用按钮语义，并通过 `aria-pressed` 表达当前项。点击入口时：

1. 将候选类型切换为对应的 `entity`、`relation` 或 `attribute`。
2. 清空旧类别筛选，避免把实体类别名称误用于关系或属性候选。
3. 更新唯一的分布详情区。
4. 同步更新下方候选标题、计数和候选卡片。

证据异常不属于本体分布，因此不作为第四个分布入口。现有异常访问能力保留为一个紧凑的“查看证据异常”按钮；查看异常时，分布总览保留上一次选择，点击任一分布入口即可返回相应候选。

### 唯一详情区

三个入口共用一个详情区，任一时刻只渲染当前类型的数据。详情区包含：

- 标题和一句类型说明。
- 类别/类型/定义总数。
- 按数量降序排列的水平比例条。
- 每行的名称和精确数量。
- 默认展示前 6 项；数据超过 6 项时显示“展开全部（共 N 项）”。
- 展开后使用有最大高度的双列网格和内部滚动，不继续无限拉长页面。

比例条以当前分布最大值为 100% 计算，仅用于同组内部的视觉比较；精确值始终以行尾数字为准。数量相同时继续按中文名称稳定排序。

### 类别筛选反馈

点击详情行时同时设置候选类型和类别筛选。选中行使用绿色背景、左侧强调线和 `aria-pressed="true"`。下方候选标题旁显示“类别：X”的可清除筛选标签及筛选后数量。

再次点击已选中的详情行，或点击清除按钮，都会取消类别筛选，但保留当前候选类型。搜索、来源和置信度筛选继续与类别筛选叠加使用。

## 累计草案表单设计

点击“生成累计草案”后，右侧检查器显示独立的纵向表单：

1. 小标题“创建草案”、主标题“生成累计草案”。
2. 简短说明：当前候选及来源证据会被冻结，随后进入对象设计和逐项审核。
3. 冻结范围摘要：候选总数、分布项总数、来源文档数。统计来自已加载的发现数据，不新增请求。
4. 可见字段标签“草案名称（必填）”。
5. 非空的建议名称：优先使用当前项目显示名加“知识草案”和当天日期；无法取得显示名时使用“发现本体 · YYYY-MM-DD”。
6. 帮助文本：名称用于草案列表、审核记录和版本追溯，生成后仍可修改。
7. 列表显示预览，随输入内容更新；空值显示“未命名草案”。
8. 独立操作区：次要按钮“取消”，主按钮“生成并进入设计”。

“取消”只关闭表单并恢复检查器的发现阶段空状态，不改变候选、筛选或草案数据。提交时继续调用现有 `createDiscoveryDraft`；前端仍会去除首尾空白，并保留现有空值回退行为。

## 组件与状态边界

在 `knowledge_service/web/ontology-workbench.js` 中：

- 用一个新的分布总览渲染函数替代三次独立 `cluster(...)` 渲染。
- 分布配置显式绑定 `kind`、标题、说明和数据源，避免通过标题文本推断类型。
- 在状态中保存最后选择的分布类型；候选类型继续使用现有 `state.discoveryKind`。
- 类别行点击负责同步 `discoveryKind` 和 `filters.cluster`。
- 证据异常入口继续复用现有异常候选逻辑。
- 草案表单保持独立构建函数，不改变 `createDiscoveryDraft` 的网络和状态转换职责。

在 `knowledge_service/web/ontology-workbench.css` 中：

- 增加三类总览按钮、比例行、双列详情网格、筛选标签和草案范围摘要样式。
- 复用现有绿色、琥珀色、边框和纸张背景变量。
- 桌面宽度使用三列总览与双列详情；窄屏降为单列，避免横向滚动。
- 草案表单控件间距至少 12px，操作区与表单主体用边框分隔。

## 数据流

```text
发现 API 数据
  ├─ entity/type clusters ─┐
  ├─ relation clusters ────┼─> 分布总览配置 ─> 当前详情区
  └─ attribute clusters ───┘                         │
                                                     ├─ 点击分布入口 ─> discoveryKind
                                                     └─ 点击详情行 ───> discoveryKind + cluster filter

discoveryKind + query/source/confidence/cluster filters
  └─> visibleCandidates()
      └─> 候选标题、筛选标签、结果数量和候选卡片

点击“生成累计草案”
  └─> 已加载发现统计 + 来源集合
      └─> 右侧表单范围摘要
          └─> 名称提交到现有 POST /ontology-discovery/drafts
```

## 空状态与错误处理

- 某一分布没有数据时，入口仍显示计数 0；详情区显示“暂无数据”，不显示展开按钮。
- 当前类别筛选没有候选时，继续使用现有空结果提示。
- 切换项目时，分布类型重置为实体，类别筛选清空。
- 草案创建的加载、409 冲突、普通错误和成功跳转继续走现有提示与处理逻辑。
- 输入框保留 `maxlength=200`；提交按钮调用现有空值回退，不在本次引入新的后端校验差异。

## 可访问性

- 三个分布入口和每个类别行均使用真实 `button`。
- 当前分布和当前类别均提供 `aria-pressed`。
- 展开按钮维护 `aria-expanded`，文本同时表达展开/收起状态。
- 草案名称使用显式 `label` 与输入框关联。
- 颜色之外继续使用边框、强调线、文字和状态属性表达选中状态。
- 保留现有 `focus-visible` 样式和减少动画偏好。

## 测试与验收

扩展 `tests/service/test_ontology_workbench_ui.py`，覆盖：

1. 页面同时存在实体、关系、属性三个分布入口及其数量。
2. 默认只渲染实体分布详情，且最多展示 6 项预览。
3. 点击关系或属性入口会切换 `state.discoveryKind`、活动入口、详情数据和候选列表。
4. 点击类别行会设置正确的类型和类别筛选；选中态、清除标签与结果数量同步。
5. 展开按钮显示全部项目，收起后恢复预览；详情区保持最大高度和内部滚动样式。
6. 证据异常入口仍可访问，点击任一分布入口可返回正常候选。
7. 草案表单存在明确标签、帮助文本、范围摘要、建议名称、实时预览、取消和主操作按钮。
8. 提交继续发送修剪后的名称并进入现有创建流程；取消不产生请求。
9. 现有映射复用、无变更诊断、冲突处理和草案创建测试继续通过。

验收时还需在桌面宽度和小于 820px 的响应式宽度各检查一次：页面不横向溢出，三类分布可清楚切换，展开区与右侧表单不拥挤。
