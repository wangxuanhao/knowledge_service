# Knowledge Service 傻瓜级操作手册重写设计

## 1. 背景与目标

现有 `docs/知识图谱操作手册.html` 已覆盖登录、用户管理、知识写入、本体建模、知识编辑、软删除和提取审核等功能，但第 5～7 章没有形成可连续执行的业务流程，截图也存在中文标注乱码、红框遮挡控件、裁切缺少上下文等问题。

本次重写的目标不是增加产品功能，而是让第一次使用系统的读者能够只看手册完成一次完整操作，并理解每一步完成后本体、实体脑图、知识台账和版本信息分别发生什么变化。

## 2. 内容原则

1. 全书使用同一个连续案例：员工“张三”从“员工”重分类为“产品经理”，所属“产品部”。
2. 每个操作步骤固定回答四件事：在哪里、点什么、填什么、成功后看到什么。
3. 本体结构与实例知识分开讲述，避免把“新增类”误写成“新增实体”。
4. 版本名称统一：软件使用“服务 v1.1.0”，结构使用“本体 vN”，单条知识使用“记录修订 rN”；若当前界面仍显示 `vN`，手册明确注明它是该记录自己的版本，而不是本体版本。
5. 只记录当前产品真实能力。属性在本体画布中挂在类详情下，不绘制成节点；实体脑图当前不展示属性分支；知识台账可以切换到属性视角。
6. 每章都提供“完成标志”和“常见误解”，使用户可以自行判断是否操作成功。

## 3. 章节结构

### 3.1 起步部分

- 封面和阅读说明：说明适用服务版本、完整案例和三类版本。
- 系统概览与启动准备：保留现有部署、登录和项目概念，但压缩与主流程无关的说明。
- 角色和权限：说明超级管理员、项目管理员和普通操作人员分别能完成哪些步骤。

### 3.2 主流程部分

主流程按以下顺序组织：

1. 创建项目并完成首次知识写入。
2. 打开本体建设台，认识类、关系、属性和本体版本。
3. 新建“员工”“产品经理”“部门”类，并设置继承关系。
4. 给“员工”添加“工号”“入职日期”属性，说明属性位于类详情中而不是画布节点。
5. 新建“隶属于”关系，设置起点类和终点类。
6. 校验、提交审核并发布本体 v2。
7. 对比发布前后：本体画布变化，实体脑图与知识台账不自动变化。
8. 按本体 v2 写入新实例，或对已有知识执行受控重分类。
9. 对比迁移前后：实体类型、关系、脑图分支、台账本体归属和记录修订变化。
10. 在知识台账分别查看实体、关系、属性和原文片段。
11. 编辑、软删除、撤销及历史记录。

### 3.3 高级流程与排错部分

- 开放提取和确认性提取。
- 知识审核。
- 实体类型关闭。
- 常见问题：发布后数据为什么没变、为什么脑图没有属性、为什么记录版本与本体版本不同、为什么旧本体知识仍存在。

## 4. 贯通案例与状态变化

案例初始状态：

- 本体 v1 包含“员工”和“部门”。
- 实体“张三”为员工，实体“产品部”为部门。
- “张三”当前为记录修订 r1，依据本体 v1。

建模操作：

- 新增“产品经理”，父类为“员工”。
- 给“员工”添加“工号”和“入职日期”属性。
- 添加“隶属于”关系，起点为“员工”，终点为“部门”。
- 发布本体 v2。

发布后的完成标志：

- 本体建设台能看到新类、属性详情和关系边。
- 实体脑图没有自动多出“产品经理”节点。
- 知识台账中的“张三”仍是 r1 / 本体 v1。

迁移或重新写入后的完成标志：

- “张三”的类型变为“产品经理”。
- “张三—隶属于→产品部”关系在实体脑图中出现。
- 台账出现实体、关系和属性记录。
- “张三”变为 r2 / 本体 v2，r1 / 本体 v1 仍能在历史记录中查看。

## 5. 截图与标注规范

### 5.1 截图来源

- 优先使用当前版本实际运行界面，不用与当前 UI 不一致的示意图冒充截图。
- 截图前固定浏览器缩放比例和窗口尺寸，避免同一章节控件位置跳动。
- 截图只保留完成当前任务所需的界面上下文；涉及左侧导航、项目选择或版本归属时必须保留对应区域。

### 5.2 标注方式

- 使用圆形编号 `① ② ③` 标记操作顺序，中文说明放在截图下方的步骤表中，避免字体乱码和长文字压住界面。
- 红框只圈定目标控件，边框与控件保留至少 6 像素间距。
- 单图最多标记三个连续动作；超过三个动作拆图。
- 不用半透明色块覆盖输入值、按钮文字、版本卡片或结果内容。
- 每张图都配“这张图做什么”和“完成后应看到什么”。

### 5.3 截图清单

主流程至少包含：

1. 选择项目并进入本体建设台。
2. 新建类并设置父类。
3. 在类详情中新增属性和数据类型。
4. 新建关系并设置起点/终点。
5. 校验与发布本体。
6. 发布后的本体版本卡片。
7. 发布后尚未迁移时的实体脑图。
8. 发布后尚未迁移时的知识台账。
9. 受控重分类的计划、预演和执行。
10. 迁移后的实体脑图。
11. 迁移后的实体台账、关系台账和属性台账。
12. 单条知识的历史版本。

## 6. 页面呈现

手册继续交付为单个可离线打开的 HTML 文件，样式、脚本和图片均内嵌。页面增加：

- 左侧章节目录和当前位置高亮。
- 顶部“完整流程”进度导航。
- 操作步骤卡片、完成标志、注意和原理四类视觉区块。
- 发布前后与迁移前后的对照表。
- 三类版本关系示意和贯通案例时间线。
- 打印样式，确保分页时截图与图注不被拆开。

不引入外部 CDN、外部字体或网络图片，避免离线打开时样式和中文标注失效。

## 7. 验证标准

1. HTML 在无网络环境下可以打开，目录、锚点和内嵌图片正常。
2. 所有中文标注可读，不出现方框或乱码。
3. 每个编号都能在相邻说明中找到唯一对应步骤。
4. 所有红框不遮挡控件文字、输入值和结果信息。
5. 主流程从创建项目到迁移后查看脑图、台账可以连续执行。
6. 全文搜索不存在把本体版本和记录修订混为一谈的表述。
7. 明确说明属性在三个页面中的不同呈现：本体详情、脑图不显示、台账属性视角。
8. 明确说明发布本体不会自动修改实例知识。
9. 验证 HTML 标签闭合、内嵌资源可解析，并在浏览器中抽查桌面宽度和打印布局。

## 8. 范围边界

本次只修改操作手册及其必要的内嵌图片资源，不改变本体、脑图或知识台账的业务实现。若实际运行界面缺少手册所需的版本筛选、迁移入口或属性展示，手册按现状标明入口和限制，不虚构尚未实现的功能。
