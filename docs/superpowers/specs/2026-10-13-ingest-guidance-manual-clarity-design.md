# 知识写入结果引导与操作手册清晰化设计

日期：2026-10-13

## 目标

在不增加流程状态机、不改变本体建模台直接编辑方式的前提下，让用户在知识写入完成后知道结果是什么、接下来可以去哪里处理，并让离线操作手册能够按步骤完成同一流程。

OWL 2 RL 及其他逻辑推理试点不属于本次范围。现有父子类扩展、domain/range 业务校验、SHACL 校验和图谱关系路径保持不变。

## 设计原则

1. 本体建模台继续直接编辑。编辑动作仍写入草案，校验与发布仍是治理边界，不增加“当前第几步”或强制通关状态。
2. 上传结果只提供上下文动作。按钮由本次任务的模式和结果决定，是快捷入口，不产生新业务状态。
3. 页面只陈述服务端已知事实。没有抽取结果时，必须区分“用户选择仅文档模式”和“执行抽取但未识别出知识”。
4. 用户术语准确。“推理路径”改称“图谱关系路径”，避免把无向多跳 BFS 误解为 OWL 蕴含。
5. 手册以 `scripts/build_knowledge_service_manual.py` 为权威源，`docs/知识图谱操作手册.html` 是生成物。`docs/2026-10-01-本体工作台操作手册.md` 只补当前入口与术语说明，避免继续扩大旧页面描述。

## 界面改造

### 1. 把写入模式带入结果工作区

`workbench.js` 提交任务时把提交瞬间的项目 ID 与 `extraction-mode` 一并传给 `IngestResults.watch(jobId, title, {projectId, mode})`。结果工作区在本地任务模型中保存 `projectId` 和 `mode`，不向后端增加新状态。

结果明细始终按任务自己的 `projectId` 请求 `/api/projects/{projectId}/assertions`，不能使用点击时的全局 `current`。即使用户在任务运行期间切换项目，结果卡仍显示原项目的任务和断言，不会串项目。

三种模式显示为：

| 值 | 用户名称 | 结果解释 |
| --- | --- | --- |
| `ontology` | 使用项目本体 · 正式入图 | 按当前已发布本体抽取和校验；合法知识正式入图，冲突事实进入审核 |
| `discovery` | 开放本体发现 · 候选暂存 | 从材料发现候选结构和事实；去本体建模台整理候选 |
| `documents` | 仅文档检索 · 不抽取图谱 | 只保存原文、切片和检索索引，不产生实体、关系、属性 |

界面和手册均称它们为“知识写入模式”，不称为“三种推理方式”。

### 2. 区分两类空结果

- `documents` 模式且断言为空：显示“本次选择了仅文档检索；原文和切片已保存，未执行图谱知识抽取。”
- `ontology` 或 `discovery` 模式且断言为空：显示“本次执行了知识抽取，但没有识别出实体、关系或属性。可核对原文、写入模式和本体术语后重新处理。”

不根据断言数量猜测任务是否成功；任务状态仍来自 SSE。

### 3. 结果卡片的局部快捷动作

每个完成任务只显示与结果有关的按钮：

- 有 accepted 断言：显示“去知识台账核对”，切换到台账并刷新当前项目。
- `ontology` 模式有 pending 断言：显示“去知识审核”，打开现有事实/约束审核页。
- `discovery` 模式有 pending 断言：显示“去本体画布处理候选”，打开本体建模层；不创建新审核页。
- `documents` 模式：显示“去原文数据源”，打开当前项目原文列表。
- 任务失败、取消或中断：显示“查看任务日志”，打开项目与运行的后台任务分区。重试仍使用后台任务已有能力，不在结果抽屉复制一套重试实现。

按钮不自动跳转；用户仍可关闭抽屉或直接进入任意页面。

为避免模块互相模拟点击细节，在应用层提供唯一导航契约 `window.KnowledgeNavigation.open(target, {projectId})`。支持的 `target` 与责任如下：

| target | 目标视图 | 导航层责任 | 目标模块责任 |
| --- | --- | --- | --- |
| `records` | 知识台账 | 确认项目存在，必要时切换到任务所属项目，再打开台账 | 台账沿用页签激活时的 `load()` 刷新 |
| `reviews` | 知识审核 | 切换项目后调用审核模块公开的 `open()` | 审核模块加载当前项目待审核项 |
| `ontology-model` | 本体建模层 | 切换项目并激活画布页签 | 建模模块按现有页签事件加载草案、候选和版本 |
| `sources` | 原文数据源 | 切换项目并激活原文页签 | 原文模块按现有页签事件加载文档 |
| `jobs` | 项目与运行 · 后台任务 | 切换项目、激活运行页并选择 jobs 分区 | RuntimeView 加载当前项目任务 |

`KnowledgeNavigation.open` 返回 Promise。它先验证项目选择器中存在 `projectId`，再完成项目切换，最后激活目标视图；项目已删除时拒绝并交给现有 `status()` 显示“该任务所属项目已不存在”。结果工作区只调用这一个契约，不直接查找目标页按钮、不调用目标页私有加载函数，也不复制审核、台账或任务重试逻辑。

### 4. 问答术语

问答结果中的标题从“推理路径”改为“图谱关系路径”，说明改为“命中实体沿现有关系边可到达的多跳路径”。后端字段 `reasoning_paths` 保持不变，避免接口兼容性变化。

非流式 JSON 问答溯源统一暂不包含在本次实现中。该项需要先确认外部调用方和兼容策略。

## 操作手册改造

### 权威离线 HTML 手册

修改 `scripts/build_knowledge_service_manual.py` 并重新生成 `docs/知识图谱操作手册.html`：

1. 在“写入固定材料”之前增加三种知识写入模式对照，明确何时选择、是否入图、结果去哪处理。
2. 把写入步骤写成可执行动作：选择模式 → 选择文件 → 预览切片 → 上传处理 → 打开结果工作区 → 按结果按钮继续。
3. 对每个结果分支写“看到什么 / 点击哪里 / 完成标志”。
4. 问答章节统一使用“图谱关系路径”，明确它不是 OWL 推理。
5. 增加排错项：仅文档模式没有实体、抽取模式结果为空、待确认知识在哪里处理。

现有截图若仍能准确定位入口则复用；不为纯文案变化重新截图。若按钮布局发生改变并使 `S04b` 标注失真，则只重新捕获受影响的截图，不批量重拍全部 32 张。

### Markdown 手册

在 `docs/2026-10-01-本体工作台操作手册.md` 开头增加“当前界面入口”说明，并新增知识写入模式、结果去向、图谱关系路径三个小节。旧版本页面名称若与当前合并后的“本体建模层”冲突，相关入口描述同步改为当前名称；不重写与本次无关的权限、API 和历史设计章节。

## 错误与降级

- 结果明细读取失败：保留现有错误文案，并提供“查看任务日志”。
- 目标页面入口不存在：按钮操作调用统一导航入口；入口返回失败时用现有状态提示显示错误，不静默失败。
- 当前项目已经切换：结果明细仍按任务保存的 `projectId` 读取；点击快捷动作时由 `KnowledgeNavigation` 明确切回任务所属项目，再打开目标视图。
- 任务所属项目已删除：保留结果卡，快捷动作显示错误，不降级到当前项目。
- 当前项目没有数据：台账和来源页使用各自现有空状态。

## 测试与验收

1. Node 单元测试覆盖 `documents/ontology/discovery` 三种模式的空结果文案和动作集合。
2. 前端契约测试锁定“图谱关系路径”这一用户可见术语，并禁止渲染模板继续显示“推理路径”；后端字段 `reasoning_paths` 保持原名。
3. 浏览器测试验证按钮调用既有导航入口，不复制后端写操作。
4. 文档契约测试要求三种模式、五类结果去向、OWL 暂不实施说明全部出现。
5. 用 `llm_model` 重新构建离线 HTML，运行手册完整性测试并在浏览器检查目录、步骤和截图标注。
6. 8100 真机至少验证三种模式切换、空结果说明和一个有结果任务的快捷动作；如果现有项目没有代表性数据，使用隔离演示项目，不修改用户业务项目。

## 不做的内容

- 不实现 OWL 2 RL、HermiT、Pellet 或推导事实入图。
- 不增加上传流程状态机、阶段条或强制跳转。
- 不复制审核、重试、台账维护逻辑到结果抽屉。
- 不改变后端 `reasoning_paths` 字段和问答 API 返回结构。
