# 本体与知识维护交互设计

用户已确认先实施模块 1—4；自然语言查询与 OAG（5—6）由另一聊天继续开发。本设计落实此前已提出且用户批准的渐进增强方案。

## 范围与实现选择

保留现有 ECharts 主图谱、Cytoscape 本体画布、原生 JS 和既有记录修订接口。整体移植 Playground 或替换主图谱引擎会扩大并发改动面；本轮采用现有引擎增强。实体/关系已有结构化编辑，不重复实现。

1. 主图谱：拖节点只调整布局；拖空白平移；滚轮/按钮缩放；拖动不误触详情。分开“适应视图”和“重新布局”，适应视图保留节点位置。相同图谱类型切换和细节刷新尽量保留布局；项目切换清理状态。布局仅属视图，不写事实。
2. 台账：实体、关系继续共用 record-dialog。补正式属性的所属实体、属性类型、数据类型和值表单，保留原始记录其他字段、绑定本体、expected_version；类型化值校验，保存走既有修订入口。读不到绑定本体时明确阻止可靠表单操作。
3. 本体建模：保持现有点选/两步连关系/改父类/审核发布，修复拖动与选中冲突、布局刷新覆盖手动位置；增加可发现的交互说明和重新布局入口。不得因移动节点产生本体命令。
4. 路径循迹：先在当前已返回的实例图中选择起终点，指定方向与最大跳数，BFS 返回一条最短路径。排除虚拟属性节点/边；保留关系本来方向及逆向遍历标志。链条和高亮联动，点边复用证据详情。明确“当前已加载图谱内”，无路径不声称全库无关系。项目/查询范围/图谱变化后清理或重新校验结果。提供清除高亮。全库寻路接后端统一范围读取需另阶段，避免侵入 OAG 正在更改的 explorer/retrieval。

## 并发边界

不修改 OAG 的服务、模型、范围、投影、数据库迁移及问答逻辑。workspace.js/index.html 与另一个聊天的前端范围改动共享，使用局部补丁，保留所有现有差异。不上线、不重启共享服务、不并行跑 PostgreSQL pytest。独立前端模块负责交互与寻路，最少挂接既有 workspace。修改的资源必须 bump index.html 缓存版本。

## 验证

Node 行为测试覆盖路径方向、循环、平行边、跳数、无结果、虚拟投影排除和输入不变；交互测试覆盖点击/拖动区分、缩放/适应不改变坐标、项目清理。属性表单覆盖数值、布尔、日期和版本绑定保留。运行相关前端契约回归。使用静态前端与隔离 API fixture 做真实浏览器拖动/平移/缩放/路径与表单检查，不调用生产 LLM、不写业务数据库。记录未完成的运行验证，不以静态字符串检查代替交互检查。
