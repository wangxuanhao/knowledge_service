# 问答可读性与检索延迟

用户已确认：紧凑系统主题标题、答案卡片、折叠证据、底部输入区，显示模型调用状态和耗时。找到未维护生效时间的材料时，明确说明原因，保留有效性边界。

## 界面与行为

移除大面积深色欢迎横幅与宽泛 header 样式影响，使用系统色变量。问题示例简短排列；答案正文安全渲染基本 Markdown，引用仍打开冻结来源。输入区保留模型开关、检索模式，时间高级项可折叠，移动端不越界。最终答案与流式草稿明确区分。证据默认折叠，保留来源、有效性和结构待定解释。

显式显示回答模式、模型未调用原因以及最终阶段耗时。此轮不把未知有效性的材料升级成有效规则，也不为让开关生效而绕过现有依据要求；模型开着但无有效依据时明确解释跳过原因。无有效依据但有待核对原文时，提示已找到材料、生效时间未确认；没有材料时才说未找到相关依据。

## 性能

现状：截图问题检索走 Milvus；API 关键词约370 ms、混合约500–570 ms，QA约877 ms。QA召回605 ms、有效性30 ms、冻结165 ms。查询按特定平台、通用、未知范围分组，每组重复完整集合 schema/index 检查和 load。

先用边界计时测量编码器、真实 Milvus 查询、schema/load、PostgreSQL 回填与投影检查。只优化确认的重复成本。若缓存已验证集合状态，按物理集合名和连接生命周期区分；重建、删除、重连必须失效，失败不得被永久缓存。平台隔离、有效期、版本可见性和投影就绪检查保持正确。

## 验证

安全契约：正文只用 DOM 创建段落、标题、列表、粗体、代码，不解释原始 HTML、不创建外部链接或任意属性；引用按钮仍由冻结来源组件生成。注入 HTML、javascript 链接、未闭合 Markdown 和正常引用均须验证。

缓存契约：适配器实例持有物理集合名到成功检查/加载时间的映射，60 秒过期，锁保护并发冷请求。仅全部成功后写入。重连、重建、删除和查询失败清除相应状态，失败可重试；外部同名替换在下次到期或查询失败时复查。它不缓存权限、投影就绪或查询结果。

回答状态契约：保留 mode=llm/evidence_only；增加 generation 的 requested/called/skip_reason（disabled/no_eligible_evidence/no_evidence）、material_status（eligible/unverified/none）。仅完成事件报告 called，不能把开关当成实际调用。timings_ms 均为毫秒；状态和阶段时间保存至前端本地历史。模型异常仍走既有错误流，不标记完成。

实际测量：热查询两次 Milvus hybrid RPC 合计25–62 ms，34次 describe_index 加集合准备347–515 ms，编码162–185 ms；首次模型加载约50秒。嵌套计时不可相加。确定性模拟测试断言调用次数/失效，实机计时只作环境相关对比。

回归：待核对文案与模型跳过原因；Markdown 转义/XSS 与引用；证据默认收起；小屏布局。Milvus 热查询不重复 schema/load，异常与生命周期失效。用相同问题和项目比较冷/热API耗时与独立阶段。只运行单一 pytest 会话，不改业务资料。

- 只读剖析命令：`python -m scripts.profile_retrieval --project <项目ID> --query <问题> --mode keyword --repeats 3`。热路径两次集合准备合计0.02ms、两次Milvus关键词RPC合计22–25ms；首次查询仍有检查与载入成本，60秒过期复查也会重新付出这部分成本。
- 无pytest负载下，实际HTTP关键词热查询160–226ms，混合热查询323–348ms。首个混合查询因本地模型冷启动约22秒（另一独立进程曾测到50秒）。这是当前模型和机器的测量，不是固定SLA。
- 同一问题的API问答约0.97–1.24秒，浏览器重复提交约1.37–1.61秒；另有一次4.77秒离群请求。已核对浏览器请求无额外Metadata条件、后端为Milvus，无全项目本地降级。冻结原文与溯源存储/读取仍然同步，不能把Milvus单次RPC耗时描述成完整问答耗时。页面现已显示各阶段。
- 本轮优化没有更改平台隔离、有效期判定或治理数据，也没有用上传时间补造生效日期。相同平台相同正文的待核对引用合并展示正文，原始记录及来源引用保留。
