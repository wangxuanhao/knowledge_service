# 统一 Metadata 限制与图谱路径检查

## 需求与语义

用户指出平台范围和 Metadata 条件分散、字段发现暴露过多系统字段、类型筛选平铺，以及路径循迹位置不合理。沿用现有浅青主题与原生前端。

平台、业务和适用对象持久化在记录的 `metadata.applicability`。查询的结构化 `applicability` 是读取这份元数据的协议，保留它对“具体/通用/未知”的语义，不能替换成简单字符串相等。平台实体与关系是图谱事实，未被原文或治理流程确认的边不能由平台名字自动补出。本次统一界面，不创建或改写任何知识关联。

## 页面设计

统一的可折叠“Metadata 限制”入口，收起时展示范围摘要。展开后依次为适用范围（平台/业务/适用对象）、知识类型（实体类型/关系类型）、其他 Metadata 条件；JSON 和系统字段放在高级设置。普通字段选择默认只显示业务元数据，已添加的系统字段条件仍可见且不被删除。保留现有字段 ID 和查询接口，避免丢失筛选能力。

路径循迹由图谱工具栏按钮打开右侧检查区，起终点、方向、跳数及结果归属于同一局部面板。路径结果按步骤纵向排列，可查看真实边的证据。窄屏为图谱内的右侧抽屉，手机上进入正常文档流，禁止挤占画布底部。

## 实施及验收

1. 先增加字段分类、统一范围结构和路径面板归属的回归，观察失败。
2. 增加独立纯函数字段展示模块，整合现有筛选界面与平台读取器。
3. 移动路径控制面板，保持现有图内最短路径、方向、跳数及原始边身份。
4. 更新资源版本；运行 Node 契约、定向浏览器和后端适用范围测试；核对筛选请求以及宽窄屏截图。

## 摘要与高级条件

高级 JSON 使用显式模式，折叠摘要计数以实际发送的过滤器为准，逐项编辑器暂停，避免覆盖手写条件。清空 JSON 可恢复逐项编辑，重置同时清空 JSON、实际过滤器、三维范围与图谱类型；切换项目清除上一项目的条件。系统字段展示选项不修改已经添加的条件。

窄屏的空详情隐藏规则包含 `:has(#graph-detail:empty)`，路径抽屉的打开态必须以相应优先级覆盖，确保用户未先选节点也能寻找路径。
