# 工作台视觉与检索一致性设计

用户要求先设计再实现，修复截图中的按钮越界、异常展示、颜色与系统主题不统一、批次状态逻辑以及向量检索不可用。

## 设计

沿用现有浅青色工作台：白色内容面板、深青主操作、描边次操作，成功、待处理与失败使用已有语义色变量。相比只修改截图局部颜色，统一组件和响应式边界能覆盖同类问题；相比重建前端框架，本次保持原生 JS/CSS 与现有业务接口，减少回归面。

- 运行总览：图标使用固定尺寸标记，数字与标题左对齐；普通统计项不使用整块选中色。
- 知识写入：状态标签仅展示有数量的状态；批次操作与文件查看操作分组；禁用不适用的操作；读取失败提供单个可重试提示，恢复时清除；切换项目立即隐藏旧批次。
- 本体建模：版本条、主操作、详情文字与发布统计统一到主题变量；候选生成按钮允许换行；中等宽度将详情移至下方，小屏将三栏按顺序排列；首次空图加载出节点时执行自动布局，后续更新保留手工布局。
- 检索：展示模型冷加载进度提示和具体降级原因。向量位于 Milvus，权威范围位于 PostgreSQL，二者需要在筛选路径显式衔接。

## 检索边界

先由 PostgreSQL 完成时间、元数据、本体范围、项目及关系端点可见性过滤，再按精确 `version_id` 从当前项目 Milvus 索引代获取缺失向量，执行范围内余弦排序。读取必须限定项目和 active，不重复套用当前业务时间，不做全局 top-k 后过滤。历史系统时间和未就绪投影不使用当前向量。模型身份、维度以及缺失向量沿用现有错误和降级处理，不静默混用。

## 验证

行为回归覆盖首次空图加载、完成批次按钮状态、自动重试取消、错误去重和恢复、项目切换、文件按钮宽度、版本条颜色以及 1280/1024/768 宽度布局。检索回归覆盖精确版本、已过滤候选、不就绪投影、历史时间、分批取向量及项目约束。运行全部 Node 契约测试和相关 Python/真实浏览器测试；对本机现有项目做只读 Milvus 范围排序验证。

## 运维说明

前端资源随 `index.html` 版本号更新；Python 服务无自动 reload，后端修复需要应用重启才进入已有进程。服务是否可连接不等于所有查询模式已验证；首次本地模型加载和范围检索分别检查。
