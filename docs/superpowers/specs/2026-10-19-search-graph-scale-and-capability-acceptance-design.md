# 检索、知识展示与 15 万实体全量大图验收补充

日期：2026-10-19。状态：按用户明确要求补充规划，**未实现、未完成容量验收**。当前工作区读取 HEAD 为 `724c10d`，含未提交改动；具体结论以本轮磁盘源码审计为准，不能套用旧索引行号或旧版本容量结论。

用户明确同时需要：**全库至少 150,000 个实体可检索；同一图谱视图可加载并绘制这 150,000 个实体。** 局部展开与聚合总览都不能替代第二项。前版草图检查只证明少量示例流程，不能证明编辑完整、检索正确或容量达标。

## 1. 三项结论分开确认

| 问题 | 当前可确认 | 仍未确认 |
| --- | --- | --- |
| 现有能力是否完整保留 | 已有逐项能力/入口规划与部分草图交互 | 尚未逐项完成实际 API/权限/版本/失败行为验收；完整审核、源码写入、类/关系停用、迁移等草图仍有缺口 |
| 知识展示是否改变 | 资料列表、台账、图谱和详情重新组织；本体图与实例图分别展示 | 新呈现不能改变事实身份、来源、本体依据及可编辑范围；更换大图渲染器必须过编辑回归 |
| 检索和 15 万实体是否完整可用 | 现有关键词/向量/混合及部分本体扩展有实现 | 正常 QA 图证据、社区能力、降级一致性与 15 万规模需要分别验收；当前小图和浏览器草图不构成容量证据 |

## 2. 展示方式：同一知识的三个入口

- **本体建模层**展示类、关系类型、数据属性、继承和约束。类型卡片用于结构编辑，不把它当作 15 万个实体实例的卡片墙。
- **知识台账**展示实体/关系/独立属性/片段的可检索分页清单，承担完整 CRUD、历史和治理操作。不能把当前浏览器加载的子集当作整库清单。
- **检索与图谱**由结果列表、局部探索、全量大图组成。结果列表按全库查询；局部探索用于核对关系和编辑；全量大图满足整体浏览要求。三种视图使用相同事实 ID、范围和对象详情。

改变的是呈现及操作归位。对象编辑必须复用当前服务和共享检查器，不能在图谱模式降为只读介绍，也不能用不同 ID 创建第二套实体。

### 编辑与知识语义的保留条件

1. 任一视图选中实体可打开属性/关联/证据/历史；按权限进入名称、类型、有效期等已有编辑，携带预期修订。关系边有独立关系详情与编辑入口；属性有独立记录身份、来源和修订。
2. 保留新增实体/关系/属性、别名、软删除/恢复、查重、融合、冲突选值、复核、撤销。大量节点下仍可按 ID/名称/别名定位，再通过详情操作，不要求先肉眼找到像素点。
3. 本体类节点、继承边、虚拟属性值节点和真实实体/关系明确区分。不能把展示节点直接提交为实体写入；绘图层删除/隐藏节点不删除知识。
4. 发布/历史只读的是该发布快照；创建草案后可继续建模。事实编辑按该记录实际本体依据校验，跨发布重分类另走迁移流程。
5. 提交成功以 PostgreSQL 新修订为准，派生图/向量同步滞后单独展示；不能只改前端 GPU 数据就标保存成功。失败/修订冲突保留输入并解释原因。

## 3. 图谱必须有两种工作模式

| 模式 | 用途 | 数据/绘制要求 |
| --- | --- | --- |
| 局部探索 | 从检索命中、来源或选定实体查看邻域、路径和证据 | 种子、方向、跳数、类型/谓词、分页邻接及显式节点/边预算；高连接度不能只靠限制 hops |
| **全量大图** | 同屏加载/绘制至少 15 万实体并保持基本交互 | 全量实体进入绘图数据集；可按视口裁剪与标签层级显示，但不能只加载前 N 条或仅绘聚合节点后称为全量 |

聚合总览是补充视图，可先展示类型/群组数量，但必须标明聚合含义。客户端缩放、隐藏标签、隐藏某类关系不改变搜索范围。当前已加载图的路径搜索和服务端全库寻路分开标识，未实现后者不得显示为“全库无路径”。

图谱结果必须显示：本次范围、实际已加载实体数、其他节点数、关系边数、数据/布局版本、是否仍在加载、截断/抽样/降级及原因。缺少精确全库计数时显示未知/估计，不虚构精确数量。

## 4. 15 万同屏的实现边界

当前 ECharts 工作区与手工 SVG 草图均不能在没有实测的情况下承诺 15 万同屏。已有性能文档主要覆盖 500 节点/1500 边；本体画布的 160/600 类测试不是实体大图测试。当前实体图 `layout:'none'`，不将其误述为每次都跑 force 导致全部瓶颈。

### 4.1 数据与渲染路线

- 为全量模式采用经实测选定的 WebGL 渲染器；参考本地 Semantica Explorer 的 Sigma/camera 结构，先验证 Sigma/Graphology 等候选在本项目数据和编辑交互上的内存、拾取和绘制能力，再确定依赖。原生 JS/CSS、资源固定版本、许可/供应链与可维护边界保持。
- 运输仅含必要 ID、类型、简短标签和位置；正文、属性、全部来源与历史按对象详情懒加载。使用分块/流式读取和紧凑数组，避免巨型 JSON、多次复制、每节点 DOM，以及在 UI 主线程重新布局全图。
- 复用持久化/服务端布局；新布局作为可取消任务计算，或在 Worker 中有预算地执行。全量加载/布局/渲染分别报告进度。主线程负责相机、拾取和有限标签，视口移动不重建整个图。
- 标签采用缩放层级和密度控制，选中/悬停优先；实体像素点与关系图层分别预算。标签关闭是显示策略，不减少全量数据集成员。
- 遇到 GPU 不支持、context lost、网络失败或内存预算不足，给出可恢复状态和局部探索入口。回退后明确未满足全量模式，不自动把局部图报告为 15 万同屏成功。

### 4.2 服务端契约：不能让前端背完整性责任

新增全量图会话/清单读模型，冻结本次项目/内容范围、数据修订水位及布局依据，返回可核对的实体/边计数和计数口径。节点与边按稳定 cursor 分块读取、去重、续传；边端点必须能在同一会话中解析。会话切换后旧响应不能写回新画布。

这不是把现有 `/subgraph` 传一个巨大 limit。局部接口需要 max_nodes/max_edges、邻接游标和 truncated/continuation；全量接口需要完整枚举和完成标志，不能静默抽样。精确路由名在实施计划中确定，现阶段不伪称接口已存在。

PostgreSQL 仍是权威，Neo4j 只有就绪且满足当前范围/时间契约时才能承担加速；不支持的范围应回到有索引、可分页的权威读取，不能每次将全项目所有正文/记录完整反序列化再裁剪。派生水位落后、资格变化和不可用原因要可观察。冻结清单不冻结权限，读取/导出仍检查当前授权和来源资格。

### 4.3 容量验收：两个要求都必须通过

在同一固定浏览器、CPU/RAM/GPU、分辨率、服务与索引配置下，建立实体 1k/10k/50k/150k 梯度。150k 指真实实体实例，不是把 chunk/属性/虚拟节点凑成 150k records。关系采用至少 300k 和 1m 两档，并补实际数据的高连接度、长标签、多来源、孤立节点、循环和类型不均衡；实际边数超过样本时按实际规模补测。

以下为**待验证目标**，不是本次测得性能，也不能在失败后静默降低规模：

| 验收面 | 初始目标/通过证据 |
| --- | --- |
| 全量完整性 | 150k 实体和约定关系集合全部进入同一图数据集；ID/计数/端点与冻结清单一致，无静默截断 |
| 初次加载 | 有进度、可取消、失败可恢复；固定基线下以全量可交互 ≤30s 为初始目标，分别记录首批可见与全量完成 P50/P95 |
| 基本交互 | 加载完成后连续平移/缩放 10s，初始目标 P95 帧间隔 ≤33ms；节点拾取/选择反馈 P95 ≤200ms；用实际屏幕几何/绘制状态验证 |
| 内存/稳定性 | 记录 JS heap、浏览器进程与可取得的 GPU 内存，提前固定目标机器预算；30 分钟探索、反复切换项目/范围/模式不持续增长、不崩溃 |
| 全库检索 | 150k 实体全集及对应关系/原文参与召回；固定基线下无模型检索暖态 P95 ≤2s 为初始目标；冷态、并发和高级范围单列 |
| 编辑回归 | 全量模式定位对象 → 编辑/来源/历史/治理 → 新修订可读 → 投影同步，完整操作与局部图、台账保持一致 |

需要先做隔离的 15 万节点技术验证，再集成到产品。仅渲染随机点、只测事件函数耗时、只运行 100k records 的脚本 dry-run、截图看到图，都不算上述验收通过。

## 5. 检索“完整”的四个维度

| 维度 | 验收内容 |
| --- | --- |
| 现有功能不丢 | keyword/semantic/hybrid；实体/关系/原文通道；名称/别名和精确 ID 定位；类型/谓词/来源、Metadata、业务/系统时点、本体归属；配额、参数和实际降级；命中高亮、证据和图谱定位 |
| 正确与可解释 | 非当前项目/越权/撤回来源不得越界；不符合本次请求时间条件的来源不进入本次证据集合。未设置业务时点的检索保留历史/未来可见语义，QA 可明确标为参考，不能冒充当前有效规则；后置剔除后必要补召回；未知、通用、不限语义一致；空结果与失败区分；当次请求、实际模式和配置可查 |
| 覆盖与质量 | 原生向量路径和权威降级路径使用可对照的分通道预算；有标注的问题集计算 Recall@k/Precision@k、引用支持性、拒答及错误分类；不保证向量检索每次 100% 召回 |
| 规模与运行 | 默认/高级范围分别验证索引下推、分页、数据可达性、过期投影、缓存冷热、并发、超时、取消、内存与延迟；UI 搜索不得只搜索已绘制的节点 |

“100% 能力保留”与“向量语义召回率 100%”不能混为一谈。精确 ID/名称等可构造确定性用例验证；开放语义问题用标注与误差分析评估。全库可检索也不是一次返回所有结果，列表需可继续浏览/精确定位，界面明确 top-k 与统计口径。

### 当前仍需补齐的链路

正常分组 QA 的图邻域/路径证据、Milvus 快路径和降级路径的分通道一致性、原文/邻接上下文补全、精确来源与高级范围的容量表现均要独立验证。社区 Global/DRIFT 和真实消融执行是新增后端能力，不用三个基础模式代替完整 GraphRAG/OAG。

本轮证据分别记录于 [图谱规模审计](../../research/2026-10-19-graph-scale-and-ui-parity-audit.md)、[检索完整性审计](../../research/2026-10-19-retrieval-completeness-and-scale-audit.md)。前版 [能力对照](../../research/2026-10-19-full-capability-ui-parity.md) 继续作为操作清单，状态随实际验收更新。

## 6. 交付顺序与完成定义

1. 既有编辑/治理入口与协议逐项验收，修复已确认的 winner/复核/恢复等断点，展示改版不退化。
2. 大图数据读模型与 15 万同屏隔离验证并行于检索规模核对；没有这一步，不以新 UI 宣称满足本项目规模。
3. 将全量/局部/列表与共享详情接通，执行上述容量、权限、版本和编辑回归；只有两项 150k 要求都通过才可标规模完成。
4. 单独接通和评测 Local/OAG 图证据、社区及消融运行；公开列出仍未实现的能力。

这一补充揭示前版规划尚缺大规模工作方式与验收条件；本次完成的是把要求和缺口写明，不代表性能或检索完整性已被证明。
