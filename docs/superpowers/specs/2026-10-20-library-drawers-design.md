# 资料库与添加操作的侧边抽屉修正

日期：2026-10-20。依据：用户要求“添加文件、记录放在侧边浮窗”，并明确指出当前平铺布局偏离已认可的 2026-10-16 工作流设计。本次按现有授权修正实际产品，不再重复征求同一布局许可。

## 展示方式

推荐采用“资料列表 + 按需打开右侧抽屉”。独立上传页面会丢失资料列表上下文；常驻分栏会一直占用列表宽度；因此本次把现有表单和详情按需放进侧边抽屉。

- 资料库首屏只保留页标题、添加文件、处理批次/更多入口、筛选与文档列表；不自动展开第一份原文。
- 点击资料行打开详情抽屉，继续保留原文、提取知识、处理记录、修订记录和来源阅读器入口。关闭回到原列表位置与焦点。
- 添加文件在右侧打开宽抽屉，复用现有文件队列、处理方式、本体绑定、元数据、时间、切片、消歧/融合设置和提交逻辑。输入不复制，关闭再打开同一项目保留未提交的选择。
- 上传以“选文件 → 处理方式与资料信息 → 确认处理”组织，只有最后一步提供正式提交。提前切换步骤不提交、不调用模型；确认摘要展示实际文件数、处理路径和绑定本体。
- 处理批次和结构化导入在抽屉内按独立入口展示，不把全部批次、上传表单、JSON 导入铺在一个页面。任务深链仍能打开目标批次。
- 台账新增实体/关系/属性沿用当前受本体约束的表单，展示改为靠右抽屉。

## 行为边界

复用真实服务端协议，不改解析、正式写入、Milvus 或版本语义。选择文件不等于提交；收起抽屉不取消已提交批次。切换项目必须关闭详情和表单，旧响应不能更新新项目；未提交文件和资料信息不得静默带入新项目。显式记录该清理行为，已提交的服务端批次仍可从所属项目任务入口查看。

主工作抽屉一次只打开一个；从资料详情/批次打开原文阅读器、抽取结果或正式记录时先收起主抽屉。切片预览的原始节点移入上传 dialog 的顶层范围，使预览可交互且保留上传表单。Escape 和关闭按钮恢复来源焦点；手机使用全屏抽屉，内容内部滚动，无页面横向溢出。沿用当前资料库的 admin-only 页面策略，不新增 viewer 路由授权；可读批次入口也不展示或执行上传、重试、暂停等写动作，动态按钮同样守卫权限。直接调用服务仍受已有权限约束。

项目切换清理由 `app.js` 的中心 `project.onchange` 调用，覆盖 UI change 事件及既有程序直接调用，不能只监听 DOM change 事件。上传完成回调持有本轮抽屉票据；用户已经关闭或切换项目时，结果不会重新弹出旧抽屉。

## 验证

覆盖：首屏无自动弹详情、点行才开；关闭恢复焦点；页签异步乱序/关闭/切项目保护；上传关闭重开保留同项目输入；步骤切换无写请求；项目切换清理未提交输入；批次深链；只读权限；桌面/390px 布局；实际少量 TXT 上传与任务回执。保留容量项目，不向该项目追加演示资料。
