# 当前工作流收敛与旧兼容清理

用户已授权删除为旧结构、旧数据保留的能力。本次直接沿用当前工作区的完整实现，不另建缺少现有修改的分支。

## 目标与取舍

采用“当前写入与读取协议唯一化”：开放抽取经候选清单、显式预览、确认复用或加入指定草案；结构编辑经 ontology-drafts 的命令、校验、审核和原子发布。删除旧流程实现及调用者，而不是继续增加缓存或版本兼容判断。单纯隐藏按钮会留下旧 API 和重复读写；一次重写数据库适配层风险大且与页面慢缺少因果证据，均不采用。

## 实施范围

1. 删除 discovery 全量自动创建草案、旧草案审核/提交、旧 mapping-only finalize 入口和前端导出。当前选批 intake 和 discover-parents 保留。
2. discovery 概览和候选脑图只从当前候选、intake runs 和已发布本体计算状态；不读 ontology_discovery_draft 副本、不 hydrate，不接受历史生成器指纹。脑图采用与概览同一窄投影，避免全量记录扫描。
3. 单独保存 source_context 文档引用构造，intake 不依赖已删除的生成工作流。来源有效性、CAS、幂等、操作依赖与逐批发布回执保留。
4. 审计旧 ontology 写入适配器及旧全量 records/query：有当前 UI 调用时先切到当前命令/分页协议，再删除旧端点与响应包装；不以 deprecated 别名继续转发。导入外部文件等仍有效的功能需通过当前草案协议实现，不能仅因模块叫 legacy 就删除用户能力。
5. 派生事实的来源只依赖 assertions.canonical_record_id；source_id 仅用于当前合法的文档切片归属。来源批量查询不通过旧候选 metadata 猜关联。保留 known_at 和 assertion_events 的历史查询。
6. 逐项清理旧结构容错分支，不能将可选外部服务、真实异常处理、双时态历史、不可变发布或输入校验误删。

## 旧数据与边界

不增加旧数据迁移读取或双写。旧 discovery artifacts 不再进入概览和候选状态；旧端点直接不存在。若旧统一草案含已删除的 publication effect 协议，必须明确拒绝，不默默恢复旧执行路径。当前 intake bindings、正式本体、来源文档、assertions、正式事实与审计历史不清空。仅在实际存在阻塞且明确定位时，使用限定范围的数据清理，而非删除整个业务库。

## 验证

- 路由清单证明旧生成/审核/finalize/全量查询入口移除，当前 intake、草案命令/审核/发布仍存在。
- 概览与脑图测试禁止读取旧 artifacts 或 current_records，验证状态和返回图仍正确。
- 真实 PG 测试验证当前多批 intake、纯复用、手工草案、拒绝/替换操作、来源撤回、幂等和发布。
- 真实来源分页验证多对多、历史时间与 chunk 归属，证明旧 metadata/source_id 不再伪造正式来源关联。
- 前端 Node 契约与必要浏览器用例验证入口仍正常，所有修改脚本同步缓存版本。
- 单个 pytest 会话顺序执行，服务重启后对当前项目做只读 HTTP 冒烟和响应计时。

最终报告区分已删除、保留的有效能力以及审计边界；不宣称已穷尽第三方依赖中的所有兼容代码。

## 最终残留审计的收敛

- 删除已无生产消费者的 ontology-details 和旧编辑器样式；属性检查器只展示正式 attribute 记录。缺少答案标识时明确无法定位冻结证据链，不推断历史时代。
- 适用范围维度统一 `{mode, values}`，非空范围身份统一 schema2。删除隐藏表单向已应用筛选的启动迁移；新的会话存储格式不读取旧格式。
- 删除 PostgreSQL 向量列编解码、空存储方法和失效的查询参数。Milvus 的真实向量写入、投影水位和重建保持有效。
- 删除 legacy_artifact_id 应用字段，以迁移 0023 删除数据库列。快照只导出、接受当前格式 18，不解析旧行形状。
- 删除已无调用的旧问答上下文实现。属性抽取通过显式依赖注入返回统一 batch，删除全局注册代理和列表结果兼容。
- 范围身份变更的现有派生索引采用一次性维护处理：限定已审计的两个项目，重算历史 scope_identity 和 active fact_keys，预检碰撞并验证权威数据指纹；正式记录 ID、payload、版本、时间与审计均不改。停止已验证空闲的本地服务后执行，随后重建已配置的外部投影。运行代码不增加旧键分支。
