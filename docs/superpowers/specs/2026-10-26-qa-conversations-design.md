# 知识问答会话与扩展结果说明

用户已确认增加独立会话列表与管理，并选择按账号保存到服务端、跨设备恢复。沿用当前项目工作台与冻结引用，不重写检索或来源授权。

## 交互与保存

- 每个账号、每个项目分别列出会话；支持新建、切换、标题搜索、加载更多、改名、删除和清空当前会话。
- 默认标题取首次提问；手动改名后不再自动覆盖。问答正文、提交范围、有效性说明和冻结引用随会话保存。
- 桌面使用会话侧栏，窄屏折叠成抽屉；输入框保持在视口内，会话列表与对话内容各自滚动。
- 删除只影响选定会话快照，来源资料和独立冻结审计不变。删除、清空及本机旧记录导入都有明确确认。
- 本机旧的 `kg_qa_v1_{project}` 不自动上传或删除，只在用户明确确认归属后复制到当前账号。
- 本轮管理问答记录，不把历史答案自动变成新问题的检索依据。

## 对话样式

按用户后续要求，对齐常见 Chat 对话布局：浅色会话侧栏、居中正文、右侧用户气泡、无卡片框的回答，引用默认折叠；检索、模型、本体扩展与时点设置收进输入区的设置浮层。手机使用紧凑项目栏和可展开的完整工作区导航，会话列表为抽屉。对话区域定位其辅助阅读节点，避免长回答把外层滚动区域撑到输入框下方。

会话请求的登录过期保持页面内存，提供另开标签页登录与重试；令牌变化时核验原账号，响应消费时再次检查身份。发送问题先保存成功，再启动回答，切换会话后的迟到保存不修改当前页面状态。

## 边界

服务端从已验证身份获取 owner，所有读取和写入同时限定 owner 与 project。viewer 可以管理自己的会话，不能借此写知识或访问他人会话。快照按显示字段白名单清洗，未知提供商字段不入库。

`qa_conversations` 使用编号迁移创建；messages 保存有限 JSON 文本，version 乐观并发校验。冲突返回409，前端保留未保存正文并要求重新加载，不静默覆盖另一设备的更新。异步切换按账号、项目和代际核验；旧响应不改写新会话。删除等待该会话保存队列并阻止延迟写入。

## 接口

`/api/projects/{p}/qa/conversations`：GET分页/标题查询，POST创建；`/{id}`：GET详情、PUT `{expected_version,messages}`、PATCH `{expected_version,title}`、DELETE `?expected_version=N`。详情为 `{conversation:{id,title,version,created_at,updated_at,message_count,messages}}`；列表为 `{conversations,total,has_more}`。删除同样校验版本，保护另一设备刚保存的新消息。

网络失败、401与版本冲突必须有可见的未保存状态。前端保留正文，提供重试或重新加载操作，切换时不可静默丢弃未保存内容。

## 本体扩展

2026-10-27 更新：下段为当时仅类名入口的诊断记录。实体名／别名到已发布类型的扩展已由 [实体扩展方案](2026-10-27-entity-ontology-expansion-design.md) 接续实现，当前行为以新方案为准。

真实项目 `test_1022_开放` 中，“美团”是实体实例名，其类型为互联网平台/互联网企业，未命中类名；语义与混合各12条，开关前后ID及次序一致，`matched=false,type_hits=0`。改查“互联网平台”两模式均命中类并得到7条类型补召回。扩展结果数可因预算保持不变。

补齐问答页独立开关（默认关闭），透传已有 `ontology_expansion` 字段，并在回答状态中显示类名是否命中、子类数量与类型补召回数量。修复平级类误报层级、QA上下文漏传台账；不把平台名自动推断成父类。

## 验收

真实认证验证两个用户隔离、跨设备恢复、跨项目404、并发409、viewer边界、删除不影响引用、快照清洗；Node验证保存队列与异步切换；实际浏览器验证会话操作和旧记录显式导入，以及桌面/手机输入框与滚动边界。以真实项目的扩展开关差分验证解释信息。
