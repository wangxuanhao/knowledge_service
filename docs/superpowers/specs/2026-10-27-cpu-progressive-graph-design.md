# 纯 CPU 渐进图谱：整体交互与视觉设计

日期：2026-10-27。状态：原扩展草案保留备查；用户已批准下面范围修订中的现有展示优化，首轮已实施。[实现与验证报告](../../research/2026-10-27-graph-visual-refresh-validation.md)记录实际交付、性能边界和未完成的容量目标。下文完整扩展草案不等于已批准或已实现的范围。

## 用户复核后的范围修订（优先于下文初稿）

用户指出，现有系统已经能够先显示小图再扩展，主要不满是展示样式，并询问新方案是否能保证速度与效果。已核对 `full-graph-view.js`：首批、下一批、自动继续、本批后暂停、取消和重新开始均已有实际入口；`SessionLoader` 已有相应会话与加载行为。渐进加载不是待新建能力。

因此近期建议收敛为**在已有渐进加载和绘图路径上改善展示**：统一局部/全量的节点类型色、轮廓、关系线、名称规则、选中与路径高亮，以及工具栏和详情布局；保留现有加载、真实数据、范围、水位及取消语义。通过轻量样式和有预算的标签提升可读性。布局调整本身不等于更换图布局算法，标签避让如需改变候选挑选，应单独测量成本。

下文的代表性采样、新 CPU Canvas 绘图器、Worker 全库索引、图块和快照系统均保留为**后续性能备选**，不是本轮已确认的新增范围，不以“修正样式”为由一起替换。只有现有路径在目标规模的对照测试中显示必须改动，才针对明确瓶颈另定原型范围。

不能在实现前保证新效果或纯 CPU 30 万节点已达标。已有合成实测为连续相机交互帧间隔 P95 68–79 ms；初稿中的首图 3 秒、交互 33 ms 等都是目标，尚未证明。近期展示改动应以同一数据/水位、相同节点关系数量、相同画布像素尺寸和 CPU 软件渲染条件进行前后对照；分别测首批、追加批次、拖动/缩放、节点/关系/空白拾取与内存，多次重复并公开波动。不能靠减少真实加载量、隐藏关键关系或缩小测试画布来宣称提速。

视觉效果需用相同场景的真实界面前后对照审阅，包含局部、逐批扩展、高密度、长名称、选择与路径状态。实现后的性能与视觉验收通过前，不将新样式当成已验证替代方案。当前只完成范围纠正，尚无“新样式已更快/更好看”的测试结论。

用户已确认：默认先显示**覆盖主要类型和关系的代表性概览**，再围绕搜索或选中实体探索。服务器和浏览器均不依赖 GPU；目标数据规模为 30 万真实实体，并验证 60 万、150 万关系两档。允许分多次加载，首先显示可操作的小图。

## 1. 设计结论与备选

推荐采用“**代表性首图 → 分批细化 → 全库概览 / 局部探索**”。完整数据规模与当前画面细节分别管理，加载过程始终可操作；类型颜色、名称、选中、关系及工具栏采用同一套规则。

| 方案 | 优点 | 局限 | 选择 |
|---|---|---|---|
| 代表性小图逐批细化，远景分级显示，按需展开真实实体 | 较快可用，兼顾整体结构、清晰名称和 CPU 预算 | 需要概览数据、增量加载与视图细节调度 | 推荐 |
| 把全部对象缓存后，每次恢复全量绘制 | 加载逻辑接近现状，快照可减少小分页 | 已测重启恢复约 9–13 秒，连续绘图仍卡顿 | 作为数据缓存手段，不作为全部显示策略 |
| 始终只显示某个实体的局部邻域 | 成本低，关系清楚 | 难以了解项目整体结构 | 保留为探索方式，非默认首图 |

依据：[纯 CPU 测试报告](../../research/2026-10-27-graph-cpu-cache-assessment.md)。Hindsight 可借鉴类型色、标签避让、层次及页面内存复用；其持续全节点 Canvas 动画不能直接扩到本项目目标规模。

## 2. 用户看到的过程

### 2.1 首次进入

先显示画布、工具栏、范围说明及轻量加载状态；首批到达后立即显示约 **300–500 个真实实体**和数量受控的真实关系。首批优先提供“点和线都能看懂的小图”，不等待全部数据。

首图从已应用的项目、权限、本体、时点及 Metadata 范围中选取代表节点：主要实体类型分配配额，包含跨类型桥接关系、普通节点和孤立实体代表；固定快照内使用确定性选择和稳定排序。不得直接取前 N 条或全部选择高阶节点。选择不能保证覆盖时，展示实际类型覆盖量，例如“覆盖 12 / 24 类”。孤立实体不是无用数据，不能被关系优先的加载永久遗漏。

缺少预生成概览时，先返回范围内可校验的真实小图，同时后台准备代表性索引；明确标记“初步小图，概览准备中”。不把尚未计算的全库总数显示为 0，也不在同步首屏请求里进行全图力导向、全图关系排序或全量导出。

### 2.2 自动补充与手动继续

建议首批显示后自动进行少量细化，目标从约 400 增加至约 800–1,200 个实体。每次请求与绘图提交分开控制：后台取数可合并较大块，主线程只提交小块，批次之间让出交互时间。

- 用户拖动、滚轮缩放、拖节点或操作表单时，立即暂停新增画面与布局工作；可保留有限后台下载，解码任务遵守背压。
- 停止交互约 200–300 ms 后，才合并补充当前视口细节。新批次不自动 fit、不重排已有实体、不改变选中项。
- 达到动态绘图预算后停止自动增加精细节点，显示“初步概览已就绪，可继续细化或放大探索”；这不是完整加载完成。
- “下一批”明确增加一个有效批次；“自动继续”只推进后台数据与当前视图允许的细节，不无限增加精细对象。达到绘图预算时可继续取数/建索引，但详细实体数量不再无界上升。
- “暂停”停止调度新批次并保留会话与游标；“继续”恢复同一水位；“取消加载”中止本次读取、保留已通过校验的当前画面；“重新开始”重新校验范围并建立会话，旧请求不能落地。

用户主动暂停与手势导致的暂缓分别记录。用户暂停优先：停止拖动不能恢复用户已经暂停的自动任务；在途批次即使完成，也先保存在合法缓存中，不自动改变画面。暂停状态下点“下一批”只提交一个批次，然后仍保持暂停；只有用户点“继续/自动继续”才恢复连续调度。

300–500、800–1,200 是原型起始参数，不是已经证明在所有 CPU 上流畅的承诺。动态预算根据实际帧耗时调节，快机器可增加，慢机器减少；不在每次细小波动时反复改变画面。

### 2.3 全库概览与局部探索

顶部保留两种工作方式：**全库概览**与**局部探索**。“全量大图”的入口迁移为“全库概览”，首次提示它覆盖完整范围、按缩放展示细节；不再暗示一次绘制全部精细节点与关系。

- 全库概览：准备完成后以类型分组、聚合连接和可缩放底图表达当前范围的整体分布；真实代表节点在相应分组区域内显示。空间分组依据实体类型与明确规则，不把任意散点位置解释成语义相似度。
- 聚合对象用带数量的空心轮廓表示，真实实体用实心类型色圆点表示；聚合连线明确为汇总，不可冒充某一条知识关系。选择聚合组后可筛选、查看成员并展开真实节点。
- 放大：仅补充视口附近的真实实体、有限关系和经过避让的名称。缩小：逐步回到聚合层。使用滞回区间与稳定 ID 保持层级切换平稳，不在阈值附近闪烁。
- 局部探索：搜索、双击真实实体或“展开邻域”进入，显示根实体及受预算约束的邻域；保留返回概览前的相机、筛选与选中位置。
- 低层级的关系底图可用预生成图块；清晰关系与选中路径由矢量覆盖层呈现。底图不参与精确实体/关系命中。
- 远景聚合区域可点击展开或放大；单条关系选择在真实关系层完成，界面提示放大查看真实实体与关系。

初步抽样、完整概览、完整索引、详细数据缓存是四种状态，不能相互代称。如沿用已有截图/导出能力，数据未完整时须带当前范围说明；本设计不新增导出功能。

## 3. 布局与工具栏

沿用现有“检索结果 — 图谱 — 详情”工作区，减少额外浮层；侧栏可收起。画布上方工具栏分为明确的两组，**缩放按钮始终左对齐，不放到中间**。

```text
检索输入 / 方式 / 检索           [本体扩展：开] [检索设置]

匹配证据   │  [全库概览 | 局部探索]             │ 详情 / 循迹 / 设置 [×]
可收起     │  [−] [+] [适应画布] [重新布局]    │ 固定标题与关闭位置
           │  [跳数] [展开邻域]    [循迹] [设置]│ 对应内容独立滚动
           │──────────────────────────────────│
           │                                  │
           │        图谱画布                  │
           │    类型色圆点 / 轻关系线          │
           │    选中节点及关联名称优先          │
           │                                  │
           │──────────────────────────────────│
           │ 当前展示 420 实体 / 860 关系      │
           │ 全库 300,000 实体 · 初步概览      │
           │ [下一批] [自动继续] [暂停/继续]   │
           │ [取消加载] [重新开始]             │
```

这是区域关系示意；加载状态条位于画布下方，避免批次按钮挤乱视图工具栏。不同模式不适用的控制显示明确禁用状态与原因，不能静默消失。

- 左侧：`− / ＋ / 适应画布 / 重新布局`；邻域跳数与“展开邻域”紧邻局部探索工具。全库模式中须选择真实实体后才能展开邻域。
- 右侧：`路径循迹 / 图谱设置`，相同高度、圆角、描边、图标与激活样式。图谱设置固定在右端。
- 两种工作方式共用工具栏，保留定位、名称显示、关系线、实体/关系类型筛选等现有能力；不得因替换视图丢失按钮。
- “适应画布”只改变相机；“重新布局”只整理当前精细视图，不同步重算 30 万实体，也不改知识事实。新批次到达不触发这两个动作。提示说明“当前视图”，不暗中重排全库。
- 右侧采用一个详情区域的“详情 / 循迹 / 设置”页签，入口按钮直接激活相应页。标题和关闭按钮始终在同一固定头部，内容从头部下方开始。
- 节点操作“设为起点 / 设为终点 / 展开邻域”放在节点名称与类型下方；不放到关闭按钮上面。设为起终点后再打开循迹页并保留该节点信息。
- 窄屏工具栏按组左对齐换行，不将 `+ / − / 适应画布` 居中。右侧区域仅在画布仍有足够宽度时占独立列；宽度不足则移到画布下方，避免遮挡工具栏与主要节点。正文操作区字号不低于现有可读性要求。

“本体扩展”使用独立状态按钮，文字为“本体扩展：开/关”，配小型开关图标与 `aria-pressed`。开启状态用浅青底及深青文字，关闭用中性描边。保留原检索参数、范围与语义，不因样式变化自动触发查询或扩大授权范围。

相机行为另作明确约定：`+ / −` 以**实际可用画布中心**为锚点，滚轮以指针下的世界坐标为锚点。`适应画布` 在局部模式适应当前展开且未被类型显示过滤隐藏的真实子图，在概览模式适应当前范围的概览边界；首图阶段只适应当前已呈现的小图，不假装已经取得全库边界。计算使用扣除右侧栏、底部状态条及工具栏后的真实画布矩形，保留至少 32 px 内边距。开关侧栏或 resize 时保留可用画布中心对应的世界坐标与缩放，更新绘图/命中尺寸；不自动重新 fit。验收须同时检查节点屏幕位置、相机锚点和工具栏位置，而非只读取坐标模型。

## 4. 视觉方向

采用与现有工作台协调的**浅色、克制、清晰的知识地图**：留白较多、名称可读、选中关系明确。参考 Hindsight 的层次和标签规则，减少常驻动画和装饰。

| 对象 | 设计 |
|---|---|
| 工作区 | 近白背景；卡片白底、细边框、8–10 px 圆角；已有导航和页面品牌保持一致 |
| 画布 | 偏冷近白 `#F8FAFB`；极淡静态网格，可在设置关闭 |
| 主色 | 沿用深青 `#0E7C7B`；激活底色 `#E7F4F2`；文字深墨 `#173638` |
| 类型色 | 青、蓝、琥珀、紫、石板等有限高区分色；同一类型在概览、局部、图例、详情中保持一致；大量类型分配稳定色并提供文字图例 |
| 真实实体 | 实心圆点，细白描边；高阶节点只做有上限的尺寸分级，不无限放大；不常驻阴影或光晕动画 |
| 聚合组 | 空心或浅填充分组标记，显示成员数及组名；与真实实体形状明显不同 |
| 普通关系 | 较细、低对比度；远景采用聚合/底图，近景才补充真实方向与关系名称 |
| 悬停/选中 | 选中轮廓、邻居与真实关联边增强；其余细节降对比；不扫描或重绘全库 |
| 路径 | 单一强调色与编号；方向、关系名称和证据入口可读；取消后恢复统一类型色 |
| 标签 | 普通名称只在合适缩放出现，屏幕网格避让；选中实体、路径、根实体优先，长名称截断并可查看完整文本 |
| 动效 | 仅批次出现或层级切换的短暂过渡（约 120–180 ms），交互繁忙或减少动态效果设置下关闭；没有全库呼吸、漂移、闪烁 |

节点、边与标签的样式规则由同一处定义，局部和全库不再分别凭各自引擎默认值生成效果。颜色不是唯一识别手段，必须保留类型名称、图例与选择轮廓；焦点与按钮状态支持键盘操作。

## 5. CPU 性能与加载设计

### 5.1 绘图成本受当前画面限制

新的目标路径为分层 **Canvas 2D CPU**，局部与全库使用同一套绘图规则。底层为缓存底图/图块，中层为当前真实节点与关系，上层为名称、选中和路径。三层按脏区或数据/相机变化重绘，空闲时停止持续 rAF。

主线程不保留并逐帧处理 30 万完整业务对象。后台 Worker 保管紧凑坐标、ID/类型索引和可见候选；详情按需读取。主线程只接收有上限的当前视图数据。CPU 索引在视口和拾取时查询网格/树候选，禁止每次 hover、空白点击遍历全部节点或关系。

Worker 的解码、索引、布局同样按有界小任务执行，批次内部定期检查取消/世代；优先处理视口与拾取请求，再处理后台构建。原型以约 4–8 ms 工作片为起点，处理完即让出任务队列；不把一个几十秒的同步过程简单搬进 Worker 后视作响应问题已经解决。

原型起点为普通概览约 1,000 个精细实体、约 2,000–3,000 条精细关系、约 80 个名称；选中/路径占用固定优先预算。根据帧耗时逐步增减，后台数据完整性不受这些显示预算影响。超高阶实体的关联关系须分页或分组、显示总数和当前显示量，悬停也不能绕过预算。

平移/缩放进行中优先变换已缓存图层，减少名称与低优先关系；停止后补充高清图块及标签。节点拖动仅更新该节点与当前可见关联边，不触发全图布局。避免随 DPR 无上限放大软件 Canvas，清晰度档位与像素预算需在原型实测。

### 5.2 数据完整性与传输

保留现有图会话的归属、范围、资格、水位、布局版本、游标、去重及取消约束。首批关系必须带同一会话内合格的实体端点；后续补全孤立实体。不能为了加速删除权限或版本检查。

网络块大小与精细画面新增数量分别控制：支持的实体/关系分页可增大，connected 现有上限需保持兼容；不把单个 300 MiB JSON 或巨大 `postMessage` 当成高效快照。全量索引/快照采用带块清单的紧凑二进制、字符串字典及坐标数组，Worker 解码，尽量转移缓冲所有权；初始化与上传避免每批复制累计全部数据。

完整概览覆盖全部合格实体（含孤立实体），可通过聚合/图块表达。其 manifest 带总量、水位与块校验信息；只有完整索引所需块全部校验、ID 去重与端点检查通过，才显示“完整索引就绪”。实体身份、坐标、类型与关系端点属于索引，完整属性和证据正文属于按需详情；完整索引就绪不要求先下载全部详情。详细块的累计读取量和当前本机缓存量分别统计；只有清单要求的详细块都在本机且已校验，才可标记“详细数据缓存完整”，淘汰任何必需块后撤销该状态。不以抽样数、图块存在或下载字节数代替完整性。

聚合统计同时覆盖全部合格真实关系。实体按互斥主类型组归属一次，未分类实体单列，父子类继承不造成重复计数；各组成员数之和等于唯一实体总数。每条真实关系按 ID 只计一次，使用“关系类型、源组、目标组”归类；反方向分别统计，自环与组内关系计入内部关系，跨组关系计入对应有向组对，平行关系保留真实条数。全部聚合关系数之和须与 manifest 真实关系总数相等，不能只汇总绘图预算内的边。

全库实体定位通过当前范围的服务端实体选择/精确记录查询实现，不依赖实体恰好在浏览器已加载列表内。定位后按同会话版本加载并展开该实体；版本已变时提示刷新，不能把新旧水位混合。

路径循迹针对“当前展开的真实子图”，包括该探索子图中视口外的实体，但不把后台全库紧凑索引或聚合层自动当作可搜索范围。入口及结果明确标注“当前展开子图”；搜索在 Worker 内可取消执行。聚合组与聚合边不能作为真实路径证据。未发现路径时明确说明当前范围，可继续展开；本设计不新增未验证的全库多跳求解器。

### 5.3 缓存与再次进入

- 同页面切换优先复用当前会话、索引、位置及已有绘图资源，避免重复请求和布局。
- 服务端保留版本化概览、块索引、坐标与图块；初次生成与用户打开画面解耦。PostgreSQL 仍是权威存储，快照和图块都是可重建缓存，不新增业务事实存储。
- 浏览器用 IndexedDB 按块保存已经取得的数据与概览。重启后先校验用户、项目、范围、策略、水位、布局与格式版本，优先恢复小概览，再在后台读取所需索引块；不再先反序列化几百 MiB 完整 JS 对象才能显示。
- 缓存先通过当前权威权限检查才可显示，校验失败不展示旧内容；详情与编辑仍走真实接口。退出、换用户以及权限范围缩小时撤销活动视图和内存引用，持久块按用户隔离并清理。
- 配额不足、缓存被浏览器清理或单块损坏时，丢弃对应块并从同一有效快照重新获取。使用体积上限及最近使用淘汰，不使缓存无限增长。

## 6. 状态与异常反馈

底栏明确区分：全库实体/关系总量、概览覆盖、已加载详细数据、当前绘制实体/关系及标签数。默认简洁呈现，技术诊断数据收进展开项；用户主流程不显示 shader、缓冲、图块坐标等实现细节。

状态依次可为“读取范围 → 读取首批 → 初步概览就绪 → 正在细化 → 已暂停 / 达到当前显示预算 → 完整概览就绪 → 完整索引就绪”。详细数据累计读取和当前缓存完整性另行标注；总量尚未取得时显示“统计中”。自动任务结束只停止加载指示，不擅自标记全部数据完成。

- 网络失败：保留同快照下已经校验的画面，提示重试；重试不重复加入相同 ID。
- 会话过期或水位变化：停止追加，明确提示刷新；保留旧画面只读且标明旧版本，当前权限失效则立即隐藏。
- 项目、用户、权限策略或已应用范围改变：取消在途请求、Worker 任务和旧选择；新世代才能落地。
- 范围为空：显示空结果及调整范围入口，不伪造小图；存在实体但没有关系时仍显示真实孤立实体。
- 图块准备失败：保留标明抽样范围的初步小图和局部探索，不宣称完整概览已完成。

## 7. 实现时的职责划分

保持原生 JS/CSS，无 npm 工程或新前端框架。只围绕这一条图谱浏览流程划分模块：

| 模块 | 负责的行为 | 对调用方提供的结果 |
|---|---|---|
| 图谱会话与快照 | 权威上下文、代表性首批、块清单、游标、聚合和细节读取 | 同一水位的合法数据与可验证状态 |
| 加载与缓存协调 | 背压、分批、取消、重试、恢复、缓存淘汰 | 首图、后续数据增量、加载状态 |
| Worker 索引与视图规划 | 紧凑数据、空间查询、细节层级、标签候选与拾取候选 | 有界的可见集合与真实身份 |
| CPU 绘图 | 图层、相机、有限节点/关系/名称、命中与选择反馈 | 一致的局部/概览画面 |
| 工作区控件 | 工具栏、详情/循迹/设置、进度、焦点 | 用户操作映射及可读状态 |

先让 CPU 绘图、加载器与视图状态形成可独立验证的路径，再接现有真实详情、证据、来源、历史与编辑入口；不在每个 UI 控件里各自处理缓存和权限。

## 8. 分阶段交付与验收

### 第一阶段：可用且一致的小图

先交付统一工具栏、右侧详情与循迹、独立本体扩展按钮、统一类型色/标签规则、代表性首图、少量自动批次、暂停/继续，以及稳定位置和有界 CPU 渲染。此阶段只宣称小图交互可用，不宣称 30 万全库方案已经通过。

### 第二阶段：30 万规模的概览与恢复

交付完整范围的聚合/底图、快照分块、空间索引、视口细化、IndexedDB 小概览优先恢复和全库实体定位。先验证 CPU 图块路径及深度缩放后的清晰度，再接入产品；不能用一张模糊位图替代真实实体探索。

### 第三阶段：完整验收

以下是拟定门槛，需由测试结果证明，尚未视为已达标：

- 固定纯 CPU 软件渲染环境及目标机器；以 30 万实体 / 60 万关系、30 万 / 150 万关系分别测试。记录软件渲染证据、画面与真实鼠标操作，不用模型坐标变化代替屏幕变化。
- 合成本机可控服务下，首次可操作小图 P95 ≤3 s，已有概览缓存且权威校验成功后的可操作首图 P95 ≤1.5 s。真实服务另计范围查询/网络耗时，必须报告整体时间与等待快照构建的时间。
- 在两档 30 万实体规模中分别验证完整范围的终态，不以首图门槛代替容量验收：已有服务端快照时，从进入页面到**完整概览就绪 P95 ≤10 s、完整紧凑索引就绪 P95 ≤30 s**；上述终态必须同时通过全实体覆盖、全关系聚合计数、索引块/ID/端点及首批外随机定位检查。
- 没有服务端快照时，后台首次生成概览、紧凑索引和最低概览层图块的预算为 **180 s**（不做全图力导向，深层图块按需生成）；页面仍须先显示小图并可交互。生成完成后，浏览器恢复索引的预算仍为 30 s，因此初次完整索引端到端预算为 210 s，期间持续公开构建与读取状态。此为目标机器上的待验证门槛，不是已测承诺；同时记录生成时间、浏览器等待、CPU 和峰值内存，不能只报快照命中路径。原型若无法满足，须在产品接入前调整方案与门槛供用户审阅，不能默默省略终态。
- 连续拖动、缩放帧间隔 P95 ≤33 ms；实体命中、关系命中、空白点击的视觉反馈 P95 ≤200 ms。详情接口读取单独计时，不用直接节点命中代替稀疏边/空白拾取。
- 加载继续进行时仍满足交互门槛；取消后不落地旧批次；增加数据不跳相机、不重排已固定实体、不丢失选择与路径。
- 验证首图的类型覆盖、普通节点/桥接/孤立实体，检查真实关系端点；对高阶实体、密集关系、自环、同点关系、长名称、海量类型分别补测。
- 验证全库总量、概览覆盖、详细读取量与当前绘制量分别正确；随机定位到首批外的真实实体，并核对 ID、范围、版本与来源。完整索引/详细数据状态必须逐块核对，非只查 HUD。
- 验证水位、布局、范围、项目、用户、策略、撤权、权威校验失败及块损坏；新用户看不到旧缓存；真正关闭并重启浏览器测试恢复。
- 30 分钟探索、反复切换与开关侧栏后无持续内存增长。原型暂以单图活动工作集 JS heap ≤400 MiB 为预算起点，浏览器总 RSS 另测并固定上限；超过预算则减少活动块、拒绝无界精细绘制，不能删掉权威数据。
- 在常见桌面宽度及窄屏验证工具栏齐全、`+ / − / 适应画布` 左对齐、关闭按钮可见、侧栏不覆盖工具；对侧栏开关及窗口 resize 验证实际相机锚点、适应范围、32 px 留白与真实命中位置；局部/概览类型色一致，名称可读，聚合对象与真实实体可区分。

测试失败先回到原型或缩小交付范围，不将硬件加速结果用于纯 CPU 验收。此设计不承诺在用户确认方案前替换现有生产绘图器。

## 9. 与现有实现和历史设计的关系

新的默认显示策略用“逐步覆盖完整范围、按层级显示”替代“自动继续后全部精细对象同时进画布”。详细数据仍可按块继续读取，但不会强制全部进入主线程对象或同帧绘制。浏览器画布不再被当成唯一全量数据容器；界面始终公开当前抽样/聚合状态。历史设计中依赖 WebGL 或 GPU 的性能假设不适用于用户随后明确的 CPU 限制。
