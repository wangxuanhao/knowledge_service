# 原件存储与资料库图文阅读设计

日期：2026-10-28。用户已确认保留原件，并授权实施此前讨论的整体方案。

## 目标与现状

资料库默认按文章顺序展示正文、表格和图片，支持 PDF、DOCX、Markdown（附件包、内嵌图和可访问的外链图）以及现有 TXT/HTML 输入。原件保留用于下载、重新解析和核对；网页阅读以固定版本的解析正文和图片为依据。

当前业务文件仅存本地 data/sources；现有 MinIO 供 Milvus 使用。PG 已有 source_document_versions、parsed_blocks、source_assets、OCR 及证据映射；资料详情默认 textContent，独立 SourceReader 才渲染图文。PDF/DOCX 的解析返回值没有保存图片，队列还长期保留 BYTEA。

## 一、对象存储

- 沿用 SourceObjectStore 的内容寻址、SHA-256 和不可变键 xx/<hash>。增加 S3/MinIO adapter 与环境工厂；local 保留作密闭测试和离线迁移来源，生产显式切换 s3，连接失败不得静默回落本地。
- 复用 MinIO 实例，业务 bucket 使用 knowledge-sources，与 Milvus bucket 隔离；业务账号仅有该 bucket 的必要权限。凭据不得进入代码、日志、报告或浏览器。
- 后端继续使用项目鉴权的 source/asset 接口；图片以授权 fetch/blob 加载，浏览器不持有 S3 凭据。读写验证 SHA-256，不能把 multipart ETag 当文件哈希。
- 上传先固化原件对象，再提交 source_objects 和队列引用；队列新增 upload_object_id，旧 content BYTEA 可空并保留兼容读。新上传不把文件内容长期写入 PG。GC 同时保护版本、附件与队列引用。
- 写对象与 DB 提交不是跨系统事务：失败不得发布虚假成功；迁移/孤儿回收使用引用检查、校验与宽限期。首版不自动删除未知对象。
- 提供显式迁移命令：默认只核查；apply 复制本地已登记原件和图片到业务 bucket，逐个校验大小和 SHA-256，补齐历史队列引用，生成不含密钥的清单。切换前要求所有引用对象可读取；校验失败不切换。保留本地回退副本，不自动删除。

## 二、图文解析

- ParsedDocument 在 text/metadata 之外携带提取资产；格式适配统一生成按顺序的 Markdown/正文块及稳定图片引用，再复用现有 Markdown blocks、HTML 清理和证据映射。
- PDF/DOCX 通过真实 DoclingDocument 提取图片、图注及可获得的页码/区域信息，按文档阅读顺序回填图片标记；不只保留 full_text。PDF 扫描页在需要时保留页面图作为阅读资产。失败显式记录，不宣称完整保真。
- 图片资产保存 bytes/MIME、相对引用、尺寸和来源信息；资产原数据进入对象存储，PG 保存关系与来源元数据。新增字段通过编号迁移，不修改旧迁移校验和。
- Markdown ZIP 使用现有安全包读取；相对图缺附件明确缺图。内嵌 Base64 图固化。可公开访问的 HTTP(S) 外链在导入时下载为固定资产：限制大小、超时、重定向和图片类型；每跳验证 URL 与地址，拒绝回环/内网/本机/云元数据地址，避免把服务端变成内网代理。不下载需要用户登录或失效的链接，失败保存可见状态。
- 不执行输入 HTML/脚本；以清理后的 HTML 和授权图片接口输出。图片状态与 OCR 状态分离：图片可读即能显示，不因无文字配图或 OCR 失败而消失。
- 阅读可用与知识抽取完成独立。documents 模式的无文字配图/OCR 失败不阻止文本和图片入库，保留 warning 与重试入口；ontology/discovery 等知识抽取模式仍严格执行既有 OCR 质量门，禁止将失败输出当可靠知识。
- 检索文本可以包含成功 OCR 内容，但文章按原位置渲染图片；不拿追加在末尾的 OCR 文本代替图文版式。
- 重新解析创建新来源版本，既有断言与切片保持原固定版本。不自动批量重写历史证据；提供显式历史补处理入口或复用整份重新处理。

## 三、阅读界面

- 保留列表和详情抽屉结构。资料有固定来源版本时默认显示图文正文；无来源版本的旧资料清楚回退到已保存文本。
- 资料详情与独立 SourceReader 复用安全图文装载模块；统一授权图片加载、失败提示、延迟加载、图片放大与 object URL 回收。
- 保留下载原件与固定版本证据定位入口；解析文本、处理记录、提取知识和修订记录继续可访问。首版聚焦文章式阅读，PDF 原版内嵌预览为可选增强，不阻塞图文交付。
- 保持关闭/重开、切资料、切项目、切页签的请求失效保护，防止旧请求覆盖新文档或泄漏图片；桌面和手机内容均不得横向溢出。
- 改动静态资源同步更新 index.html 的版本号和相关契约断言。

## 验收

1. 本地与 S3 adapter 同一协议：流式上传、去重、校验、缺失、拒绝非法键、受引用保护删除；真实 MinIO 原件/图片上传、读取和下载。
2. 新上传队列没有 BYTEA 原件，租约/重试/ZIP/来源版本不退化；旧队列兼容，迁移后可重新处理。
3. 真实生成的带图 DOCX、PDF，加上 Markdown ZIP/Base64/公开外链输入，形成文字—图片—文字的有序阅读结果；缺图失败有明确状态。
4. documents 模式配图无文字或 OCR 失败仍可读；抽取模式不放宽知识质量门；旧固定版本证据仍能定位。
5. 前端在 1440/768/390px 验证图文、放大、失败、切项目/页签/关闭时的异步和 Blob 生命周期；跨项目素材访问受既有鉴权拒绝。
6. 单一 pytest 会话运行相关后端/迁移/权限回归；Node 契约另跑；真实解析和 MinIO smoke 单独记录，不用 mock 结果宣称真实链路通过。

## 部署顺序

保存基线 → 测试与实现 → 建业务 bucket/账号 → 应用编号迁移 → 核查并复制旧对象与队列原件 → 逐对象校验 → 设置显式 S3 配置 → 重启后端 → 验证固定原件、图文阅读及来源定位。操作不删除原本地目录、不改 Milvus bucket、不重建现有索引。
