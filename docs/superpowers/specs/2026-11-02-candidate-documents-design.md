# 按资料核对候选：统一入口与数量说明

用户已批准统一右侧宽抽屉、直白说明和按资料折叠，并要求直接说清几份资料、多少条候选内容需要核对。本次在现有 checkout 上保留全部已有改动；只切任务分支，不提交、不操作真实业务候选。

## 呈现

本体建模侧栏使用“从资料候选补充本体”，主要句式为“来自 X 份资料，共 N 条候选内容待核对”。N 为当前项目真正 pending 的正常候选数，X 为这些候选对应的不同资料数，不包含异常、已加入草案、已批准或已入库内容。无资料数时显示“资料数量待核对”，不能伪造 0。说明候选包括实体、关系和属性；选择、预览、加入草案、审核发布按实际阶段表达。本体建模各重复入口按钮统一使用“按资料核对候选”；资料库和批次原入口保留“本批次”等范围提示，打开后使用同一抽屉和标题。底栏及有正式本体后的侧栏同步，消除“将生成多少类型”的确定性承诺和退役按钮名称。

本体、资料库、批次和任务入口均复用现有 WorkspaceDrawers 与 OntologyIntake，以右侧宽抽屉打开。读取、选择、预览、提交进度和回执保持抽屉位置；桌面宽度兼顾资料列表和候选详情，小屏全宽。不改变各入口的真实查询范围、确认及幂等守卫。

## 资料目录与候选

inventory 从同一读取快照的完整、已核验范围返回轻量资料目录：资料 ID、名称、候选总数、可核对数和已加入草案数，之后再对候选分页。可核对的 inventory 数与现有列表行为一致（包括明确可复用的已入库关联实体）；与侧栏只计新 pending 的口径通过依赖说明区分。尚未读取候选时也显示资料标题和可核对数。标题可展开/收起；多资料初次默认全部收起，单资料默认展开，提供全部展开/收起。

点击未加载资料按需读取该资料的第一页，不静默加载全项目。每组提供“继续读取本资料”并显示已加载/总数；原全局分页仍可用。按资料请求保留 batch/run 范围，不能扩大范围；candidateIds 入口只展示准确候选及允许的依赖，不采用未经裁剪的全项目资料目录。混合全局/资料分页按候选 ID 去重，资料读取不推进全局 offset，所有操作保留显式选择与映射。

每份资料标题显示“待核对 N 条 · 已选 M 条”（切换状态时匹配所选状态，必要时显示已加载数量）。折叠不改变选择、映射或当前候选详情。整组选择只作用于已读取且匹配筛选的可选候选，明确标注“选择本资料已加载候选”，不暗中选择未读条目。原文证据和返回来源全文入口保留。按种类/建议类型筛选只针对已读内容，清晰提示；资料筛选可使用完整目录。

## 状态与错误

展开状态隔离于项目、来源范围和账号，关闭重开可恢复，同范围重读应更新服务端数量。延迟响应不得污染切换项目、关闭后或不同范围的工作区。读取资料失败保持已有选择，提供重试，不修改草案。未知提交结果恢复优先，禁止自动提交。加载不应把所有资料改成展开，也不能改变已经明确设置的折叠偏好。
