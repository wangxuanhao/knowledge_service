# 工作流性能优化设计

用户已批准按 `docs/research/2026-11-03-workflow-performance-audit.md` 的诊断优化。范围是减少数据库往返和重复图计算，保持发布、候选确认、审核、正式写入及融合的业务契约。

## 方案选择

采用批量持久化与请求内数据复用：它直接处理已经实测的瓶颈，不改变确认/审核/发布的含义。延长前端超时只改变等待体验，不解决重复工作；直接移除来源校验、证据或全表锁会改变正确性，本轮不采用。异步索引和项目级并发协议需要独立验证，本轮保持现行投影完成和锁语义，不对它们宣称已优化。

## 设计与不变量

1. **发布溯源边**：同一活动先验证完整逻辑边集合、严格 JSON payload 与终态冻结规则，然后按有界批次 INSERT。使用既有事务与唯一约束，保留跨项目 FK、ID 冲突、重放身份与失败回滚。不得减少证据边、使用忽略冲突掩盖不同 payload，或用改变审计内容换取速度。
2. **草案编译**：明确选择的一批建议在同一请求内复用本体工作图、正式记录与影响索引；逐项按原顺序生成相同操作和证据、风险、依赖。保留通用命令路径的手工/恢复/删除语义。操作构建结果需与原逐条编译路径等价，最后仍执行整图校验、来源与修订/预演指纹检查。
3. **审核来源读取**：project-scoped 批量读取断言，在一次一致性检查内按 ID 去重；按原来源顺序核对每个冻结快照。缺失/撤回/变化继续阻断。缓存仅在当前调用/一致性快照中存活，不越过事务边界，也不省略最终并发守卫。
4. **共享写入收益**：上述基础设施若被正式写入或融合复用，验证结果相同；不顺带改写并发锁协议或索引一致性承诺。

兼容细节：旧路径的影响明细顺序来自 Turtle 序列化/解析。快速路径需复用相同的 subject/predicate 排序，避免改变普通操作指纹。目标存在匿名节点入向引用时，保留有界于这些复杂命令的旧图复制路径与每请求记录快照；匿名节点的解析身份不稳定，不以强制统一其身份换取速度。此类请求不承诺解析次数与建议数无关，另以回归验证等价含义与来源/回滚；本轮同规模性能样本无此类匿名约束。

来源预读取也需保持异常优先级：历史运行允许存有格式异常的 `assertion_snapshots` 扩展字段。只对容器、条目和断言 ID 形状满足既有正常契约的数据批量读取；资格检查本身不抛异常，异常形状沿用原逐条检查路径，在原状态/资料/断言检查位置报错。不得因提前提取后续 ID，掩盖前一运行已失效的错误，也不得把异常数据当作通过。

## 验证

先补会暴露线性 SQL/全图重建问题的回归，并验证失败，再实现。覆盖严格 payload（包括 true 与 1）、逻辑去重、不同 ID 的幂等重放、主键碰撞、跨项目隔离、终态不可追加、事务回滚，以及候选来源变化、选择子集、多次加入与依赖复用。

必须包含两种反例：无效的中间操作前缀即使最终图可成立也仍拒绝；预检查通过后、最终写入守卫前发生的来源/修订变化仍拒绝并完整回滚。性能断言使用 SQL/解析/读取次数，不依赖机器秒数；溯源测试覆盖 1、100 与跨 1000 条的规模，图编译测试覆盖递增建议数量，来源读取覆盖跨批边界与多个运行共享断言。

复用匿名同规模拓扑（2份资料、154条唯一候选、83定义、249操作、100+77两批/23复用），在独立临时 PostgreSQL 库测量相同阶段，核对事实、断言、证据、回执和融合撤销。计时比较使用原样保留的基线；结果为同机诊断观测，不作为吞吐/P95或真实 LLM/向量投递认证。只有一个 pytest 会话，测试与基准不并行；不操作真实项目数据。

## 工作区边界

全量回归暴露既有API分层违约时，按现有ApplicationData门面封装数据读取，保持API返回、异常类型、鉴权、读取顺序、事务与任务入队语义。只移动访问接缝，不改变索引状态判定或元数据聚合。本轮另将旧测试对已退役私有方法/编码器接缝/索引准备的假设对齐当前契约，保留原业务断言并独立审查，不能通过放宽业务守卫迁就测试。

使用当前 checkout 的 `perf/workflow-batching-20261103` 分支，不创建环境或安装依赖，不提交、推送或覆盖现有三处前端未提交修改。后端修改验证完成后检查本地服务是否空闲；若安全重启，沿用现有配置与入口并核对健康，不执行真实业务写入。
