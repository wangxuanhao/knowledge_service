# 搜索与图谱页面重排设计提案

日期：2026-11-05。状态：用户已选择“图谱优先”并授权实现、验证后合并到本地 master；布局、自动概览、集成及夹具代码审查均已通过，2026-11-06 完成功能验收，待 Git 集成。

## 要解决的问题

用户反馈：顶部“筛选 / 基于此范围提问”等区域占用过多；图谱较小；点击“在图谱查看”后详情侧栏扩大，但图谱仍然局促；首次进入没有可见知识。

改造前的证据：`graph-surface.css` 将画布固定为 `clamp(280px,calc(100dvh - 550px),680px)`；`workspace.css` 在打开详情后保留检索结果、图谱、详情三列；`selectEntityDetail/openKnowledgeRecord` 可以只更新检查器，不负责确保目标出现在图谱中；默认局部模式依赖先选择实体，全量模式需要点击加载。

## 方案选择

推荐“图谱优先”：一行顶部操作 + 占据剩余空间的图谱 + 可收起的单个侧栏。结果和详情使用同一侧栏切换，默认侧栏关闭。

另提供“检索优先”和“沉浸画布”两种预览。前者固定结果栏，便于连续比较证据；后者收起导航、将工具浮在画布上，适合长时间看图。三版使用相同的示例知识和页面状态，便于比较空间分配。

设计阶段的预览文件：`.benchmarks/graph-workspace-design/prototype.html`。启动：`D:/anaconda/envs/llm_model/python.exe .benchmarks/graph-workspace-design/serve.py`。只使用标明的示例数据，内存状态，不连接业务 API；所有方案切换都在预览服务内。正式实现沿用原有图谱、范围和读取接口，并保留此前的图谱点击修复。

## 推荐布局

- 保留现有品牌、导航语言和颜色。标题、检索输入、筛选入口、基于范围提问放在同一条约56–64px的顶部栏。
- 筛选仅展开编辑器；默认只显示短范围摘要、条件数，不再永久占用独立整行。详细条件和系统修订时间仍可查看与修改；只有明确“应用”后生效。
- 主工作区占满顶部栏以下的可用高度。画布使用剩余空间，不再通过固定扣除550px计算高度。
- 常用视图操作放在一条约40–49px工具栏，类型、范围、加载情况放在约32–35px页脚。设置、扩展参数、历史明细按需展开。
- 桌面侧栏固定约300–320px、独立滚动；打开它不能使图谱高度变小，也不能因来源内容较长而继续变宽。结果与详情共用一个槽位，不形成三个常驻内容列。
- 在窄屏使用可收起底部面板，主图仍保留可操作区域。不能通过隐藏内容或极小字体挤压控件。

## 首次进入与默认内容

已选择项目时，在当前已应用范围内自动读取项目概览；展示真实的已发布实体和关系。图谱读取沿用 PostgreSQL 图谱会话路径，不应额外要求检索索引就绪。未选择项目时展示明确的项目选择入口。

大项目默认仅加载一批，不自动遍历整个项目。建议使用现有 `SessionLoader`、每页200条：首批关系页最多包含200条关系及其至多400个端点实体；无关系时读取至多200个实体。只有完整清单满足至多200实体/400关系时，才允许在最多3个分页请求内补齐小图。否则停止自动读取，保留“继续加载 / 加载全部 / 取消”入口。

始终区分当前画面、已加载数量、完整范围总量。部分数据不得显示为“全量完成”；后续分页失败时保留已展示内容并标明不完整。

再次切回页面，如果已有同项目、同范围的有效探索视图，恢复它而不是重复读取或覆盖用户当前选择。项目、已应用筛选、本体范围或系统修订时点改变后重新核对范围；显式对象打开优先于默认概览。

## “在图谱查看”的行为

1. 保留项目、权限、已应用筛选、本体及双时态范围。
2. 目标已经在当前显示图中时，居中并高亮它；结果侧栏切到对象详情，不再增加一个侧栏。
3. 目标未加载时，在相同范围内读取有界邻域，再显示并聚焦目标，不能只打开详情而保留空画布。
4. 关系必须在图中显示正确主体和客体，并让两端都进入可视区域。范围排除端点时明确提示，不能私自放宽筛选或读取范围外节点。
5. 文档、切片等来源内容继续使用来源阅读能力，不伪装成实体节点。虚拟属性节点仍回到其所属实体和原记录身份。
6. 收起详情后释放宽度并重新适配画布；浏览或编辑详情不重置已加载图、范围和选中对象。

## 状态与并发约束

- 加载中：明确“正在读取当前范围”，可显示骨架，不展示伪造的知识。
- 当前筛选无结果：说明是范围内无知识，提供调整/清除筛选入口。
- 项目无已发布知识：提供资料库、构建任务或候选核对入口；有待发布候选时说明状态，不将其当作正式事实绘制。
- 读取失败：保留范围，提供重试；不能将失败显示为“没有知识”。
- 项目A→B→A、切换筛选、离开页面、手动取消后，旧请求不能重新填充画布。沿用现有 ticket/epoch、取消和资格检查。
- 默认加载不能覆盖从台账、来源、检索结果等入口传入的显式对象或历史上下文；保留现有 `suppressNextAutoGraph` 等优先级规则。
- “基于此范围提问”复制实际已应用条件，保持现有不兼容条件提示，不能以画面筛选代替权威范围，也不能暗中删除条件。
- 不扩大标签预算、常驻图层或大项目扫描；保留上一轮节点与关系的点击范围改进。

## 落地验收标准

- 1440×900和1366×768下，画布填充内容区剩余高度；打开对象详情前后，画布高度差不超过1px。
- 推荐桌面方案只有一个可见结果/详情侧栏；其宽度稳定，来源长内容独立滚动，不挤出画布。
- 320/390/768/1024/1440宽度无页面横向溢出；检索、筛选、提问、收起详情均可操作。
- 首次进入有知识项目可自动看到真实有界概览；0实体、只含孤立实体、大项目部分加载、失败、取消都具有正确状态。
- 从结果、台账和来源执行“在图谱查看”，必须能看到并聚焦正确对象，不接受只有详情变化的通过结果。
- 真实回归覆盖筛选及双时态传递、历史只读、项目切换竞争、默认加载与显式对象竞争、类型筛选、缩放拖拽、点击命中、来源阅读和权限。

本提案只覆盖本页面布局与进入/定位行为，不改权威事实、发布审核流程、搜索排名或索引门禁。实施遵循对应 implementation plan；预览代码不直接作为生产实现。

## 实施验收（2026-11-06）

- 紧凑顶部栏、剩余高度画布及单个可收起结果/详情面板已实现。桌面详情面板宽320px，1440×900下打开前后画布高度均为550px；窄屏使用底部面板与现有导航菜单。
- 首次进入读取真实有界概览；空范围、空项目、局部加载、失败及取消均有对应状态。从检索、台账及来源定位时保留精确实体/关系身份、修订与原始范围，普通画布检查不重建图。
- 前端契约958项、串行浏览器回归121项均通过；关系/节点像素在DPR1/1.25/2下通过。五组截图已检查；正常服务HTTP200，16个变更资源与本地文件一致，119个测试资产无哈希漂移。
- 未操作真实项目的审核、发布、写入或融合数据；本轮验收范围为前端页面与既有范围/历史接口的交互回归。
