# 平台规则资料包、图文阅读与视频 ASR 设计草案

日期为 2026-11-10。用户已授权实际接入 FunASR。本文记录现行实现及后续资料包扩展设计。

## 本轮实现范围

- 单独 MP4/WebM、Markdown 引用的本地视频及现有 ZIP 附件链路已接入。预览展示播放器，正式处理生成 ASR 文字。
- 本地 SenseVoiceSmall 与 FSMN-VAD 使用独立离线 CPU 子进程，语音段保存真实起止毫秒。原件进入 MinIO，运行记录、转写和片段映射进入 PostgreSQL。
- 原文播放采用鉴权 Blob，解析视图展示转写段，点击转写段可定位视频。首期上限为 25 MB、600 秒，MP4 使用 H.264/AAC，WebM 使用 VP8/VP9/AV1 与 Opus/Vorbis。
- 外链视频显示待固化状态，资料提交者通过包内本地视频提供离线字节。
- 下文 schema_version=2、声明附件、Range 与短时播放票据属于后续扩展。当前包继续使用根 manifest 的 Markdown documents 清单或自动发现 .md。

## 业务范围

- 资料默认保留全部历史，按平台、业务、适用对象与业务有效期筛选。
- 业务本体按平台规则建模，图片和视频通过资料媒体类型管理。
- 接入入口覆盖单独文件，以及 Markdown 与附件共同组成的资料包。
- 图片文字使用现有 OCR 能力。视频语音通过本地 FunASR 生成文字。
- 阅读端展示原始媒体，文本端展示供切片、检索与知识抽取使用的文字。
- 原文、解析任务和文字片段分别记录版本，重试、人工修订与模型更换均能追溯。

## 当前 ZIP 的真实行为

已核对 integrations/markdown_package.py 与 services/ingest_batches.py。

1. 上传入口支持 .zip。正式资料包使用普通、未加密 ZIP，现有打包脚本使用 ZIP_STORED。
2. 包内可以包含多级目录。路径使用正斜杠及相对路径，文件名支持 UTF-8。
3. 系统读取 ZIP 根目录的 manifest.json。
4. manifest 含 documents 时，按清单顺序读取所列 Markdown。path 为完整包内路径，title 与 metadata 会用于对应文档导入。
5. 缺少 manifest，或 manifest 缺少 documents 时，系统遍历包内所有 .md 并按路径排序。
6. 明确的空 documents 清单会导致包内无文档错误。清单中路径缺失、重复、格式错误会导致包校验失败。
7. 每份 MD 的本地图片引用相对该 MD 的目录解析。图片由正文实际引用关联，同包共享图片可复用。
8. manifest 位于额外外层目录时，当前读取器会走自动发现 MD 的路径。正式打包工具将 manifest 放在 ZIP 根目录，便于准确应用元数据。

当前可用结构如下。

```text
规则包.zip
├── manifest.json
└── 抖音电商/
    ├── 规则A.md
    ├── 规则B.md
    └── assets/
        └── example.png
```

当前可用 manifest 如下。

```json
{
  "documents": [
    {
      "path": "抖音电商/规则A.md",
      "title": "规则A",
      "metadata": {
        "rule_id": "rule-a",
        "source_url": "https://example.com/rules/rule-a",
        "collection_category_path": ["商家管理", "入驻资质"]
      }
    },
    {
      "path": "抖音电商/规则B.md"
    }
  ]
}
```

collection_category_path 是本方案建议的采集分类字段名。metadata 可以保存该字段，筛选控件及业务适用范围仍需按明确字段映射接线。平台、业务、适用对象使用现有 applicability 结构，当前由上传批次控件填写。

当前默认限制为单个上传对象 25,000,000 字节、单批 1,000 份文档、单批 1,000,000,000 字节。ZIP 限制为 5,000 个成员、解压总量 512 MiB、压缩比上限 200。打包脚本采用每包 200 份 MD、24,000,000 字节的默认值。管理员配置与服务返回能力为运行时依据。

## 当前预览修复

- 支持格式文案、扩展名与文件选择器均使用服务能力更新。
- “预览原文”与“预览切片”分别展示图文和分片结果，两者均支持包内文档选择与时间识别。上传拖放区在全部步骤持续可用。
- 图片预览复用 SourceContent 的图片加载、放大与资源清理能力，图片字节在选中文档的预览响应中按 SHA256 去重。
- 图片缺失、不可读及外链待固化分别展示。图片 OCR 与知识抽取在正式处理批次执行。
- 预览使用临时上传文件，响应结束后删除，正式资料和来源对象在提交处理时保存。
- 图文预览缓存有界，切换文档、失败重试和关闭窗口按预览会话校验结果归属。

## 多模态资料包的扩展契约

建议后续引入明确的 schema_version=2。旧包继续按当前 Markdown 规则处理，扩展包通过版本分派进入媒体解析器。未实现的版本应明确返回错误。版本校验与媒体识别在接入扩展包时同步上线。

下面是拟扩展格式，实施后可支持视频附件及独立媒体资料。

```text
规则资料包.zip
├── manifest.json
├── documents/
│   └── 规则说明.md
└── assets/
    ├── images/
    │   └── 场景示例.png
    └── videos/
        └── 规则讲解.mp4
```

```json
{
  "schema_version": 2,
  "documents": [
    {
      "path": "documents/规则说明.md",
      "media_type": "markdown",
      "title": "规则说明",
      "metadata": {
        "rule_id": "rule-a",
        "collection_category_path": ["规则解读"]
      },
      "attachments": [
        {"path": "assets/images/场景示例.png", "media_type": "image"},
        {"path": "assets/videos/规则讲解.mp4", "media_type": "video"}
      ]
    }
  ]
}
```

attachments.path 统一相对包根目录。正文中的图片或视频引用相对 MD 目录解析，规范化后必须匹配同一包内资产。重复引用只登记一次实际对象，并保留各处引用位置。声明与正文引用冲突时返回文档级校验问题。

独立图片或视频可作为 documents 的一项，path 指向该媒体文件，media_type 分别为 image 或 video。同一视频作为独立资料及 MD 附件时，来源版本分别关联，底层字节按 SHA256 复用。

建议正文视频支持以下两种写法。

```html
<video src="../assets/videos/规则讲解.mp4" controls></video>
```

```markdown
[观看规则讲解](../assets/videos/规则讲解.mp4)
```

对于 manifest 声明且正文缺少定位点的媒体，在该份资料的附件区展示。包校验展示选中文档、全部声明附件、未引用附件与未找到文件，便于上传前核对。

实际采集样本“天猫/规则解读_1-必读，新商入驻指南_20001170.md”含 Markdown 形式的 MP4 链接。采集与第二阶段打包工具需要增加视频链接识别及本地文件关联。离线播放所需视频字节应固化到本地对象存储，外链的可访问状态单独记录。

建议多模态格式将根 manifest 定为唯一清单。为兼容资源管理器整体压缩目录，可在仅有一个外层目录且只有一个候选 manifest 时归一化包根。存在多个候选 manifest 时要求用户选择，明确记录实际包根。此归一化随版本 2 接入。

## 媒体展示与解析职责

| 媒体 | 原文阅读与预览 | 解析文字 | 证据定位 |
| --- | --- | --- | --- |
| Markdown | 排版、表格、图片及关联视频 | 规范化正文 | 原文块、行号与字符位置 |
| 图片 | 原图、缩放与识别状态 | 现有 OCR 的可信文本 | 图片资产、OCR 运行和文字框坐标 |
| 视频 | 播放器、时长与转写状态 | ASR 的分段转写文字 | 视频资产、ASR 运行和起止毫秒 |

视频首期预览目标为 MP4 的 H.264/AAC 及浏览器可播放的 WebM。MOV/MKV 等接入支持与派生播放副本由后续解析器确定。原件与播放副本分别记录对象哈希，播放器使用可播放的副本。

视频大小、总时长、单任务音频长度、ZIP 展开量和任务并发各自设配置项，并通过能力接口返回。视频扩展入口与较大文件限额同步验证，参数根据模型和机器资源确定。

## 视频播放与上传前预览

资料页采用“原文媒体／解析文字”两个视角。原文媒体提供播放器，解析文字按时间分段显示，点击文字片段定位播放位置。转写进行中或模型未配置时，界面同时展示媒体就绪状态与文本处理状态。

已有图片通过鉴权 fetch 获取 Blob，原生 video 标签的分段读取需要独立设计。建议媒体服务支持 HTTP Range、206 与 Content-Range，通过 MinIO 范围读取流式返回。先用现有 Bearer 鉴权申请短时播放票据，票据绑定用户、项目、来源版本、资产与失效时间，播放器使用对应媒体地址。

视频上传前预览分为两种情况。

- 单独选择本地视频时，浏览器使用本地 File 的 object URL 播放，移除文件或关闭窗口时释放。
- ZIP 内视频通过受限预览会话暂存，服务返回包目录与媒体预览地址。按需展开选中的视频并缓存至该会话，播放器按 Range 读取。会话具有所有者、项目、TTL 与容量限制，清理时移除临时对象。

视频预览会话与正式来源版本分别管理。提交时校验原包与文件 SHA256，并复用已校验的暂存原件。正式提交和重试使用幂等键。多进程部署时，预览会话登记使用共享存储，接入路由和媒体读取共同校验会话所有者。

## OCR 与 ASR 处理链路

图片沿用来源版本、图片资产、ImageOCRService、OCR 质量回执与原文映射。独立图片上传由媒体解析器生成统一来源表示，随后调用现有 OCR 服务。

视频链路分为原件固化、媒体探测、音轨提取、ASR、转写审核、文本切片和知识抽取。

1. 原始视频进入 MinIO，来源版本登记媒体 MIME、时长、编码信息、来源 URL 与 SHA256。
2. 本地 ffprobe 探测视频，本地 ffmpeg 提取适合模型的音频。采样率与通道要求由适配器能力返回。
3. ASR 服务调用本地适配器，保存模型与配置指纹及分段转写。
4. 成功转写形成规范化处理正文。片段保留视频时间区间，并进入已有检索、抽取与审核流程。
5. 无音轨、无语音、模型未配置、识别失败与待核验分别记录。原件可播放状态和文字就绪状态独立展示。
6. OCR/ASR 原始结果、人工修订文本及被当前知识处理采用的版本分别保留，重跑模型产生新运行记录。

检索结果通过 source_version_id、asset_id、transcription_run_id、segment_id、start_ms、end_ms 关联视频。视频中的分钟秒数用于证据定位，规则的发布时间及业务有效期继续使用独立日期字段。

## FunASR 的预留接口

后续拟增加 integrations/asr.py 和 services/media_transcription.py，分别负责模型适配与业务运行编排。模型信息集中在系统配置中，manifest 提供媒体与来源字段。

```python
class ASRAdapter:
    def available(self) -> bool: ...
    def capabilities(self) -> dict: ...
    def transcribe(self, audio_path, *, language=None) -> dict: ...
```

capabilities 返回模型标识、版本、配置指纹、采样要求、语言、时间戳能力和设备信息。transcribe 返回全文及 segments。每段包含 text、start_ms、end_ms，可选 speaker 和 confidence。模型未提供的可选值保持空值。

建议的系统配置包括 KG_ASR_PROVIDER、KG_ASR_MODEL_DIR、KG_ASR_DEVICE、KG_ASR_CONCURRENCY。provider 的预留值为 none 与 funasr。运行时从已准备的本地权重与依赖加载模型，部署交付包含离线模型准备说明。

运行记录保存任务状态、提供者、模型指纹、语言、音频哈希、文本、警告和错误码。重试键由项目、来源音频哈希、模型指纹和参数组成。重复请求复用相同运行，同项目内多份资料可关联同一已校验的转写结果，人工修订建立独立版本。

## 存储与能力接口

MinIO 保存原始 ZIP、文档与媒体字节，并分别登记派生音频、播放副本的用途和引用。PostgreSQL 保存来源版本、资料范围、媒体属性、OCR/ASR 运行、文字片段、审核版本和知识证据。Milvus 保存可检索文本的投影。

资产增加 media_type 表达 image 或 video，kind 表达 local、external 等引用来源方式。新增转写运行与分段记录，复用现有来源对象、发布守卫和未引用对象回收机制。

后续能力接口按类型区分接入、预览和文字解析能力。例如 MP4 可上传且可播放，但 ASR 模型未配置时显示“等待配置语音识别”。服务返回支持的包版本、扩展名、媒体限额及 OCR/ASR 可用状态，页面据此显示格式、按钮与解析提示。

- 按统一适配器接入指定本地模型，核对中文、噪声、无语音、长视频和时间戳。
