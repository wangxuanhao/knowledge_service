# 类型纠正与合并设计

用户在前一轮调研方案基础上要求整合设计并优化能力。本次复用既有草案审核、不可变发布、重分类与撤销通道，不新增平行治理系统，不自动修改正常项目数据。

## 用户操作

- 名称/说明不准确：沿用术语标注编辑，保留 IRI。
- 个别实体分类错误：沿用知识编辑入口，保留实体 ID 和版本历史。
- 类型整体不合适：停用时可以明确选择同种类活动替代术语；说明发布后仍须在受控重分类里迁移旧知识。
- 两个实体类型重复：在类型详情选择目标类型，预览影响并确认加入草案；源类型停用并指向目标，不物理删除。已有实例不因类型合并而互相合并。

## 方案取舍

1. 推荐：将显式类型合并编译成既有原子操作，并保留发布后受控迁移。沿用现有版本与审核体系，避免引入新真值。
2. 只增加停用替代下拉框：实现较小，但结构引用仍需手工逐条修改，无法满足重复类型的完整操作。
3. 发布时自动全量迁移实例：结构和数据同时完成，但会改变既有默认不迁移约定，且大数据量事务、审核与撤销更复杂，本次不采用。

## 类型合并契约

仅支持 class → class（实体类型）；关系/属性继续支持停用替代，不在本次机械合并其约束。

新增 POST `/api/projects/{p}/ontology-drafts/{draft_id}/type-merge-preview`，body 为 expected_revision、source_iri、target_iri。读取当前工作草案，返回 source_iri、target_iri、expected_revision、preview_fingerprint、operations（动作、目标、before、after）、impact（受影响实例/关系计数）、warnings、can_merge；预览不增加变更操作、不修改实例。准备草案可沿用 ensureDraft，UI 应明确是准备草案而非迁移。

提交仍走 commands：`{action:'merge_class',target_iri:source_iri,replacement_iri:target_iri,preview_fingerprint,reason}`。服务器在同一工作事务内重新生成方案，检查修订和预览指纹；来源记录成员/版本变化使确认失效。缺少指纹、目标不合法、类型停用、自合并、错误种类、引入循环或无法支持的结构一律拒绝，不残留部分操作。

编译器应处理已支持的 incoming subClassOf、domain/range（含受支持 union）、SHACL class/targetClass 引用；目标吸收源的父类但去掉合并产生的直接自环，其他循环或结构不兼容应拒绝。目标保留原标签/说明，源标签可作目标 skos:altLabel；源定义保留并设置 deprecated 和 dcterms:isReplacedBy。遇到未知语义引用不得静默忽略，应阻止并列出原因。重写必须使用现有 canonical_turtle_diff/结构化原子操作通道，不允许绕过审核直接替换发布本体。

编译结果逐项审核；不承诺所有建议必须一起获批。最终活动依赖门禁阻止仅批准停用而留下活动引用的非法发布。只批准一部分结构调整时，界面不能声称合并已经完成。未发布候选仍按最终获批映射门禁处理，不静默重定向候选；提示重新核对候选映射。

审查补充：merge 编译结果必须在 append 前完整试应用并验证与目标图同构，不能落入普通 command 捕获错误后保存 blocked atoms 的路径。顺序应先移除阻塞/循环引用，再增加新引用，最后停用源。确认指纹包含草案 ID/revision、基线/当前本体 ID、有效图规范摘要、全部影响记录 ID/版本，避免计数相同但成员变化漏检。发布门禁需覆盖 sh:class、targetClass、支持的 union 引用。历史替代映射仅在当前术语缺失时回退；按知识来源版本之后的历史集合解析，多个不同目标明确判为歧义，不沿用“任选第一个”。

## 迁移整合

仍通过现有重分类 plan/preview/apply。增加安全的替代链解析：A→B→C 时，只有唯一、同种类、最终活动的 C 可作为迁移目标；循环、多目标、失效或跨种类链不可随意择一。预览和写入重新校验全体相关知识，保留实例 ID、正文、有效期和证据。源类型被停用但没有替代目标时展示明确的下一步，不把它误报成普通同名搬运。

## UI 和反馈

类型详情新增“合并到已有类型”区块，显式目标选择和原因、影响预览、确认加入草案；目标或原因/草案修订变化使预览失效，防重复点击和项目切换。停用区增加同种类活动替代目标（可不选），不选时清楚告知旧知识不会删除且没有自动迁移目标。

显示“加入草案 → 审核发布 → 预演迁移旧知识”的分阶段结果，链接/按钮复用受控迁移入口。不要向用户展示指纹、数据库字段等实现细节。新增前端契约测试并同步资产版本号。

## 验证

- 编译器：结构重写、保留源、标签不覆盖、循环/错误种类/未知引用拒绝。
- API/草案：预览只读、指纹/修订过期、原子写入、草案变更不改实例。
- 迁移：多跳替代、安全拒绝歧义/循环、保留 ID/历史、原有迁移与撤销回归。
- 前端：真实控制器或 DOM 契约验证先预览后确认、目标变动失效、项目变动失效、停用携带替代目标及无替代提示。
- Python 测试只开一个 pytest 进程；使用既有 llm_model 环境，不打印 .env。不发布用户真实草案，不迁移真实实体。
