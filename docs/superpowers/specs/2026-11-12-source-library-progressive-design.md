# 资料库递进检索设计

用户已批准“上一批命中资料的全部正文中继续检索”，完成后合入 master 并推送。

沿用单次 query/retrieval_mode，新增请求体 search_steps，表示此前按顺序应用的条件，每项 {query, retrieval_mode: keyword|semantic}。最多7个此前条件，加当前条件最多8步；每词1..2000字符。旧Scope请求兼容；document_id直接定位忽略链。

关键词此前条件由PG文档级SQL谓词累积，不能仅取已加载页或枚举全量文档ID。每个语义此前条件在当前资格范围内召回最多100片段，按资料去重后将这些资料ID加入下一步资格范围；下一步搜索其全部正文切片。保留项目/时态/适用性/本体/过滤范围及权限，禁止绕过父门禁。中间步骤忽略处理状态，最终统一筛状态；不静默降级，任一步不完整则最终不完整。完整条件链、语义中间结果版本与排名身份进入游标范围，变化拒绝旧游标；在一次快照中重放。最终响应附 bounded_by_semantic（链中存在语义步骤）及 complete；单次旧响应继续兼容。

页面新增“在结果中继续检索”、条件标签与“退回上一步”。点击继续进入待追加状态，清空输入但保留结果；提交才将上一查询冻结为此前条件。切模式保持原有即时搜索，在待追加状态的空输入不得丢失链。删除任意条件重放剩余链；退回删除最后一步；清空、引用定位、切项目清除全部链（清空保留模式，其余恢复关键词）。状态/范围/刷新/分页保持链。仅成功且仍对应当前请求的非空结果允许继续，失败/加载时禁用。缓存及过期请求身份含链。向量参与过的最终结果明确为召回范围内再检索，最终关键词不能显示全库精确匹配；片段安全文本渲染。手机换行，不增加横向溢出。
