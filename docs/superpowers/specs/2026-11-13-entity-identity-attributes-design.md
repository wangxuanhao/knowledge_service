# 跨文档实体身份、属性事实、图谱与检索设计

状态：用户已于 2026-11-13 确认实施；按同日实施计划分阶段验证。本文是目标设计，不代表所有功能已经实现。

## 目标与具体体验

两份文档中的同一个“美团平台”可以归到一个实体节点，文档各自的有效时间、适用范围、属性值和原文证据仍分别存在。用户不需要手动拆分文档或修改来源时间。明确的身份自动处理，身份不确定和事实冲突分别进入复核。历史重复数据由系统扫描、分组、预览，允许批量确认明确的组。

属性既支持金额、数量、布尔值等短值，也支持 TTL 声明的说明类长文本。图谱显示实例值与来源，不把属性定义误当作事实。关键词、语义、混合检索以及证据问答都纳入已经接受的属性；候选不混入正式知识结果。

## 设计前的代码证据

- `services/reconciliation.py` 与 `services/entity_resolution.py`：候选同时按类型、valid_from、valid_until、applicability 完全相等筛选，随后才做名称/别名及语义匹配。没有以时间区间交集做实体归并。
- `services/governance.py::_merge_inputs`：手工融合也要求时间及适用范围相等。直接删除这一检查会丢失现行范围语义。
- `services/service.py`：抽取 ID 带切片前缀，来源事实先存在，然后通过归并形成规范实体。关系和属性的正式事实键已经包括主体、谓词、具体值/客体、时间及适用范围。
- `services/formal_writes.py`：正式写入、断言接受、事实重定向和投影事件有既有原子计划；应复用该入口，禁止旁路改表或直接改索引。
- `repository/scoped_reads.py`：范围过滤与关系/属性端点资格依赖实体记录自己的时间和适用范围，必须一起改造，不能只放宽融合。
- `services/attribute_extraction.py`：可选抽取把本体属性定义传入模型，所有结果进审核；提示词偏向稳定标量并排除职责等内容，不足以支持已声明的描述型属性。
- `services/explorer.py::_entity_attributes` 与 `web/evidence-inspector.js`：已有实体→属性→多值结构及逐值表格，但缺少长文本阅读、逐值来源分页和清晰分组。虚拟属性节点不是正式实体。
- `domain/search_projection.py`、`repository/projection_inputs.py`、`services/projection_sync.py`：Milvus 构建和投影白名单没有 attribute。`services/retrieval.py` 和 `services/service.py::search` 也只定义 entity/relation/chunk 通道。仅在页面显示属性不足以让其被检索。
- `services/graph_sessions.py`：完整图按冻结范围和项目水位分页；属性展示必须按需、有界加载，不能把全部长文本塞进全量图清单。

## 方案选择

1. 放宽为时间区间重叠：改动小，但无交集的历史文档仍无法识别同一平台，且容易把事实时间误当身份。不可作为最终方案。
2. 规范实体身份与来源事实时间分离（采用）：保留单个规范 ID，每份来源支持独立保存时间、范围、状态和证据，统一改造查询资格、融合与投影。
3. 只在浏览器按名称折叠节点：无法修复属性挂接、检索、历史查询与证据归属，不采用。

## 一、身份与时间的契约

### 规范身份

规范实体 ID 继续使用现有 entity 记录 ID，保持图谱、关系端点和外部引用兼容，不另外制造一套用户需要管理的实体。新增内部的身份规则与来源支持读取模块，隐藏匹配、断言及时间资格细节。

身份判断至少包含项目、稳定类型 IRI、业务身份范围以及名称/别名或业务唯一键。文档发布日期、文档有效期与事实 applicability 不能默认成为长期对象的身份键；同名不是充分的身份凭据。

每个本体类支持两种明确的身份策略：

- `reference`：跨文档统一身份。平台、组织等在确认属于长期对象后使用；有已登记唯一键时优先按唯一键识别，否则必须在规则允许的身份范围内得到唯一且无冲突的名称/别名匹配。
- `scoped`：保留业务区间和身份范围作为区分条件，适用于不同批次事件、合同等。不同合同若有相同唯一合同编号，仍可通过强身份键识别为同一对象。

策略在本体类详情中配置并随发布版本固定。旧类缺少声明时保留现有保守策略；系统扫描会按类型展示“可启用跨文档身份”的建议，但不能根据中文类名暗中给所有事件套用同一规则。历史清理向导允许用户一次确认某类或某组的身份规则，后续导入复用，不要求每次手工合并。

如果同名同时匹配多个规范实体、有冲突的唯一标识、或类型不兼容，输出可复核候选和原因，不能取查询结果第一条。纯向量高分不能覆盖这些冲突。多个时间区间既不是必须合并的依据，也不是长期对象不能合并的依据。

身份候选选择、唯一性检查、来源支持添加和规范 ID 分配必须在正式写入的同一个锁定依赖快照中执行。预抽取的匹配只是建议，提交时重查；并发导入两个相同长期对象不能各自提交一个新规范身份。新增强身份键唯一索引与版本 CAS，按项目和声明的身份范围隔离；同名歧义不能通过给姓名建全局唯一索引来解决。

### 来源支持与业务时间

文档或切片中的每次提及仍是独立断言。其 payload 保存原始 valid_from、valid_until、applicability、原文位置与文档版本；批准或融合不改写原文时间。

规范长期实体记录不再继承“最新导入文档”的时间或范围。显式维护的实体存续期（如成立、注销）与文档适用时间使用不同字段，不能推测或互相覆盖。实体存续期未知不等于无限期有效。

关系、属性事实继续各自具有有效区间和适用范围，维持现有规范事实键。多个来源支持同一事实时合并支撑，不人为更改时间、数值或字面量。

### 范围可见性

统一资格模块用于列表、图谱、检索回填、证据、脑图和问答，禁止各入口单独猜测身份：

- 当前时间/范围查询：实体需要同一条有效来源支持同时满足时间、范围和接受状态；不能把文档 A 的时间与文档 B 的平台条件拼接成一条不存在的证据。
- 有效的关系/属性可以在查询内带出其已接受的规范实体端点，不能因规范实体曾来自另一份日期较早的文档而隐藏合法事实。
- 半开区间仍为 `[valid_from, valid_until)`；未知时间遵守 include_unknown。不把两个不连续区间取外包络填平中间空白。
- 手工实体的直接身份声明作为一种可审计的支持来源，不要求伪造文档。
- 历史 known_at 只使用当时已知的身份映射、事实修订和断言决定。之后的融合不能重写过去视图。
- 撤回来源会移除相应支持与相关事实资格；只剩被撤回来源的实体不能继续以正式知识出现。

实现上给断言支持增加事务维护、有索引的读取投影（支持实体 ID、断言 ID、文档版本、已知区间、有效区间、范围、撤回状态）。断言和历史事件仍是权威，投影可重建。必须有数据库迁移和旧数据回填，不依赖在 metadata 中永久累积无界来源数组。

## 二、新导入与已有数据的操作流程

### 新导入

1. 本体指导抽取，得到实体提及和事实候选。
2. 按已发布身份策略匹配规范实体；强键/唯一精确匹配自动归并，歧义进入身份复核。
3. 为每个提及保存来源支持，把关系端点及属性主体映射到规范 ID。
4. 属性值仍按治理规则审核，身份统一不等于属性值自动正确。
5. 原子写入事实、断言、映射、审计及投影事件。失败不产生半套身份重定向。

### 已有重复数据

入口沿用台账中“实体消歧与融合”，新增“扫描已有重复实体”。图谱发现同名节点时可跳转到该区域并预填候选，不复制一套合并逻辑。

扫描按类型、规范名、别名/唯一键和身份策略分组，并分页返回：组内实体、不同文档、现有时间范围、置信依据、推荐保留 ID、影响关系/属性数量、冲突及不能自动处理的原因。

界面分为“可确认的明确匹配”和“需要复核”。可以选中多个明确组，预览后一次确认；涉及唯一键冲突、含糊同名或单值属性冲突的组，不能默认勾选。名称查询只是找候选，不是执行合并。

预览展示真实变化：保留节点、停用节点、关系/属性端点迁移、保留的各来源时间、重复事实支撑归并、冲突值。预览有成员与版本指纹；数据变化后重新预览。批处理按组原子提交、逐组报告成功/失败，可重试，不以一个冲突阻塞所有无关组。

用户确认已有组后记住明确的身份决定/别名，在同一身份规则下指导后续导入。融合可审计、可撤销；撤销若遇后续写入依赖，先展示影响并遵循现有版本冲突策略，不能静默抹除后续资料。

不启动全项目历史数据自动合并。先发布新机制并提供扫描预览；实际清理由用户在上述入口确认。

## 三、属性事实与抽取

### 定义和值

属性定义仍来自发布 TTL（稳定 IRI、标签、说明、domain、range、SHACL 多值约束）。实例属性保留独立记录：主体 ID、属性 IRI、原生值、datatype、有效期、适用范围、来源断言与状态。定义只在帮助或类型说明里出现，不能作为已提取的实例值。

字符串值支持段落和换行，完整正文及证据在权威存储保留。不能把整个来源切片未经选择直接当作每个实体的属性；也不能把实体对象硬塞进字符串字段来绕过关系建模。

### 抽取开关与策略

保留现有 extract_attributes 布尔接口与默认关闭，不因导入 TTL 静默增加模型调用。上传设置展示本次发布包含多少属性以及“本体已定义属性，开启后按定义提取，结果先审核”的明确提示；仅文档模式仍禁用抽取。

开启后按属性定义、domain/range 和正文证据抽取。已声明的描述型字符串属性允许段落，不再被“职责等一律不是属性”的通用提示词覆盖。本体没有定义的内容保持保守候选治理，不能把任意长句自动批准为新属性。

候选值须有连续原文证据；跨切片丢失或不完整时标记诊断，不自行补全文字。按本体切片选择相关属性，显式记录截断/预算，不以固定每实体五项造成无提示丢失。属性编辑和审核使用多行输入，服务端长度及原生类型约束保持一致。

### 多值与冲突

- 同主体、谓词、相同 datatype/value、相同时间与范围：共用规范事实并增加独立支撑。
- 相同值在不连续时间内出现：阅读层可分组展示，但保留独立区间，不能改写成一个连续区间。
- 多值属性的不同值：分别显示，各自附来源、时间、范围和状态。
- 单值约束下，时间重叠且适用范围兼容的不同值才构成冲突；不重叠值作为历史版本共存。未知时间单列“时间待核”，不能被当作确定的永恒事实。
- 多段文字按原值分别保留；相似文本只可提示去重或摘要，不能自动融合为一条新事实。
- 身份已确定但属性有冲突时，冲突进入独立审核；不能为规避冲突而永久拆成两个实体。融合后不直接接受任何待审核值。

### 身份融合发现原先已接受值互相冲突时

采用“全部争议值退出确定事实，独立审核”的显式事务策略，不能沿用当前必须选择胜出值的合并接口来冒充已支持：

1. 预览列出冲突集合及隔离影响，用户确认身份融合时同时明确接受这些值进入冲突复核，而不是默认保留任一值。
2. 同一正式写入事务中完成主体重定向、冲突集合建立；该集合中涉及的已接受属性断言走现有 `accepted → contradicting` 事件，保留原始 payload、原文、原主体与历史映射。
3. 对应属性事实形成可审计的隔离修订，不作为当前确定属性参加普通图谱/索引/问答检索；冲突面板通过集合专用读取展示全部值与来源。撤销融合按事件恢复原主体和决定，不抹去原来的历史。
4. 冲突集合按规范实体、谓词、交叠时间/范围保存成员及状态，有数据库索引。图谱属性面板和问答在当前范围内独立读取此标记；即使候选不在正式检索通道，问答仍知道“该属性存在未解决冲突”，不能把无确定值解释为没有信息。
5. 为严格 SHACL 引入专用的 `identity_merge_with_review` 写入策略，只容许本次已确认隔离引起的、明确枚举且带 shape/predicate 的校验诊断（包括隔离后 minCount 缺失）。该实体显示“身份已统一，属性约束待复核”，不得声称整体 conforms；无关类型、端点、datatype、引用完整性失败仍中止事务，普通写入继续严格校验。
6. 属性审核明确接受某值并拒绝/取代其余值后，重新校验、创建正式事实与索引投影，关闭冲突集合。支持撤回及时间切分的决定也必须有完整审计。两个已接受值若不构成约束冲突则不隔离。

## 四、图谱、详情与脑图展示

主画布以规范实体和真实关系为主，节点可显示“属性 4 项 / 7 个值”等有界摘要，不在节点上堆长段落。

### 知识图谱是主要设计对象

完整图和局部图均保留多实体、多类型、交叉连接及环路的网络布局，不转换为实体为根的树。默认画布只显示真实实体与有方向的业务关系；选中实体高亮其直接关系，未选中网络适度弱化但不自动删除。局部探索的跳数和完整图分页继续沿用现有语义。

桌面布局为网络画布＋可收起的右侧实体详情栏；窄屏详情在画布下方或底部抽屉中展开。悬浮实体显示少量属性摘要及多值/冲突提示，触屏通过点击取得同样信息。点击实体后，侧栏的“属性”按定义分组、按事实值列出。长文本和逐值来源在侧栏展开，不放进悬浮提示。

明确取消“展开到图中”的设计：不画属性连接线，不创建属性分组节点、属性值节点或临时属性覆盖层。画布中的边只表示两个实体之间的真实关系。同一个“上海”字面量属于不同主体时，各自留在对应实体的属性面板，不能因此生成共享实体。属性定义只作侧栏帮助说明，不作为实例网络实体。

属性分组和多值列表有界分页加载；打开侧栏、切换属性、展开全文和查看来源均不重新布局关系网，保留相机及实体手工位置。全量图的 GPU 缓冲和清单只包含真实实体/关系，不为了显示属性增加渲染节点或边。

全量图与局部图共用“关系网络＋实体悬浮摘要＋点击属性侧栏”的交互，数据按当前范围获取。“转为脑图”仅为另一个入口，不是属性展示的唯一入口。示意交付以真实网络图谱为主，不能只用树形示意代表知识图谱。

### 共用的属性阅读与脑图行为

选中实体后使用同一范围的属性面板：按属性分组，显示具体值、短预览、有效期、适用范围、状态、文档数和支撑条数（文档数与出现次数分开计数）。长文本提供“展开全文/收起”；每个值有“查看来源”，分页展示文档标题、文档版本、原文引文及定位，不只显示一个总数。

属性阅读在侧栏中分为“属性分组 → 具体值 → 全文和逐值证据”，这不是画布上的三级树。合法多值、历史区间值、未解决冲突分别标注，冲突候选不能被当作普通已接受值。脑图也只用实体关系组成树，选中卡片后使用同样的属性阅读面板；不再给属性画分支。

### 冲突的发现与处理入口

悬浮摘要仅提示“存在冲突”，不放裁决按钮。图谱侧栏并列显示冲突值、有效期、适用范围、原文及来源，具备权限的用户可点击“处理冲突”，在保留图谱选中实体和相机的情况下打开统一知识审核抽屉，预定位到该冲突集合；只读用户仍可查看全部证据但不能提交。

该抽屉与台账“知识审核 → 属性事实”复用同一份状态、版本校验、服务端审核接口和操作记录，不能为图谱另建一套直接覆盖值的逻辑。首次展示不预选胜出值，提交必须有理由。当前“保留旧值/拒绝候选”“接受新值”保留；融合产生的多方冲突按集合裁决，并支持经明确审核把不同生效区间修正为不同历史事实。尚无法确认时保持待审核，不强迫选择。纯多值或互不重叠的历史值不进入冲突裁决。

处理完成后，重新获取实体属性、冲突数量与来源，并按投影状态更新图谱/检索的就绪提示；旧抽屉的陈旧版本提交必须拒绝。新事实写入、旧事实取代、审计和索引事件沿用正式写入事务。

完整图保留现有分批载入，属性在实体选中后加载；不能将所有属性/证据并入全图启动响应。局部图、完整图详情、检索结果和脑图选中节点复用属性面板与事实 ID。

身份信息与来源时间分开展示：实体卡显示规范名称、类型、别名及来源文档数；属性/关系各自显示有效期，不把某份文档日期标成平台的出生或消失时间。

## 五、检索与证据问答

新增正式 attribute 检索通道，支持关键词、语义、混合；默认纳入检索，并提供属性数量/类型控制，结果总预算仍有上限，不能让大量属性淹没实体和原文结果。

每条属性按其自身事实版本建立检索内容：主体显示名、属性标签/IRI、datatype 与具体值。查询标签、金额、状态或段落中的词均能命中。值不依赖人工填写的 text 才能被索引。属性名/主体名的变更须使依赖投影失效并重建或增量更新。

长文本以确定性的窗口和重叠片段索引，使用独立片段 ID，指回属性事实 ID/版本与值内偏移；完整值保留在 PG。检索按事实聚合去重，按属性/实体限制预算，返回匹配片段而非截断后永远无法命中的尾部。不得让多个片段占满 top-k。

属性事实按有效期、适用范围、接受状态和主体资格预过滤并由 PG 校验命中版本。实体索引不拼接全量属性，避免不同时间/范围的属性泄漏到同一实体向量。候选、冲突候选不混入正式属性通道。

跨来源身份的实体/关系向量资格采用逐支持上下文投影，不能继续用规范实体行上某份文档的时间做 Milvus 预过滤：每条投影带 canonical_record_id/version、support_context_id/version、完整关联的时间/范围和（长属性时）window_id；vector_id 包括这些标识。投影仅覆盖当前有效支持，原文决定和记录版本仍由 PG 校验。原生索引按单条上下文同时匹配时间和所有范围条件，禁止把多份来源的字段拆成互不关联的数组。

Milvus 分组召回按 canonical_record_id 去重（属性按事实/版本去重），采用可验证的 group-by 能力或有界排除已见规范 ID 的补召回；若达到预算仍不完整则返回明确的完整性状态，不声称全量 top-k。重新补召回时排除的是规范 ID 而不是单个向量窗口，避免一个长属性或多来源实体占满预算。原有规范行时间过滤不可在支持上下文合格后再次错误排除该实体。历史查询仍由 PG 按当时支持和身份图读取。

命中属性的结果明确显示“所属实体 → 属性名：命中值/片段”，点击定位实体详情对应值。问答上下文携带属性事实版本和原文断言，引用可追溯；事实值与原文证据分别标识，不把模型摘要当引文。未解决的单值冲突须明确呈现不确定性，不能悄悄选一个值回答。

历史 keyword 路径、召回评估、按平台检索、来源扩展和问答冻结快照同步支持 attribute。历史 semantic/hybrid 保持现有不支持策略，不能拿当前向量冒充历史结果。

Milvus 新索引使用新的投影能力/版本清单；旧索引没有属性能力时给出可操作的重建状态，不能返回“无属性结果”伪装完整成功。新索引在完整构建、对账、追平水位后切换，失败保留现有服务状态并说明降级范围。

## 六、迁移、安全与一致性

新增编号 SQL 迁移，纳入当前迁移器与应用只读版本检查。回填来源支持时利用 assertions、assertion_events 与 record_version_assertions，按历史决定构建已知时间，不靠 source_id 猜来源。回填可幂等复跑，有数量和缺失诊断。

已有 entity ID 与旧入口继续可解析；合并后的旧 ID 通过有历史时间的重定向定位。不得重用旧 ID 或按名字直接覆盖。来源支持撤回、属性更新、身份融合均经正式写入计划与事务/outbox。

Neo4j、Milvus、PG 列表/统计、全量图会话水位和检索快照同步处理身份变化。新读模型未就绪时明确阻止跨时间融合写入，不能使索引与权威记录各用一套规则。

开发验证使用现有 llm_model 环境和隔离测试库，不对业务库自动迁移、回填、批量融合或重建索引。上线时把迁移/回填、双读对账、索引重建、功能启用分成明确步骤，并给出回退方式。

## 七、实施顺序与验收

1. 身份策略、来源支持与统一资格读模型：先建立能保存多段时间而不泄漏范围的基础，再放宽长期对象归并。
2. 抽取/审核/手工融合/已有数据扫描：复用身份规则与事实写入事务，确保属性主体、关系端点及来源一起正确重定向。
3. 属性值与证据读取、长文本输入及图谱详情：当前范围内按值阅读，完整图有界按需加载。
4. 属性投影、检索和问答：加入通道、长文窗口、去重、引用与版本切换。
5. 集成验证与迁移说明：全部入口对账、真实性能检查和真实浏览器检查后交付。

核心验收场景：

- reference 类型的“美团平台”在重叠、不重叠以及未知文档时间下有唯一身份；来源时间不被扩大或丢失，范围仍分别生效。
- 两个同名但唯一标识不同的对象不会自动合并；事件/合同的 scoped 策略不会被名字或向量高分绕过。
- 同一支持同时满足时间/平台条件，不出现跨来源拼接资格；撤回与 known_at 读取不泄漏未来身份或已撤回事实。
- 同值多文档去重支撑，多值保留，单值时间重叠冲突可审核，身份归并不强行选值。
- 字符串属性保留换行和原始值；HTML 以纯文本转义；金额、布尔值与 datatype 不因展示或索引被改型。
- 只在属性 value 中出现的词，包括长段落尾部，可被关键词/语义/混合检索命中并定位原文；旧索引必须报告缺失能力。
- 多个长文窗口按事实去重，不占满检索预算；不同时间、平台、历史版本的值不混入同一结果或答案。
- 全量图计数与画布只含真实实体/关系；属性不增加节点或连线，悬浮摘要和侧栏有界，搜索、脑图、路径和导出不回归。
- 历史融合分组支持批量确认、版本漂移拒绝、逐组重试和可审计撤销；未确认不改业务数据。
