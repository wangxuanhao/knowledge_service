# 逐文件原件预览、后台解析与资源 ZIP 流程设计

状态：四步上传流程、后台准备任务、逐文件/批量配置与 API 已实现并通过专项回归。ZIP 仅承载一个 MD/HTML 主文档及相对资源，其他格式独立上传。全文 OCR/ASR 准确率与长文件容量仍需单独验收。

## 目标与边界

上传仅做暂存、轻量校验和重复检查，不自动启动全文解析。用户核对文件并完成逐文件或批量配置后，明确点击“开始解析”。后台生成可审核的正文与切片，用户再次确认才入库。耗时解析有持久任务和阶段反馈。文件选中、字节上传、解析完成、知识写入和检索就绪是不同状态。

ZIP 的常规入口不要求用户提供 `manifest.json`。一个 MD/HTML 主文档及其引用资源是一份资料，PDF、Word、视频作为独立资料分别上传。页面不提供 ZIP 内独立文档列表或切换器。后台仍必须检查包路径、解压大小和引用资源，这不属于批量遍历导入文档。

## 方案选择

| 方案 | 行为 | 取舍 |
| --- | --- | --- |
| 只把现有预览按钮移到文件行 | 点击后仍调用同步全文解析 | 改动少，但不能解决扫描 PDF、Word 和视频的长时间等待及重复解析 |
| 上传即解析 | 上传校验通过即消耗解析资源 | 启动早，但误传、重复文件与待调整配置会造成浪费，本次不采用 |
| 上传核对、配置、明确开始解析（推荐） | 上传暂存后配置，点击开始才启动后台解析 | 人工启动边界清楚，可先去重与确认配置，适合长任务 |

## 人工操作流程：四步

### 第一步：上传与核对文件

选择文件后上传至有归属和有效期的暂存区，只进行格式、大小、安全、主文档结构与重复检查；不调用全文 Docling/OCR/ASR，也不抽取知识。原件预览在每个文件行，拖放区只负责选择文件。

清单展示文件名、类型、大小、上传字节进度、校验状态、重复提示和原件预览/移除按钮。校验中的页数或时长仅在低成本取得时显示；不能为了取这些信息启动完整解析。ZIP 是一个 MD/HTML 主文档及其关联资源，不展示多文档浏览器，也不要求 manifest。

重复检查按实际内容哈希及有权限的项目范围进行，不能只看文件名。同内容已在当前清单中时提示已有文件；有可复用成功产物时显示“已有解析结果，可复用”；正在运行时提示现有任务。只有文件内容、解析配置与解析器/模型版本一致才复用解析。相同文件、不同适用范围不直接判为同一入库资料；解析复用与资料版本/入库去重是两个判断。

不支持的真实 .doc 在此说明当前支持缺口，不建议修改后缀。PDF/图片/视频原件预览独立于全文解析；DOCX 原版式预览依赖本地转换能力，未就绪时说明可下载原件，不能伪装为已支持。

点击“下一步：配置资料”仅切换步骤，不启动解析。上传或校验未完成的文件有明确提示，阻断项必须修复或移除；可明确选择只继续有效文件。

### 第二步：配置资料

同批允许不同平台和不同业务，无需用户预先按平台拆批。项目是整批的共同边界，文件所属平台、业务、受众、标题、文档时间为逐文件配置。表格摘要展示各文件最终值，行内“设置”打开该文件编辑；平台本身可以多选，但不能用整批多选替代逐文件归属。

勾选多份后显示“批量设置”，支持填写适用范围、时间、解析方式及切片参数。只提交勾选启用的字段，未启用字段保持原值；选择只填未设置项或覆盖所选文件，覆盖前展示影响数量和字段。逐文件修改优先，不因编辑批次默认值静默被覆盖。批次默认值仅用于新加入的文件，已有文件通过明确批量操作更新。

平台/业务按项目规则校验：受限范围需至少选择一个值；“不限”是明确选择，不能以空值代替；草稿允许暂不填写，开始解析前按项目规则检查必填项。不同配置的混合选择显示“多个值”，不能显示成统一值。

解析方式与切片参数默认收起为“高级设置”，系统使用与文件类型相符的默认值。底部主按钮为“开始解析（N 份）”，展示将新解析、复用结果、关联现有任务的文件数量；此按钮是人工流程唯一的首次深度解析启动点。

### 第三步：解析与检查结果

开始后立即进入结果页，不阻塞请求等待全文。每文件独立排队与执行，完成一份即可查看该份原件、解析正文和切片。显示总体计数，例如“已完成 2 / 5，处理中 1，排队 1，失败 1”；这表示文件数量而非计算耗时百分比。

每行状态区分待解析、排队、正在解析、解析完成、解析失败、正在取消、已取消，以及结果复用。运行时展示实际阶段、耗时与最近活动：PDF 的解析/OCR，视频的音频准备/转写等。解析器能报告完成页数或音频时间段时显示对应进度条及计数；不能报告时显示不定进度条、阶段与耗时，不捏造百分比。上传字节进度和解析进度分开展示。

支持查看、取消、仅重试失败项和返回配置。取消不承诺瞬时抢占：不可中断调用显示正在取消，并在安全边界停止后续工作，不把旧产物写成新结果。移除运行项要先发出取消；若多个文件项共享底层任务，取消只解除该项关联，仍有其他引用时不能中止任务，无人引用时才请求取消底层工作；暂存数据按保留策略回收。关闭页面不会取消已明确启动的任务，重新进入恢复服务端状态。模型不可用、文件损坏和无可识别正文分别给出可操作错误。

修改平台、业务、受众、标题和时间不重跑 OCR/ASR；修改切片参数只重新切片；修改 OCR/ASR/解析方式则标记旧结果过期，用户明确点击“重新解析”后只处理受影响文件。元信息版本、解析指纹和切片版本分别记录；任务绑定解析指纹，迟到的旧解析结果不得覆盖新解析配置，但仅修改元信息时进行中的结果仍可复用，入库时校验最新元信息版本。服务端按内容与配置复用成功产物，并合并同范围内的重复运行请求，客户端重复点击不创建重复工作。

### 第四步：确认入库

选择解析完成且校验通过的资料，展示最终范围摘要和警告，点击“确认入库（N 份）”。不要求先入库才能查看切片。允许先确认成功项，失败项继续保留重试；有缺失资源、低识别质量等警告时保留具体定位与审核提示。

入库复用已确认的解析和切片产物，不重复上传、OCR 或 ASR。入库后分别展示知识抽取/保存状态和检索索引状态，不能将“解析完成”称作“可用于知识问答”。返回步骤不删除已完成产物；丢弃草稿会按清理策略释放无人引用的暂存资源。

## API 操作契约（已实现）

人工页面和 API 共用暂存、配置、解析、入库四阶段服务，不要求每批只有一个平台。现有正式 ingest-batches 接口保持兼容；新流程通过 preparation 会话提供，禁止直接把现有 start 动作重解释为只解析，避免改变调用方的入库语义。下列路径已纳入 OpenAPI 与回归；具体请求见 `docs/file-preparation-api.md`。共同入库方式通过 `PATCH /{id}/settings` 持久化并使用 settings_version 校验，确认不能静默采用另一页面更新的配置。

1. `POST /api/projects/{p}/preparations`：创建草稿会话，可提交默认配置。默认配置只作用于新项，不回溯覆盖旧项。
2. `POST /api/projects/{p}/preparations/{id}/files`：单文件 multipart 上传，可带该文件 options 与幂等键；返回 item_id、校验/重复状态、可复用信息。上传不启动全文解析。多文件调用复用同一会话即可。
3. `PATCH /api/projects/{p}/preparations/{id}/items/{item_id}`：逐文件配置。另设批量配置操作，显式提交 item_ids、fields 和填空/覆盖模式；返回每项最终配置及版本。
4. `POST /api/projects/{p}/preparations/{id}/parse`：提交 item_ids、各项预期配置版本和幂等键。先校验本次选择，阻断错误逐项返回且本次不启动；通过后返回 202 和逐项任务/复用状态。只排队深度解析，不写知识。
5. `GET /api/projects/{p}/preparations/{id}` 及逐项结果接口：轮询会话和任务状态，返回阶段、时间、可选进度计数、错误、正文/切片引用；未取得真实计数时 progress 为 null。支持逐项取消与失败重试。
6. `POST /api/projects/{p}/preparations/{id}/publish`：选择已就绪的 item_ids 与结果/配置版本，携带幂等键；校验通过返回正式入库任务 ID。非就绪项、过期结果和范围配置错误不能被静默入库。同一文件项和同一发布快照即使更换幂等键也返回原发布任务，不生成重复资料。再次发布须明确选择修订既有资料或创建独立资料，不能因重试隐式创建副本；修订需校验目标资料版本。对发现的已有资料提供复用已有资料、明确创建独立资料或修订的选择，不能只凭内容哈希决定业务身份。

API 调用示例语义：同会话上传 A.pdf（平台美团、业务到店）和 B.pdf（平台抖音、业务电商），分别携带 options；一次 parse 处理两项，轮询后再 publish 成功项。无人值守客户端可以在上传/配置成功后直接调用 parse，并在结果符合其既定策略后调用 publish；无需模拟点击，但不能让上传接口隐式承担昂贵解析与入库。以后若提供一键自动化封装，必须明确声明启动解析及自动入库策略，内部仍复用同一阶段契约。

接口均校验项目归属、权限、有效期及版本。幂等键在对应操作和项目范围内生效，相同键不同请求内容返回冲突；内容哈希只用于解析复用，不替代接口幂等，也不替代入库语义检查。批量修改采用预期版本校验，本次冲突时不部分覆盖，返回具体冲突项供刷新。

## 资源与验收决策

- 未点击开始解析的草稿不会创建 OCR/ASR/全文解析任务；轻量校验与原件按需预览仍有合理成本。
- 相同内容相同解析配置复用；不同元信息复用正文但独立处理入库范围，不跨越权限共享产物。
- 任务和产物持久化、受限并发、超时、失败重试、保留期和无人引用清理由服务端控制，页面关闭不丢任务。
- 测试覆盖上传不触发深解析、混合平台配置、批量覆盖/填空、重复请求合并、配置版本冲突、真实与不定进度、取消恢复、选择成功项入库，以及 API 与页面相同的阶段边界。

## ZIP 识别规则

1. 根目录一个 `.md`、`.html` 或 `.htm` 为主文档；允许一个统一外层目录。
2. 图片和视频等相对资源由主文档引用，通常放在 `assets/`。只作为该资料的资源处理，不生成额外资料行。
3. 多个可能的主文档直接提示分别上传，不静默合并。PDF/Word/独立视频的推荐入口是独立文件上传。
4. 新上传边界仅允许 MD/HTML/HTM 主文档，无论是否带 manifest。PDF/DOCX/图片/视频主文档 ZIP 及 `document.pages` 图片页包不属于这个新入口；应提示独立上传。普通用户界面不要求填写或编辑清单。
5. 历史兼容仅指已经保存的来源继续可读，包括既有非 MD/HTML 主文档或图片页包；不能把“历史可读”解释为继续允许新上传这些布局。应在新上传校验入口增加明确的 MD/HTML 资源包 profile，不能收窄历史读取器的默认能力。
6. 主文件缺失、无效路径、损坏/加密 ZIP、容量超限为阻断错误。缺失图片和未固化外链按具体内容显示可定位的警告，不笼统声称“ZIP 渲染失败”。
7. HTML/Markdown 预览保留原有清理和资源隔离规则；按资源类型处理，不能把普通 PDF 附件误作图片或主文档。

## 文件验证与真实样本

现有样本检查记录在 `tests/docs/README.md` 和 `tests/docs/validation-report.json`。

- 30 页 PDF 的第 24–30 页是 OCR 候选；其余多为可提取文字页面，因此需要混合页处理。
- 19 页协议的原生少量文字主要为重复内容，主体为图像，19 页均是 OCR 检查候选。
- Word 样本是 OLE `.doc`，当前产品返回 `unsupported_format`；这是格式支持缺口，不是文件损坏。
- 无 manifest 的 MD/HTML＋图片、MD＋视频、单外层目录 ZIP 已使用当前包解析器验证。
- 8 秒语音视频已验证容器、时长和音轨；未把媒体探测当作 ASR 准确率验收。
- 有界当前管线试验：30 页 PDF 仅第一页成功导出 1718 字符，初始化及处理共 85.61 秒；19 页扫描协议的第一页在 90 秒窗口内未完成。未验证任何一份全文，也不能由冷启动单页时间外推吞吐量。
- 同一扫描协议第一页预览图单独调用 RapidOCR 约 12.95 秒得到 964 字符、51 块、平均置信度约 0.896；这是单页 OCR 可运行证据，不能替代完整 Docling 或逐字质量验收。

OCR 候选诊断是启发式提示，不能代替逐页/区域识别和人工核对。真实资料不得仅依据“能提取到几个字”认定无需 OCR。

## 实现与兼容边界

新入口使用 `api/preparations.py`、`services/preparations.py`、`preparation_runner.py` 和 `repository/preparation_store.py`；迁移 0041 持久化会话、原件、任务、租约、幂等操作与正式任务的准备结果。上传与预览不启动模型；明确解析后才创建持久任务。

前端由 `document-preparation.js` 与 `document-preparation-view.js` 负责四步流程，`library-workspace.js` 接入原有抽屉。原件预览在文件行；配置与结果以清单为主，时间及识别、切片参数按需展开。恢复页面会恢复已保存的共同处理方式，单文件与批量编辑都校验打开表单时的版本。

正式入库继续使用已有批次与文档 worker，并复用准备结果。来源及 OCR/ASR 关联会克隆并重映射到正式文档，保持后续资料重处理的归属约束。新旧接口的 source 读取保持兼容；旧同步预览渲染器保留兼容测试，新文件入口不调用它执行全文解析。

同内容的成功解析结果可复用，运行任务可合并；失败/取消任务可在明确解析时重新排队。模型与解析器配置进入指纹，worker 缓存按运行时隔离。正式资料的重复判断包含尚未生成来源的既有排队任务；默认跳过重复，独立入库需要明确选择，修订从已有资料详情操作。

原始暂存区和未入库来源按有效期回收，正式来源引用受到保护。共享任务只解除本项关联；最后一个使用项取消后在安全边界停止。不可抢占的模型调用不承诺立刻结束。真实页级/时间段计数未提供时返回 progress=null，显示阶段、耗时与心跳。

Word 原版式在线转换尚未提供；DOCX 可下载原件核对，旧 DOC 当前不支持。完整 PDF OCR、视频转写质量及容量验收不包含在本轮专项回归中。

## 验收条件

- 文件行上的原件预览只打开所点文件；删除、同名文件、切换项目后不会串资料。
- 有效 MD/HTML 资源 ZIP 不需要 JSON，可显示正文、表格及本地图片/视频。
- 新上传的 PDF/DOCX/视频主文档包和 `document.pages` 包均有明确的拒绝回归；相同历史来源仍能读取。新上传入口已使用独立 profile，历史读取器默认能力保持兼容。
- 扫描 PDF/视频的原件预览不会启动 OCR/ASR；明确开始解析后创建后台任务，返回任务 ID 后立即可离开页面。
- 上传与第一步的下一步均不启动深解析；完成配置并点击开始解析才排队。
- 同批不同平台文件能分别设置范围；修改平台/时间不重复 OCR/ASR，批量应用不静默覆盖逐文件设置。
- 解析慢、失败、取消、重试和服务重启均有明确状态，进度来自实际阶段/计数。
- 解析产物能复用于正式处理；重复点击不会重复上传、OCR 或产生多份知识。
- 桌面和手机都能查看文件、定位错误、返回清单及继续流程。
