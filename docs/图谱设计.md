# 美团规则知识图谱设计

> 基于 `实体关系分析\实体关系提取明细.xlsx`（4 个 sheet：357 条规则逐文件提取 + 403 实体 + 89 关系 + 图谱蓝图）反向归纳。
> 用 LLM（qwen3.8-2.4t-a95b @ MaaS）批量补全 + 持续入库。

## 0. 整体架构


### 2.2 关系频次降噪

`RuleDocument --appliesTo--> 本规则` 这种"自指"是噪声（共 8 次）。需要：
- **后处理**：剔除"本规则"、"本规范"等自指
- **强约束**：LLM 抽取时 prompt 加"appliesTo 头实体不应是 RuleDocument 自身"

### 2.3 边属性

```yaml
edge:
  predicate: 21 类之一
  source_file: 来自哪个 rule_txt
  source_text: 原文片段（用于溯源）
  confidence: LLM 置信度
  source_role: 头实体的角色（actor 类型）
  target_role: 尾实体的角色
```

## 3. 图谱结构（Graph Topology）

### 3.1 度中心节点（hub）

- `Platform` (1 个 canonical 节点) → 连 5 万+ 边（collectsUses, appliesTo, handles, ...）
- 357 个 `RuleDocument` 节点 → 各连 10-30 条边
- 主流 Law 节点（民法典 6 次、消保法 ×次、...）→ 50+ RuleDocument 引用

### 3.2 索引设计

```python
# 节点
(:Platform {name, canonical, alias_count, source_files})
(:User {name, ...})
(:RuleDocument {rule_id, title, file_path, category_l1, category_l2})
(:Violation {name, category})
(:Penalty {name, category})
(:Law {name, full_name})
(:PersonalData {name, category})

# 边索引
(:Platform)-[:PUBLISHES]->(:RuleDocument)
(:RuleDocument)-[:APPLIES_TO]->(:Merchant)
(:RuleDocument)-[:HAS_LEGAL_BASIS]->(:Law)
(:RuleDocument)-[:PROHIBITS]->(:Violation)        # 由"违规行为"字段反推
(:Violation)-[:TRIGGERS]->(:Penalty)
(:Platform)-[:COLLECTS]->(:PersonalData)
(:Platform)-[:SHARES_WITH]->(:ExternalOrg)
(:Merchant)-[:COMMITS]->(:Violation)
```

### 3.3 跨文件实体合并

同一规则在多份文档被引用 → 一份文档只创建一个 `RuleDocument` 节点（按 `rule_id` 唯一）；同一 `Violation` / `Penalty` / `PersonalData` 节点可被多条 RuleDocument 关联。

```turtle

  a sh:NodeShape ;
  sh:targetClass mt:RuleDocument ;
  sh:property [
    sh:path mt:ruleId ; sh:minCount 1 ; sh:datatype xsd:string ;
```

## 5. LLM 抽取策略

### 5.1 单文档抽取（per-file，对应 xlsx Sheet 1）

每份 rule_txt 通过一次 LLM 调用（结构化 JSON 输出）抽取 6 类字段：

```json
{
  "rule_id": "规则 ID（如 364 行 Excel 中的）",
  "rule_name": "规则名",
  "category_l1": "一级分类（业务线）",
  "category_l2": "二级分类（板块）",
  "category_l3": "三级分类（子类）",

  "actors": {
    "平台":   ["美团", "大众点评", "平台", "我们"],
    "用户":   ["用户", "消费者", "买家"],
    "商家":   ["商家", "商户", "卖家", "店铺"],
    "履约服务方": ["客服"],
    "监管/外部": ["第三方", "合作商", "支付机构"]
  },

  "defined_terms": [
    { "term": "到店综合类行业", "definition": "美团平台发布的最新《到店综合业务明细》" },
    { "term": "非正常消费行为", "definition": "实际交易中，任意一方不是以接受服务..." }
  ],

  "violations": [
    { "category": "质量/安全", "term": "过期", "evidence": "原文片段" },
    { "category": "履约违规", "term": "超时", "evidence": "..." }
  ],

  "penalties": [
    { "category": "商品处置", "term": "删除", "evidence": "..." },
    { "category": "资金赔付", "term": "退款", "evidence": "..." }
  ],

  "legal_basis": ["中华人民共和国民法典", "消费者权益保护法"],

  "spo_relations": [
    { "subject": "平台", "predicate": "收集使用", "object": "个人信息", "evidence": "原文片段" },
    { "subject": "规则文档", "predicate": "适用于", "object": "商家", "evidence": "..." },
    { "subject": "违规行为", "predicate": "触发", "object": "处罚措施", "evidence": "..." }
  ]
}
```

### 5.2 Prompt 关键约束

- **actor 必须从 canonical map 中选**（或用极少新值）
- **predicate 必须从 21 类核心关系中选**（约束抽取）
- **每个三元组附 evidence 原文片段**（用于溯源）
- **appliesTo 头不能是 RuleDocument 自身**（过滤自指）
- **violation / penalty 的 category 字段**应尽量归并到 7-12 个大类（虚假交易/售假侵权/质量/履约/账号秩序/价格违规/广告/信息违规/...）

### 5.3 抽取 → 入库流程

```
LLM JSON 抽取
  ↓
1. alias 归一（actor / violation / penalty / law）
2. canonical 实体去重
3. SHACL 校验（ruleId 必填、appliesTo ≥ 1、violation-triggers-penalty 完整性）
4. 图谱 upsert（Neo4j / FalkorDB / in-memory）
5. 反向生成 Sheet 1 同款明细（CSV / xlsx），便于和 xlsx 对比
```

## 7. 评估口径

- **覆盖率**：多少份 txt 成功抽取（目标 >95%）
- **实体召回**：xlsx 已有 403 实体，LLM 自动抽取能复现多少（目标 >80%）
- **关系召回**：xlsx 89 个核心关系，LLM 能复现多少（目标 >70%）
- **噪声率**：出现频次 ≤1 的"长尾"关系占多少（目标 <30%）
- **同义合并率**：抽取的实体中，alias→canonical 合并比（预期 5:1 - 10:1）
