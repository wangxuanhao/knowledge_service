平台规则资料上传与 ZIP 打包操作手册

核对日期：2026-11-16。适用于独立图片、长图 OCR、文档媒体、视频 ASR 和单资料 ZIP 上传。流程为“上传核对 → 配置资料 → 解析与检查 → 确认处理”。上传只暂存和校验，明确开始解析后才识别；确认提交后自动维护检索索引。每个独立文件或 ZIP 对应一份资料。

1. 先选上传方式

手里的资料上传方式处理结果
TXT、Markdown直接选择 .txt、.md读取正文，生成切片和所选模式的处理结果
PDF直接选择 .pdf解析原生文字、表格；扫描内容按文档 OCR 配置处理，保留 PDF 原件
Word直接选择 .docx解析正文、表格，自动取出可提取的内嵌图片做 OCR
HTML直接选择 .html、.htm解析网页文档；带本地附件时一起打包
图片、长截图直接选择 .png、.jpg、.jpeg、.webp保存完整原图，开始解析后 OCR；长图自动分块识别，仍是一份资料
视频直接选择 .mp4、.webm保存原件供播放，开始解析后通过 ASR 转写语音及时间段
一份 MD / HTML 及图片、视频附件将一个主文件与引用的 assets/ 打成一个 ZIP普通包不需要 manifest.json，附件归属于该资料
同一规则的多张连续截图在一个根目录 MD 中按顺序引用 assets 中各图后打 ZIP作为同一资料识别；旧 document.pages 包只保留历史读取
多份互不相关的规则多选独立文件，或每份规则分别打 ZIP 后多选每个文件或 ZIP 各建一份资料，可统一提交

独立图片和图片合集只接收静态 PNG、JPEG、WebP。动画或多帧图片会被拒绝，请先导出静态图片；GIF、TIFF 不属于本轮独立图片上传格式。文件扩展名还必须与实际内容一致。

单独上传 MD 只会上传该文件。引用本地图片、视频的 MD 应连同附件打包。Word 的内嵌图片会自动提取，无需先另存为 MD；复杂浮动图、文本框和精细排版不保证还原为 Word 原版式，核对时可下载原文件。视频只转写语音，不做视频帧 OCR。

2. ZIP 怎样做到一包一份资料

推荐：一个 MD / HTML，加上 assets，不需要清单

一份规则.zip
├── 规则.md
└── assets/
    ├── 场景1.png
    ├── 场景2.jpg
    └── 规则讲解.mp4

规则.md 可以这样写：

# 规则说明

发布日期：2026-01-01
生效时间：2026-02-01

这里是规则正文。

![违规场景一](assets/场景1.png)
![违规场景二](assets/场景2.jpg)

[播放规则讲解](assets/规则讲解.mp4)

普通包不需要 manifest.json。 系统识别唯一主文档，并按正文引用关联附件，不把每个附件当成另一份资料。PDF、Word、独立图片和视频直接上传，不必为了打包而添加 JSON。

引用路径相对 MD / HTML 所在目录。HTML 可使用 <img src="assets/场景1.png" alt="违规场景一"> 和 <video src="assets/规则讲解.mp4" controls></video>。日期填写原文对应日期；平台、业务和适用对象在对应文件的资料设置中填写。所有文件外面仅多套一层文件夹时可归一化包根；不要放两个主文件或依靠文件名字母顺序自动拼接。

可选：兼容已有的 manifest.json

manifest.json 是描述主文件入口、标题和可选 metadata 的清单，不是知识正文。现有采集程序的清单只有满足当前唯一根目录 MD / HTML 要求时才可用于新上传；普通 MD / HTML 与 assets 包不必手写它。有序图片页清单只供历史来源读取。

{
  "schema_version": 2,
  "document": {
    "entry": "规则.md",
    "title": "规则说明",
    "metadata": {"rule_id": "rule-a"}
  }
}

清单放在 ZIP 根目录，entry 相对包根且只指定一份主资料；例如上述结构需有根目录 规则.md 及相对引用的 assets/。即使有清单，也必须满足唯一根目录 MD / HTML 主文档。title 可省略，填写时非空且不超过 300 字符；metadata 是 JSON 对象。普通包优先用前面的无清单结构。document.pages 只保留已入库历史来源的读取，不支持新上传；旧的多资料 documents 包须拆开，并逐包满足当前根目录主文档要求。

采集分类可保存在 metadata，但任意自定义字段不会自动成为图谱筛选条件。处理前仍应核对文件行中的实际标题、平台、业务、适用对象和时间。

手动压缩时检查

  1. 将主文件、附件和可选清单整理好，清单放在包根，路径写完整。
  2. 在资源管理器中选中这些文件和文件夹，压缩为普通、未加密的 .zip。
  3. 打开 ZIP 核对层级、文件名和媒体引用；文本与清单使用 UTF-8 编码。

RAR、7z、ZIP 内再次嵌套的压缩包不作为主资料解析。包内只使用相对路径，不放磁盘绝对路径、符号链接或指向包外的路径。未引用文件会提示，但不会自动成为额外资料。

网络图片怎样变成本地附件

对 ![示例](https://example.com/images/a.png)，先下载图片到 MD 同级的 assets/a.png，再改为 ![示例](assets/a.png)，最后连同 MD 打包。

脚本只收集实际引用的本地文件；网络图片地址会保留并写入报告警告。服务端可按远程图片配置尝试抓取，离线阅读前仍需核对是否已固化。网络视频标记为待固化，需提供本地视频附件。

3. 多张连续截图组成一份资料

三张图属于同一份规则时，在根目录放一个 MD，按阅读顺序引用各图，再与 assets 一起压缩：

规则截图.zip
├── 规则截图.md
└── assets/
    ├── 01.png
    ├── 02.png
    └── 03.webp
# 规则截图

![第一页](assets/01.png)
![第二页](assets/02.png)
![第三页](assets/03.webp)

这是一份主文档，图片按正文引用位置处理，不依靠文件名排序。直接多选三张独立图片会建立三份资料，不会自动合并。

历史兼容边界： 已入库的 document.pages 图片页来源仍可读取，但当前上传入口明确拒绝新的图片页清单包。旧脚本的 --image 模式可保留历史工具用途，不能把输出当成当前可直接上传的包；请改为上述 MD 引用图片的结构。PDF、Word、独立图片和视频仍分别直接上传。

长图无需人为裁成多份。后台分块 OCR 并把文字框还原到完整原图位置；这是识别计算分块，不是资料拆分，也不同于知识切片。技术识别失败时先核对问题区域并重试，不能将部分文字当成完整解析。

4. 只打包选中的真实平台规则

现有采集根目录为 D:\workspace\知识图谱源数据\平台经济规则。例如：

平台经济规则/
└── 抖音电商/
    ├── 某条规则.md
    └── assets/
        └── 某张图片.png

脚本会保留相对于 --root 的路径。要让输出可用于当前上传，把主 MD 的直接父目录作为 --root，并用不带子目录的文件名选件。 若用上层采集总目录作为根，会得到“根 manifest＋平台子目录主文档”，不满足当前唯一根 MD 的要求。以下命令已按正确根目录写法整理；来源目录只读。

只选一份规则

在 PowerShell 运行：

& 'D:\anaconda\envs\llm_model\python.exe' `
  'D:\workspace\knowledge_service_v2\knowledge_service\scripts\package_rule_documents.py' `
  --root 'D:\workspace\知识图谱源数据\平台经济规则\抖音电商' `
  --file '创作者管理_「违规营销：憋单」实施细则_aHsCBTFBK4YS.md' `
  --output-dir 'D:\workspace\knowledge_service_v2\outputs\unified-media-example\single-rule-packages'

运行成功后生成 rule-documents-001.zip 和 packaging-report.json。--file 可重复，选择两份 MD 就输出两个 ZIP。

从清单中只选一部分

先创建 UTF-8 文本文件 D:\workspace\knowledge_service_v2\outputs\selected-rules.txt，每行是相对该平台目录的根 MD 文件名，不带平台或其他子目录：

创作者管理_「违规营销：憋单」实施细则_aHsCBTFBK4YS.md
专题解读_生鲜和鲜花绿植虚假宣传规则白皮书_aJkzdMC7vZJy.md

再运行：

& 'D:\anaconda\envs\llm_model\python.exe' `
  'D:\workspace\knowledge_service_v2\knowledge_service\scripts\package_rule_documents.py' `
  --root 'D:\workspace\知识图谱源数据\平台经济规则\抖音电商' `
  --list-file 'D:\workspace\knowledge_service_v2\outputs\selected-rules.txt' `
  --output-dir 'D:\workspace\knowledge_service_v2\outputs\unified-media-example\packages'

空行和以 # 开头的行会忽略；清单可带 UTF-8 BOM。--file 与 --list-file 可重复混用，按命令中的选件顺序处理，重复路径只选一次。

现在每份 MD 各生成一个 ZIP，不再按每包 200 份 MD 合包。 两份规则会输出 rule-documents-001.zip、rule-documents-002.zip；十份规则输出十个包；确认每包都是根目录 MD 加引用资源后，可一起选中上传。附件在各自包中归属对应资料。

--manifest 也保留为选件入口：传入含 documents 的 JSON 可同时选择多份 MD，并保留每份标题与 metadata，输出仍是每份 MD 一个新版包；也可传入新版单资料清单。--manifest 不能与 --file、--list-file 同用。这里的脚本输入清单与上传 ZIP 内的清单用途不同，多项 documents 不能继续作为上传包清单。

每次使用尚不存在的输出目录，且输出目录必须在 --root 外。脚本默认限制每包 24,000,000 字节；可用 --max-zip-bytes 指定不超过 25,000,000 的值。单份资料加附件超过上限会报错，不会拆成丢失上下文的小包。--max-documents 只是旧命令兼容参数，不再改变每包一份资料的规则。

上传前打开 packaging-report.json，核对包列表、文件、字节数、SHA256 和外链警告。脚本会检查其生成结构与媒体可读性，但历史格式的打包成功不等于当前新上传校验通过。检查主文档是否在包根；不同父目录的资料分别以各自父目录为根生成。必要时去掉旧清单、把 MD 与其 assets 一起整理到包根后重压缩。脚本不执行 OCR、ASR，也不代表知识抽取已验收。

5. 旧的多资料 ZIP 怎样迁移

旧包情况新上传的行为整理方法
旧 manifest 的 documents 只有一项只在满足当前唯一根 MD / HTML 及引用资源时可新上传其他格式作为历史来源读取；新包按第 2 节重整
documents 有两项或更多明确拒绝，不再自动拆成多份资料用新版脚本逐份生成 ZIP
无清单，含多个 MD 或多个主文件明确拒绝为每份资料分别打包；同一资料的连续截图用一个根 MD 按顺序引用
过去已成功入库的多资料包历史记录及来源继续保留无需为适配新规则重传或删除历史资料

拆分旧包时：

  1. 保留原 ZIP，解压一份副本到新的工作目录，核对正文与附件齐全。
  2. 若主 MD 都在同一目录，使用其直接父目录作为 --root，用不带子目录的 --file 或 --list-file 选件。分处不同目录的 MD 分别运行，输出目录各自放在源目录之外。
  3. 需要保留自定义标题和 metadata 时，可用选件 --manifest。若用解压总目录和旧清单拆包，脚本会保留嵌套路径；此类输出不能直接上传，还需将每份 MD 及其相对引用资源整理到各包根目录，更新或移除旧清单后重压缩。
  4. 核对报告及每包内容，确保每包是唯一根 MD / HTML 和引用资源，再在页面多选 ZIP，按四步流程操作。

脚本不会直接读取旧 ZIP 或自动解压。如果旧包主文件是 PDF、DOCX、独立图片或视频，应分别直接上传原文件；当前 ZIP 入口不接收这些格式作为主文件。只有 MD / HTML 引用本地资源时才按第 2 节打包。不要仅把旧清单从 documents 改名为 document 而继续期望导入多份正文。

6. 在页面上追加、预览和提交

  1. 选中项目，进入“资料库 → 添加文件”。当前是四步：“上传核对 → 配置资料 → 解析与检查 → 确认处理”。
  2. 第 1 步分次选择或拖入文件。打开「添加文件」后，把文件拖到上传核对区域的虚线框或空白处即可，也可点「选择文件」。这里只暂存和验证；点击对应文件行的“原件预览”检查原件，DOCX 会在弹窗内按标题层级、表格与内嵌图片渲染，分页与页眉页脚以 Word 打开为准。
  3. 第 2 步可逐文件点击“设置”，在该文件卡片下展开平台、业务、适用对象和时间配置；相同字段可勾选后“批量设置所选文件”，选择填补空值或覆盖。同批不要求一个平台或业务。选择本批后续处理方式，并按需在“高级解析设置”调整切片或属性提取选项；切片参数用“将切片设置应用到所选文件”明确应用。
  4. 点击“开始解析”后，第 3 步显示排队、文字识别、视频转写和切片向量准备状态。PDF、图片和视频等可能耗时较长，可离开后继续查看；只有真实可用的阶段数量才显示数量进度，不把心跳当成精确百分比。
  5. 解析完成后，逐文件“查看正文与切片”，核对 OCR/ASR 文字、来源位置和分段。技术识别失败或结果过期时，点该文件“重新解析”；也可用“重试失败或过期项”。拆分不符合预期时，先在“高级解析设置”调整切片策略、最大字符数或重叠，再点该文件“重新拆分”——正文与识别结果直接复用，不重复 OCR 或转写，仅按新设置重新生成切片。
  6. 第 4 步选择已核对的成功文件，按下表确认后续任务。解析结果直接复用；确认提交后自动维护正式索引，草稿本身不能被搜索或问答引用。
  7. 已提交文件不再留在上传清单，去“处理批次”看后续进度。“继续未完成上传”只找回未提交的文件、配置和可复用解析，不是恢复已入库资料；关闭添加文件窗口不取消后台任务。未提交准备会话自创建起保留 7 天，访问不会续期；过期后未提交暂存会被清理，需要重传。此期限与切片向量缓存的 7 天有效期是两回事，已提交资料和批次另行保留。
处理方式第 4 步按钮本次任务与后续操作
仅文档检索开始建立检索索引正式提交正文和切片，自动建立或更新索引；不抽取实体关系
开放发现开始构建本体生成待核对候选。可复用正式术语的候选按确认流程写入，需要新定义时加入草案审核发布
使用项目本体开始知识抽取按已发布本体抽取与校验，核对正式事实及待审核项

开放发现会参考已发布的类名。只有草案时仍可生成候选，新增定义在审核发布后可用于「使用项目本体」。

解析把原文及媒体转换为可检查的正文，切片再按规则分段。图片 OCR 和视频 ASR 按正文引用位置合入统一文字流，再按长度、重叠和章节规则切片，不因附件身份强制单独成片。 不同片长及段落边界仍可能产生多片；各自的图片区域和视频时间段保留。

时间和业务范围按每份资料核对；批量填写只适用于已选且确实相同的文件。发布时间、生效时间、失效时间和上传时间不能混用。向量预计算失败与解析失败分开：前者可在确认提交后由正式索引任务补算；正文识别技术失败则应先重新解析，不能确认提交。过滤少量低置信文字后仍有足够可靠内容的提示不一定阻断，需要人工核对正文。

已有资料怎样重新处理或构建图谱

可以先选择“仅文档检索”完成解析、OCR/ASR 和切片，先使用文档检索，之后再构建图谱。打开资料详情，找到“重新处理 / 构建图谱”，选择处理方式，再点击“创建处理任务”：

详情中的处理方式本次任务做什么
仅文档检索重新生成正文切片并更新项目检索输入，暂不抽取实体和关系
开放发现生成待核对候选，之后确认复用正式术语，或将新定义加入草案审核发布
使用项目本体按已发布的项目本体重新抽取并校验事实；尚未发布本体时，先完成发布

此入口复用固定来源和可复用的成功 OCR/ASR，不需要再次上传文件。资料 ID 保持不变，系统创建新的处理任务与处理代际，并保留处理历史。点击“查看处理任务”可进入后台任务查看进度，完成后仍需核对索引同步与图谱结果。已有未结束任务时，先完成或取消该任务；缺少固定原始来源的旧资料会提示重新上传，已有正文仍可阅读。

“解析视图”中的“重试 OCR”或“重试未完成 OCR 区域”只更新该图片的识别结果。若希望新文字进入检索切片或图谱，回到资料详情执行整份重新处理，再核对索引和相应审核结果；单项 OCR 重试不会自动重建这些结果，历史记录继续保留。

首次索引、旧索引重建与普通增量更新由后台自动处理。在资料库、检索图谱、问答或台账打开“检索索引”，查看切片与事实覆盖数量、进度和错误。普通失败会按间隔重试；管理员可手动“重建全部检索索引”。上传或重新处理完成不等于立即可检索，以“可检索”状态和实际结果为准。

“图文阅读”呈现固定来源的正文、表格与关联媒体；“已保存正文”查看系统用于切片及知识处理的保存文字，可能包含 OCR/ASR 补入内容，不能代替原文件排版。PDF 的固定版本阅读器通过本地渲染显示原版页图，不依赖浏览器 PDF 插件；页图有分辨率上限，精细核对可下载原 PDF。

主检索关键词、语义和混合方式依赖项目 Milvus 索引就绪；首次建立和后续同步自动处理，资料库的字面关键词查询另行读取已保存资料。页面混合检索默认关键词候选语义排序，也可在检索设置改为双路融合；最低语义相似度默认 0.35，可调整。图谱默认保留全部历史业务时间；按当前或指定业务日期筛选时，还需核对生效、失效及未知日期项。

9. 大小限制和常见问题

当前默认限制如下，页面还会读取服务能力；文件、图片和 ZIP 的各项检查都要满足。

对象限制
单个上传文件或 ZIP25,000,000 字节
单张图片，包括独立图片和图片页10 MiB（10,485,760 字节），不超过 40,000,000 像素
单份资料的图片最多 200 张，图片总字节不超过 100 MiB；仍受 ZIP 上传大小约束
一个批次最多 1,000 份资料，总上传量不超过 1,000,000,000 字节
ZIP 安全检查最多 5,000 个成员、解压总量 512 MiB、压缩比上限 200；禁止加密及符号链接
文本非空，最多 1,000,000 字符
视频不超过 600 秒；MP4 使用 H.264/AAC，WebM 使用 VP8、VP9、AV1 与 Opus/Vorbis

图片即使小于 25,000,000 字节，也可能超过更严格的 10 MiB 或总像素限制。多帧图片请逐帧导出为静态图片；确属同一资料时，用一个根 MD 按顺序引用后打包。OCR 耗时取决于图像尺寸、分块数、文字密度与机器负载，视频 ASR 还包含模型启动时间。
