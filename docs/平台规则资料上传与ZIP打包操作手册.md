# 平台规则资料上传与 ZIP 打包操作手册

核对日期：2026-11-11。适用于独立图片、长图 OCR、文档媒体、视频 ASR 和单资料 ZIP 上传。**每个独立文件或 ZIP 对应一份资料；在第 1 步分次追加文件后，可以统一提交。已有资料可从详情创建新的处理任务。**

## 1. 先选上传方式

| 手里的资料 | 上传方式 | 处理结果 |
| --- | --- | --- |
| TXT、Markdown | 直接选择 `.txt`、`.md` | 读取正文，生成切片和所选模式的处理结果 |
| PDF | 直接选择 `.pdf` | 解析原生文字、表格；扫描内容按文档 OCR 配置处理，保留 PDF 原件 |
| Word | 直接选择 `.docx` | 解析正文、表格，自动取出可提取的内嵌图片做 OCR |
| HTML | 直接选择 `.html`、`.htm` | 解析网页文档；带本地附件时一起打包 |
| 图片、长截图 | 直接选择 `.png`、`.jpg`、`.jpeg`、`.webp` | 保存完整原图，正式处理时 OCR；长图自动分块识别，仍是一份资料 |
| 视频 | 直接选择 `.mp4`、`.webm` | 保存原件供播放，正式处理时通过 ASR 转写语音及时间段 |
| 一份文档及图片、视频附件 | 将一个主文件与引用的附件打成一个 ZIP | 建立一份资料，附件归属于该资料 |
| 同一规则的多张连续截图 | ZIP 中用 `document.pages` 明确图片顺序 | 建立一份有序图片资料，保留页序 |
| 多份互不相关的规则 | 多选独立文件，或每份规则分别打 ZIP 后多选 | 每个文件或 ZIP 各建一份资料，可统一提交 |

独立图片和图片合集只接收静态 PNG、JPEG、WebP。动画或多帧图片会被拒绝，请先导出静态图片；GIF、TIFF 不属于本轮独立图片上传格式。文件扩展名还必须与实际内容一致。

单独上传 MD 只会上传该文件。引用本地图片、视频的 MD 应连同附件打包。Word 的内嵌图片会自动提取，无需先另存为 MD；复杂浮动图、文本框和精细排版不保证还原为 Word 原版式，核对时可下载原文件。视频只转写语音，**不做视频帧 OCR**。

## 2. ZIP 怎样做到一包一份资料

### 推荐：一个主文件，加上引用的附件

```text
一份规则.zip
├── manifest.json
└── 平台/
    ├── 规则.md
    └── assets/
        ├── 场景1.png
        ├── 场景2.jpg
        └── 规则讲解.mp4
```

`平台/规则.md` 可以这样写：

```markdown
# 规则说明

发布日期：2026-01-01
生效时间：2026-02-01

这里是规则正文。

![违规场景一](assets/场景1.png)
![违规场景二](assets/场景2.jpg)

[播放规则讲解](assets/规则讲解.mp4)
```

引用路径相对 **MD 所在目录**。这里的 `assets/场景1.png` 对应包内 `平台/assets/场景1.png`。日期仅为写法示例，整理时填写原文对应日期。HTML 写法 `<img src="assets/场景1.png" alt="违规场景一">` 和 `<video src="assets/规则讲解.mp4" controls></video>` 也可关联媒体。

根目录的 `manifest.json` 使用新版单资料清单：

```json
{
  "schema_version": 2,
  "document": {
    "entry": "平台/规则.md",
    "title": "规则说明",
    "metadata": {
      "rule_id": "rule-a",
      "source_url": "https://example.com/rules/a",
      "collection_category_path": ["商家管理", "营销规则"]
    }
  }
}
```

`entry` 相对 ZIP 根目录，只指定一个主文件。主文件支持 MD、TXT、DOCX、HTML、PDF、PNG/JPEG/WebP、MP4/WebM；`title` 和 `metadata` 可省略。`title` 非空且最多 300 字符，`metadata` 必须是 JSON 对象。打包脚本会自动生成清单，但脚本的选件入口只负责 MD 及有序图片合集；其他主文件可按此结构手动打包。

平台、业务和适用对象在页面对应控件中填写。采集分类可以先保存在 metadata；任意自定义字段不会自动成为图谱筛选条件，需要已有字段映射。

### 无清单的简易包

不放 `manifest.json` 时，根目录只能有一个主文件，其余附件放在 `assets/`：

```text
简易规则.zip
├── 规则.md
└── assets/
    └── 场景1.png
```

两个 MD、两个独立主文件，或多张图片没有明确页序的包都会被要求整理。不要依靠文件名字母顺序自动拼接。所有文件外面仅多套了一层文件夹时，系统可以去掉这一层作为包根；多层套目录或多个候选根请自行整理。

### 手动压缩时检查

1. 将主文件、附件和可选清单整理好，清单放在包根，路径写完整。
2. 在资源管理器中选中这些文件和文件夹，压缩为普通、未加密的 `.zip`。
3. 打开 ZIP 核对层级、文件名和媒体引用；文本与清单使用 UTF-8 编码。

RAR、7z、ZIP 内再次嵌套的压缩包不作为主资料解析。包内只使用相对路径，不放磁盘绝对路径、符号链接或指向包外的路径。未引用文件会提示，但不会自动成为额外资料。

### 网络图片怎样变成本地附件

对 `![示例](https://example.com/images/a.png)`，先下载图片到 MD 同级的 `assets/a.png`，再改为 `![示例](assets/a.png)`，最后连同 MD 打包。

脚本只收集实际引用的本地文件；网络图片地址会保留并写入报告警告。服务端可按远程图片配置尝试抓取，离线阅读前仍需核对是否已固化。网络视频标记为待固化，需提供本地视频附件。

## 3. 多张连续截图组成一份资料

若三张图是同一份规则的连续页面，可以直接建立有序图片包，无需另写 MD：

```text
规则截图.zip
├── manifest.json
└── assets/
    ├── 01.png
    ├── 02.png
    └── 03.webp
```

```json
{
  "schema_version": 2,
  "document": {
    "title": "规则截图",
    "pages": ["assets/01.png", "assets/02.png", "assets/03.webp"],
    "metadata": {
      "source_url": "https://example.com/rules/a"
    }
  }
}
```

`pages` 数组的先后就是阅读和识别顺序，路径不能重复，`entry` 与 `pages` 只能使用一种。这个 ZIP 对应 **一份资料、三张图片**。同批直接选择三张独立图片则会建立三份资料，不会自动合并。

也可以用脚本生成。下面的截图目录和图片名为示例，请替换成自己的实际路径，并选一个尚不存在的输出目录：

```powershell
& 'D:\anaconda\envs\llm_model\python.exe' `
  'D:\workspace\knowledge_service_v2\knowledge_service\scripts\package_rule_documents.py' `
  --root 'D:\workspace\我的规则截图' `
  --image 'assets/01.png' `
  --image 'assets/02.png' `
  --image 'assets/03.webp' `
  --title '规则截图' `
  --output-dir 'D:\workspace\knowledge_service_v2\outputs\unified-media-example\image-page-packages'
```

`--image` 可以重复，按命令中的顺序打包；不能同时使用 `--file`、`--list-file` 或 `--manifest`。`--title` 仅用于 `--image` 模式，MD 的标题或 metadata 用输入清单指定。

长图无需人为裁成多份再上传。后台会将原图分块 OCR，并把文字框还原到原图位置；计算分块不是资料拆分，也不同于后续的知识切片。处理中可查看已完成块数和总块数；部分块失败时保留已识别结果并提示覆盖不完整，需按问题位置核对和重试。

## 4. 只打包选中的真实平台规则

现有采集根目录为 `D:\workspace\知识图谱源数据\平台经济规则`。例如：

```text
平台经济规则/
└── 抖音电商/
    ├── 某条规则.md
    └── assets/
        └── 某张图片.png
```

MD 已使用 `assets/某张图片.png` 时，脚本会保留平台子目录及相对引用，收集该 MD 引用的图片和视频。不会递归把整个采集目录都打进去，也不会改写源文件。

### 只选一份规则

在 PowerShell 运行：

```powershell
& 'D:\anaconda\envs\llm_model\python.exe' `
  'D:\workspace\knowledge_service_v2\knowledge_service\scripts\package_rule_documents.py' `
  --root 'D:\workspace\知识图谱源数据\平台经济规则' `
  --file '抖音电商/创作者管理_「违规营销：憋单」实施细则_aHsCBTFBK4YS.md' `
  --output-dir 'D:\workspace\knowledge_service_v2\outputs\unified-media-example\single-rule-packages'
```

运行成功后生成 `rule-documents-001.zip` 和 `packaging-report.json`。`--file` 可重复，选择两份 MD 就输出两个 ZIP。

### 从清单中只选一部分

先创建 UTF-8 文本文件 `D:\workspace\knowledge_service_v2\outputs\selected-rules.txt`，每行一份相对采集根目录的 MD 路径：

```text
抖音电商/创作者管理_「违规营销：憋单」实施细则_aHsCBTFBK4YS.md
抖音电商/专题解读_生鲜和鲜花绿植虚假宣传规则白皮书_aJkzdMC7vZJy.md
```

再运行：

```powershell
& 'D:\anaconda\envs\llm_model\python.exe' `
  'D:\workspace\knowledge_service_v2\knowledge_service\scripts\package_rule_documents.py' `
  --root 'D:\workspace\知识图谱源数据\平台经济规则' `
  --list-file 'D:\workspace\knowledge_service_v2\outputs\selected-rules.txt' `
  --output-dir 'D:\workspace\knowledge_service_v2\outputs\unified-media-example\packages'
```

空行和以 `#` 开头的行会忽略；清单可带 UTF-8 BOM。`--file` 与 `--list-file` 可重复混用，按命令中的选件顺序处理，重复路径只选一次。

**现在每份 MD 各生成一个 ZIP，不再按每包 200 份 MD 合包。** 两份规则会输出 `rule-documents-001.zip`、`rule-documents-002.zip`；十份规则输出十个包，可一起选中上传。附件在各自包中归属对应资料。

`--manifest` 也保留为选件入口：传入含 `documents` 的 JSON 可同时选择多份 MD，并保留每份标题与 metadata，输出仍是每份 MD 一个新版包；也可传入新版单资料清单。`--manifest` 不能与 `--file`、`--list-file` 同用。这里的**脚本输入清单**与**上传 ZIP 内的清单**用途不同，多项 `documents` 不能继续作为上传包清单。

每次使用尚不存在的输出目录，且输出目录必须在 `--root` 外。脚本默认限制每包 24,000,000 字节；可用 `--max-zip-bytes` 指定不超过 25,000,000 的值。单份资料加附件超过上限会报错，不会拆成丢失上下文的小包。`--max-documents` 只是旧命令兼容参数，不再改变每包一份资料的规则。

上传前打开 `packaging-report.json`，核对包列表、文件、字节数、SHA256 和外链警告。脚本会检查生成包的结构与媒体可读性，但不执行 OCR、ASR，也不代表知识抽取已验收。

## 5. 旧的多资料 ZIP 怎样迁移

| 旧包情况 | 新上传的行为 | 整理方法 |
| --- | --- | --- |
| 旧 manifest 的 `documents` 只有一项 | 可兼容为一份资料 | 建议重新打包为 v2；核对原有 title、metadata 和引用 |
| `documents` 有两项或更多 | 明确拒绝，不再自动拆成多份资料 | 用新版脚本逐份生成 ZIP |
| 无清单，含多个 MD 或多个主文件 | 明确拒绝 | 为每份资料分别打包；连续截图改用 `pages` |
| 过去已成功入库的多资料包 | 历史记录及来源继续保留 | 无需为适配新规则重传或删除历史资料 |

拆分旧包时：

1. 保留原 ZIP，解压一份副本到新的工作目录，核对正文与附件齐全。
2. 如果原清单包含多份 MD，可将解压目录作为 `--root`、原 `manifest.json` 作为 `--manifest`，输出目录放在解压目录之外。
3. 若只重传其中几份，用 `--file` 或 `--list-file` 重新选取；需要保留自定义标题和 metadata 时，用选件 manifest。
4. 核对报告及每包内容，再在页面多选生成的 ZIP，统一提交。

脚本不会直接读取旧 ZIP 或自动解压。如果旧包主文件是 PDF、DOCX 等，可以直接分别上传原文件；需要附件时按第 2 节手动整理为各自的单资料包。不要仅把旧清单从 `documents` 改名为 `document` 而继续期望导入多份正文。

## 6. 在页面上追加、预览和提交

1. 打开系统，选择或创建项目，进入“资料库”，点击“添加文件”。
2. 在第 1 步“选择文件”中选择文件或拖入上传区。再次选择或拖入会追加到当前列表，可分几次准备，最后统一提交。每个独立文件或 ZIP 是一个待处理资料项，完整上传区只在这一步显示。
3. 点击“预览原文”，核对正文、表格、图片、页序和视频。一个 ZIP 就是一份资料，不再提供 ZIP 内文档切换器；图片可放大，视频可播放。
4. 单独点击“预览切片”查看文本分段。原文与切片是分开的检查入口。预览不执行媒体 OCR/ASR，独立图片、图片合集或纯视频在正式处理前可能还没有可检索文字。
5. 进入第 2 步“资料与处理方式”，填写平台、业务、适用对象，核对时间处理方式及处理模式。此步显示文件数量和名称的紧凑摘要；需要补文件时点击“返回修改文件”，回到第 1 步追加，已有队列保留。
6. 进入第 3 步“确认并处理”，核对全部待提交资料后点击“开始处理”。此步同样只显示文件摘要和“返回修改文件”，不重复展示完整上传区。
7. 在“处理批次”查看每份资料的解析、OCR/ASR、切片和后续进度，以及需要人工处理的问题。

| 处理模式 | 适合的用途 | 后续操作 |
| --- | --- | --- |
| 仅文档检索 | 解析正文、执行 OCR/ASR、生成切片，供文档检索；暂不抽取实体和关系 | 核对识别质量；项目首次索引需显式构建，已有索引核对增量同步状态 |
| 开放本体发现 | 首次梳理规则，产生类型和事实候选 | 到本体建模层核对候选，加入工作草案并在收件箱审核 |
| 使用项目本体 | 按已发布本体抽取 | 核对类型、关系、正式写入结果和待审核项 |

解析把正文和媒体转换成文字，切片把文字分段并保留来源，抽取生成实体与关系。媒体格式不需要额外定义为业务实体类型。开放发现的候选仍须经过本体及关联事实审核后形成正式图谱结果。

时间自动识别按每份资料执行；手工填写会覆盖本批文件，只有整批日期一致时才统一填写。发布时间、生效时间、失效时间和上传时间含义不同，核对原文后填写。

### 已有资料怎样重新处理或构建图谱

可以先选择“仅文档检索”完成解析、OCR/ASR 和切片，先使用文档检索，之后再构建图谱。打开资料详情，找到“重新处理 / 构建图谱”，选择处理方式，再点击“创建处理任务”：

| 详情中的处理方式 | 本次任务做什么 |
| --- | --- |
| 仅文档检索 | 重新生成正文切片并更新项目检索输入，暂不抽取实体和关系 |
| 开放发现 | 产生本体与事实候选，经过本体审核和事实确认后才形成正式图谱结果 |
| 使用项目本体 | 按已发布的项目本体重新抽取并校验事实；尚未发布本体时，先完成发布 |

此入口复用固定来源和可复用的成功 OCR/ASR，不需要再次上传文件。资料 ID 保持不变，系统创建新的处理任务与处理代际，并保留处理历史。点击“查看处理任务”可进入后台任务查看进度，完成后仍需核对索引同步与图谱结果。已有未结束任务时，先完成或取消该任务；缺少固定原始来源的旧资料会提示重新上传，已有正文仍可阅读。

“解析视图”中的“重试 OCR”或“重试未完成 OCR 区域”只更新该图片的识别结果。若希望新文字进入检索切片或图谱，回到资料详情执行整份重新处理，再核对索引和相应审核结果；单项 OCR 重试不会自动重建这些结果，历史记录继续保留。

项目索引首次仍需管理员显式发起构建。已有项目索引通过增量同步追赶最新处理结果；上传或重新处理完成不能直接等同于立即可检索，请确认索引已就绪。

## 7. 处理完成后看哪里

| 想检查什么 | 页面入口及检查点 |
| --- | --- |
| 正文、表格、完整长图、图片页序和视频 | 资料详情的“图文阅读”；图片可放大、按宽阅读或查看原始比例 |
| PDF 原版页面 | 打开固定版本原文的“阅读视图”，使用上一页、下一页或页码输入；支持来源区域高亮、下载和新窗打开原件 |
| 已保存文字与切片 | 资料详情的“已保存正文”及切片结果 |
| OCR 文字、文字框、分块进度和失败区域 | “在原文中打开”里的“解析视图” |
| 图片文字对应位置 | 从证据打开固定来源，核对原图上的对应区域与高亮 |
| 视频语音对应位置 | 点击解析视图的时间段与转写文字，跳到原视频位置 |
| 原文件或原始 ZIP | 固定版本原文中的下载入口；按来源类型提供原件或原包 |
| 事实及证据 | 资料详情的“提取知识”，或“检索与图谱”中的来源入口 |
| 为什么停在需要处理 | “处理批次”和资料的“处理记录”，核对 OCR/ASR 质量问题 |
| 以后补做解析、文档检索或图谱 | 资料详情的“重新处理 / 构建图谱”，选择模式后创建任务 |

OCR 与 ASR 成功后，文字进入知识处理输入及切片，并保留图片区域或视频时间段。上传成功、原件能打开、识别完成、索引就绪和事实已写入是不同状态，应分别检查。部分分块失败时，已有文字可保留，但不能当成完整识别；重试后仍需检查覆盖范围。

“图文阅读”呈现固定来源的正文、表格与关联媒体；“已保存正文”查看系统用于切片及知识处理的保存文字，可能包含 OCR/ASR 补入内容，不能代替原文件排版。PDF 的固定版本阅读器通过本地渲染显示原版页图，不依赖浏览器 PDF 插件；页图有分辨率上限，精细核对可下载原 PDF。

关键词、语义和混合检索依赖项目 Milvus 索引就绪；首次构建需显式发起，已有项目核对增量同步。图谱默认保留全部历史业务时间；按当前或指定业务日期筛选时，还需核对生效、失效及未知日期项。

## 8. 文件和识别结果保存在哪里

| 内容 | 保存位置 |
| --- | --- |
| 独立上传原件、原始 ZIP、提取的图片与视频附件 | MinIO 来源对象存储；相同媒体字节可按内容哈希复用 |
| 资料、metadata、来源版本、正文和解析块 | PostgreSQL |
| OCR 运行、文字框、分块区域和进度、ASR 结果与时间段 | PostgreSQL |
| 切片与原文、图片区域、视频时间段的映射 | PostgreSQL |
| 本体、正式知识与来源断言 | PostgreSQL |
| 关键词和向量检索投影 | Milvus |

阅读器从服务端读取固定来源版本及关联媒体。长图 OCR 的裁切区域记录在运行中，完整原图保留；不需要把每个计算块当成新资料保存。

ZIP 主文件保留在完整原包中；读取或下载时按固定入口定位并核验 SHA256，不要求另存一份重复主文件。PDF 分页 PNG 当前按需在本机生成并返回阅读器，不作为新的资料或知识记录写入；原 PDF 保持完整。

## 9. 大小限制和常见问题

当前默认限制如下，页面还会读取服务能力；文件、图片和 ZIP 的各项检查都要满足。

| 对象 | 限制 |
| --- | --- |
| 单个上传文件或 ZIP | 25,000,000 字节 |
| 单张图片，包括独立图片和图片页 | 10 MiB（10,485,760 字节），不超过 40,000,000 像素 |
| 单份资料的图片 | 最多 200 张，图片总字节不超过 100 MiB；仍受 ZIP 上传大小约束 |
| 一个批次 | 最多 1,000 份资料，总上传量不超过 1,000,000,000 字节 |
| ZIP 安全检查 | 最多 5,000 个成员、解压总量 512 MiB、压缩比上限 200；禁止加密及符号链接 |
| 文本 | 非空，最多 1,000,000 字符 |
| 视频 | 不超过 600 秒；MP4 使用 H.264/AAC，WebM 使用 VP8、VP9、AV1 与 Opus/Vorbis |

图片即使小于 25,000,000 字节，也可能超过更严格的 10 MiB 或总像素限制。多帧图片请逐帧导出为静态图片；确属同一资料时再用 `pages` 指定顺序。OCR 耗时取决于图像尺寸、分块数、文字密度与机器负载，视频 ASR 还包含模型启动时间。

| 页面或命令提示 | 检查和处理方法 |
| --- | --- |
| ZIP 必须只包含一份资料／要求拆分旧包 | 按第 5 节拆包；不要在一个 ZIP 放多份待导入正文 |
| 无清单包要求一个根主文件及 assets | 将一个主文件放包根；多个连续图片改用 v2 `pages` 清单 |
| 不支持的清单版本／需要一个 document | 使用整数 `schema_version: 2` 和单个 `document`；`entry`、`pages` 二选一 |
| 清单文件或图片页缺失、路径重复 | 核对相对 ZIP 根的路径、大小写与实际文件，删除重复页路径 |
| 图片缺失或未引用文件提示 | 核对正文相对路径；补齐要用的附件，删除无关文件或补上引用 |
| 图片字节、像素、动画或格式被拒绝 | 按上述限制导出静态图片；扩展名须与图片实际格式一致 |
| 长图显示部分完成、识别失败或置信度不足 | 查看分块进度和问题区域；核对原图后重试。识别补全后，在资料详情重新处理，才会更新切片及检索/图谱输入 |
| 原图可见，预览切片没有 OCR 文字 | 预览不跑 OCR；提交正式处理后查看解析结果与处理记录 |
| 视频可播放但没有转写 | 查看 ASR 进度、音轨与语音内容，核对本地模型；画面里的字幕不会自动做帧 OCR |
| 网络媒体离线时打不开 | 下载到本地 assets、修改引用，重新打包并核对固化状态 |
| metadata 的分类没有出现在筛选中 | 核对清单及字段映射；页面业务范围须使用对应控件 |
| 处理结束，图谱没有节点 | 核对处理模式、候选审核及正式事实写入；仅文档检索不会自动生成图谱事实 |
| OCR 重试成功，检索结果仍未更新 | 单项重试只改识别结果；执行整份重新处理，并检查首次索引构建或增量同步是否就绪 |
| 资料重新处理提示已有未结束任务 | 先在后台任务完成或取消原任务，再创建新的处理任务 |
| 第 2、3 步没有完整上传区 | 这是文件摘要；点击“返回修改文件”回到第 1 步追加，原有队列会保留 |
| 输出目录已存在／位于源目录内 | 为本次打包指定源目录之外的新目录 |
| 单份资料和附件超过包上限 | 减少无关附件，或将确属独立的资料分开；脚本不会自动把一份资料拆开 |

## 10. 样例目录与验收范围

本轮新样例统一使用 `D:\workspace\knowledge_service_v2\outputs\unified-media-example\`，其中 `packages/` 是单资料 ZIP 的输出位置。先确认本机文件已经生成，再核对 `packaging-report.json` 并上传；本文给出的路径与命令本身不表示样例已运行通过。旧的多 MD 合包样例应先按第 5 节拆分，不能继续用来学习 ZIP 内文档切换。
