# 平台规则资料上传与 ZIP 打包操作手册

适用于本轮已合并的资料库、图文阅读、图片 OCR 和视频 ASR 功能。核对日期为 2026-11-11。

## 1. 先确认文件怎么上传

| 手里的资料 | 上传方式 | 处理结果 |
| --- | --- | --- |
| TXT、Markdown | 直接选择 `.txt`、`.md` | 读取正文，按处理模式生成切片和知识 |
| PDF | 直接选择 `.pdf` | 解析正文与表格，扫描内容按文档 OCR 配置处理 |
| Word | 直接选择 `.docx` | 转换正文、表格和相关图片 |
| HTML | 直接选择 `.html`、`.htm` | 解析网页文档内容 |
| 视频 | 直接选择 `.mp4`、`.webm` | 保存原件供播放，正式处理中通过 ASR 生成文字与语音时间段 |
| PNG、JPG 等图片 | 写一份 MD 引用图片，再把 MD 和图片一起打成 ZIP | 保存图片，正式处理中通过 OCR 识别文字 |
| 多份 MD 和附件 | 上传 ZIP | 每份 MD 建立一份资料，关联各自引用的图片和视频 |

**当前单独 PNG、JPG 图片的上传入口尚未接入。图片 OCR 已接入 MD／ZIP 附件处理。**

单独上传 MD 时，上传内容只有该文件。带本地图片或视频的 MD 应与附件一起打成 ZIP。多个 PDF 或视频可以直接多选或拖入上传区，按文件分别处理。

## 2. 最容易理解的 ZIP 结构

假设有两份规则、三张图和一个讲解视频，可以准备成下面的结构。

```text
我的规则包.zip
├── manifest.json
├── 规则A.md
├── 规则B.md
└── assets/
    ├── 场景1.png
    ├── 场景2.jpg
    ├── 场景3.png
    └── 规则讲解.mp4
```

`assets` 是建议使用的附件目录名。系统根据 MD 中的相对路径关联文件，也可以沿用采集程序已有的附件目录名。

例如，`assets/场景1.png` 表示这份 MD 同级的 `assets` 文件夹内的 `场景1.png`。

### 规则A.md 的内容

```markdown
# 规则A

发布日期：2026-01-01
生效时间：2026-02-01

这里是规则正文。

![违规场景一](assets/场景1.png)
![违规场景二](assets/场景2.jpg)

[播放规则讲解](assets/规则讲解.mp4)
```

### 规则B.md 的内容

```markdown
# 规则B

这里是另一份规则的正文。

![违规场景三](assets/场景3.png)
```

日期示例用于说明字段写法，整理真实资料时填写原文对应的日期。

HTML 图片写法同样可以关联附件，采集得到的表格内图片可沿用这种写法。

```html
<img src="assets/场景1.png" alt="违规场景一">
```

视频还可以使用以下写法。

```html
<video src="assets/规则讲解.mp4" controls></video>
```

## 3. 多张图片怎样处理，页面为什么刷新进度

处理单位是每份 MD，图片和视频归属于引用它们的资料。

以上面的 ZIP 为例，选择文件时看到 1 个 ZIP，提交后批次里会有 2 个资料处理项。规则A 关联 2 张图片和 1 个视频，规则B 关联 1 张图片。

处理流程如下。

```text
读取 ZIP
  → 找到需要导入的 MD
  → 按每份 MD 的正文引用寻找附件
  → 图片逐张 OCR，视频逐个 ASR
  → 识别文字与正文共同生成切片
  → 根据所选模式检索、抽取候选或写入图谱
```

页面会定时查询批次状态，也就是轮询进度。后台的图片识别按附件引用逐张执行，并受 OCR 并发限制。本机当前文档并发上限为 4，图片 OCR 上限为 1，视频 ASR 上限为 1。

放入 `assets` 的文件通过正文引用进入对应资料的媒体处理。准备包时，把需要识别的每张图都写进 MD。同一张图可以被多份 MD 引用，来源关联分别保存在各自资料中。

### 手里只有图片时

如果三张图属于同一份规则，可以新建 `图片资料.md`，把下面的内容与图片一起打包。

```markdown
# 图片资料

![第1页](assets/第1页.png)
![第2页](assets/第2页.png)
![第3页](assets/第3页.png)
```

这样会形成 1 份资料、3 张关联图片。如果每张图是一份独立规则，可以分别建 MD，让资料名称和来源范围更清楚。

## 4. 网络图片和本地 assets 怎样对应

下面的写法引用网络图片。

```markdown
![示例](https://example.com/images/a.png)
```

要把它做成本地附件，按下面三步操作。

1. 下载图片，保存到 MD 同级的 `assets/a.png`。
2. 将 MD 中的引用改成 `![示例](assets/a.png)`。
3. 把 MD 和 `assets` 一起打包。

打包脚本收集 MD 实际引用的本地文件。网络图片地址会保留，并写入打包报告的警告。服务端可按远程图片配置尝试抓取，离线阅读需要核对图片是否已保存成功。

网络视频引用会显示待固化状态。准备离线视频时，也按“保存到 assets、修改 MD 引用、一起打包”的步骤处理。

每次运行使用新的输出目录名。先检查 `packaging-report.json` 中的文件清单、警告和大小，再上传生成的 ZIP。

### 手动压缩

文件较少时，可以在资源管理器中选中 MD、`assets` 和可选的 manifest，右键压缩为 ZIP。压缩完成后打开 ZIP，核对目录和引用的文件名。

有 manifest 时，把它放在压缩包第一层。MD 可以放在平台子目录中，manifest 的 path 要包含对应子目录。

上传包使用普通、未加密的 `.zip`，MD 和 manifest 使用 UTF-8 编码。RAR、7z 和 ZIP 内再次嵌套的压缩包不作为资料包入口解析。包内使用相对目录，保留实际文件即可，不要加入磁盘绝对路径或符号链接。

## 6. manifest.json 是做什么的

manifest 用来指定导入哪些 MD、它们的顺序、标题和额外 metadata。脚本会自动生成，也可以按需要准备输入清单。

```json
{
  "documents": [
    {
      "path": "规则A.md",
      "title": "规则A",
      "metadata": {
        "rule_id": "rule-a",
        "source_url": "https://example.com/rules/a",
        "collection_category_path": ["商家管理", "营销规则"]
      }
    },
    {
      "path": "规则B.md",
      "title": "规则B"
    }
  ]
}
```

| 情况 | 当前系统的行为 |
| --- | --- |
| ZIP 根目录存在 manifest，且有 documents | 按 documents 的清单及顺序读取 MD，应用对应 title 和 metadata |
| 根目录没有该清单 | 自动查找 ZIP 中的全部 `.md`，按路径排序读取 |
| documents 中列出的 MD 缺失或重复 | 返回包校验问题，需要修正清单 |
| manifest 放在平台子目录里 | 当前根目录读取逻辑会走 MD 自动发现，逐文件 metadata 需要调整到根 manifest 后应用 |

`path` 相对 ZIP 根目录。例如实际文件在 `抖音电商/规则A.md`，清单里就写这个完整包内路径。

图片和视频在 MD 正文中引用，`documents` 清单填写 MD。多个 PDF 可在文件选择器中直接多选上传。

采集台账中的分类可以先保存为 metadata。平台、业务、适用对象的业务筛选使用系统已有的适用范围字段，上传时在对应控件填写。自定义的分类字段需要有对应的筛选映射才能用于图谱条件。

## 7. 在页面上如何上传和处理

1. 打开系统，选择或创建项目，进入“资料库”，点击“添加文件”。
2. 选择文件或拖入 ZIP。上传区在三个步骤中都可继续追加文件。
3. 点击“预览原文”，用“ZIP 内文档”选择器逐份检查正文、表格、图片和视频。图片可以放大，视频可以播放。
4. 点击“预览切片”，查看提交前生成的文本片段。ZIP 图片附件的 OCR 与视频 ASR 在正式处理中生成。
5. 进入“资料与处理方式”，填写平台、业务、适用对象，并核对时间处理方式。
6. 选择处理模式，进入“确认并处理”，核对本批范围后点击“开始处理”。
7. 在“处理批次”查看每份资料的进度和需要人工处理的问题。

| 处理模式 | 适合的用途 | 后续操作 |
| --- | --- | --- |
| 仅文档检索 | 先保存原文、验证图片和视频、生成可检索文字 | 查看解析结果，并核对检索索引就绪状态 |
| 开放本体发现 | 梳理首次导入的规则，产生业务类型和事实候选 | 到本体建模层核对候选，加入工作草案并在收件箱完成审核 |
| 使用项目本体 | 按已经发布的业务本体抽取 | 对齐已有类型和关系，核对写入结果及待审核项 |

解析把文档和媒体转换成文字，切片把文字分段并保留来源位置，抽取产生实体与关系。选择开放发现时，候选经过本体及关联事实审核后形成正式图谱结果。

图像和视频通过资料媒体信息管理，实体与关系类型按业务含义定义。

## 8. 处理完成后看哪里

| 想检查什么 | 页面入口 |
| --- | --- |
| 排版、图片、表格和播放器 | 资料详情中的“图文阅读” |
| 解析后保存的文字 | 资料详情中的“已保存正文” |
| OCR 结果、ASR 转写和来源块 | “在原文中打开”中的“解析视图” |
| 视频语音对应的位置 | 点击解析视图里的时间段和转写文字，跳到原视频 |
| 提取的事实及其来源 | 资料详情中的“提取知识” |
| 批次或文档为什么需要处理 | “处理批次”和资料的“处理记录” |
| 节点、关系及条件筛选 | “检索与图谱” |

OCR 和 ASR 成功后，识别文字会进入知识处理输入及对应切片。原图和视频通过固定来源版本关联，可以继续阅读或播放。

图谱默认保留全部历史业务时间。按当前或指定业务日期筛选时，核对生效、失效及未知日期项。时间自动识别按各份资料执行，手工填写的时间会覆盖本批文件，整批日期相同时再统一填写。

关键词、语义和混合检索依赖项目检索索引就绪。图谱和索引的实际状态分别核对。

## 9. 文件保存在哪里

| 内容 | 保存位置 |
| --- | --- |
| 原始 ZIP，以及其中 MD 的原始字节 | MinIO 来源对象存储 |
| 已关联的图片和视频原件 | MinIO 来源对象存储，按内容哈希复用字节 |
| metadata、来源版本、正文、解析块、OCR 和 ASR 结果 | PostgreSQL |
| 切片与原文、图片文字框、视频时间段的对应关系 | PostgreSQL |
| 本体、正式知识与来源断言 | PostgreSQL |
| 关键词和向量检索投影 | Milvus |

上传成功后，图文阅读从服务端读取已保存的附件。MD 中原有的相对路径由来源版本记录关联到对应对象。

## 10. 大小限制和常见问题

本机当前单个上传文件或 ZIP 上限为 25,000,000 字节。一个批次最多 1,000 份资料，总上传量上限为 1,000,000,000 字节。页面读取服务能力，管理员调整后以页面值为准。

ZIP 另有限制，最多 5,000 个成员、解压总量 512 MiB、压缩比上限 200。打包脚本使用普通 ZIP 并自动控制大小。

视频首期上限为 600 秒。MP4 使用 H.264/AAC，WebM 使用 VP8、VP9、AV1 与 Opus/Vorbis。CPU 转写包含模型启动时间，当前短样本的正式后台任务用时约 191 秒。

| 遇到的情况 | 检查和处理方法 |
| --- | --- |
| 图片缺失 | 核对 MD 相对路径、文件名和 ZIP 内实际位置，补齐附件后重新打包 |
| 图片可见，OCR 需要人工处理 | 查看识别结果和置信度，核对后重试，或填写原因忽略该附件的识别文字 |
| 视频可播放，转写还没出现 | 查看批次进度及 ASR 状态，核对本地模型、音轨和可识别语音 |
| 文件格式或视频编码被拒绝 | 核对本手册的上传类型及视频编码范围 |
| 只有图片的 ZIP 没找到资料 | 新建 MD，把要处理的图片逐张写入引用，再一起打包 |
| 网络图片离线时打不开 | 下载到本地 assets，修改 MD 引用，再提交 ZIP |
| manifest 的分类没有应用 | 核对根目录 manifest.json、documents 清单及字段映射 |
| 资料处理结束，图谱还没有节点 | 核对处理模式、候选审核和正式事实写入状态 |
| 输出目录已存在 | 给这次打包换一个新的输出目录名 |
